## 取用接口

`lib/trips/seed-runner.ts` 提供 `createSeedTripRunner`。调用方为一只狗的一次调度保存并复用同一个 `intentId`。

```ts
const intent = createSeedTripRunner(db)(dogId, intentId)
const pendingOrExisting = intent.create()
const { trip, delivered } = intent.start()
// 执行器在确认本趟结束以后调用。
const finished = intent.finish('done')
```

- C4 使用专门的种子狗授权分支。每阶段在自己的 `BEGIN IMMEDIATE` 事务内检查狗仍满足 `is_sample=1 AND owner_id IS NULL`。没有 Cookie、owner 或 session 参数。种子记录保留 D 的原有字段。
- 对 `[dogId, intentId]` 计算 SHA-256 并使用专用 Trip ID 前缀，复用现有 Trip 持久化和主键。意图键只能使用规定的 1–128 个 ASCII 字符。相同键用于不同狗时得到不同 ID，同狗并发依靠 SQLite 写锁串行化。相同意图返回已存记录，无法通过稳定 ID 操作其他狗或其他来源的 Trip。
- `create()` 成功后，即使 `start()` 失败，也可用原键重试同一 pending。实际开始与延迟投递共用 C4 事务。重复开始返回既有 running 或终态和空 `delivered`，首次时间保留。结束沿用 C4 规则，重复相同终态返回原记录。C4 保留数据库抛出的原始故障，支持 SQLite 已主动回滚的情况。
- 可信调用方后续在 C4 start 成功并且 C7 合入后，需在 running 阶段交给 C7 已核实的场景、季节、天气和时段，并确认 C7 有明确的种子狗内部授权入口。已交的 C7 接口目前只接受 C4 归属键，联合接入须扩展内部身份边界。条件不足或无匹配时保持事件为空，随后由正常旅行执行器结束本趟。

实现文件为 `lib/trips/service.ts`、`lib/trips/seed-runner.ts`、`contracts/api.md`。测试见 `tests/seed-runner.test.mjs` 和 `tests/helpers/seed-runner-worker.mjs`。本地默认 `data/app.sqlite` 只读检查为 0 只种子狗、0 趟种子 Trip。以下数据均来自另建的隔离库，未对默认库或生产库执行导入和业务写入。
