## C 提供给 D 的历史读取契约

`lib/db/migrations/007-trip-history.ts` 提供待注册 v7 SQL。新增 `trip_event_fact`，以 `(trip_id,event_id)` 引用现有 occurrence。主干现行初始化、schema 文件及 v2–v5 迁移仍沿用 v5。A 确认 K6 和迁移顺序后，将这份 SQL 接入迁移列表及 fresh schema，并补两种初始化路径的对象一致性测试。

`v_trip_event_history` 为只读接口。字段为 `trip_id`、`event_id`、`dog_id`、`happened_at`、`event_code_at_occurrence`、`public_text_at_occurrence`、`history_status`。新 occurrence 插入时由触发器在同一 SQL 语句复制数据库中的事件代码和公开模板原文。C7 上层继续核对已审事件语义和授权。迁移时旧 occurrence 只建立两字段皆为 NULL 的标记，`history_status='unverifiable'`。新记录为 `frozen`。更新、删除和替换保护覆盖 occurrence、事实表、快照及绑定。

供 D 在现有最早事件查询的位置取用，继续由 D 决定现有派生规则对历史不可核验状态的出参表示。

```sql
SELECT event_id, happened_at, event_code_at_occurrence,
       public_text_at_occurrence, history_status
FROM v_trip_event_history
WHERE trip_id = ? AND dog_id = ?
ORDER BY julianday(happened_at), event_id
LIMIT 1;
```

读到 `unverifiable` 时缺失的代码及摘要保持空，禁止回退查当前 `event.text` 或把后续事件说成历史上最早发生的事件。C 回归中，同一模板从 `ev_old` 和「旧的公开摘要。」改为 `ev_new` 和「新的公开摘要。」后，旧 Trip 的查询仍返回原字段，新 Trip 在新版本时间记录第二组字段。D 分支当前还读可变模板，实际新快照的摘要稳定性须在 D 改读后合验。

## 种子权限与快照绑定

- `lib/trips/seed-event-scope.ts` 提供 `seedIntentTripId(dogId, intentId)` 及 `requireRunningSeedEventTrip(db, { dogId, tripId, intentId })`。事务内检查精确意图 ID、同狗、`auto`、`is_sample=1`、`owner_id IS NULL` 及 running，并返回过滤需要的开始时间、兴趣和屏蔽字段。已有 C8 种子的 ID 向量测试一致。入口不接收 Cookie。
- `lib/trips/departure-snapshot.ts` 分配下一版、校验 D 的 Snapshot 白名单和元数据、追加快照并写 `trip_snapshot`。绑定要求匹配 pending Trip，绑定 `(dog_id,snapshot_version)` 的外键及唯一约束保证准确版本。读方使用 `readDepartureSnapshot(db, tripId, dogId)`，历史无绑定返回 NULL。所有消费者需要自己先完成内部授权。
