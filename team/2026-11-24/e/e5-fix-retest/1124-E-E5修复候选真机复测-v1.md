## 3. 性格滑块「闪退」——未修复，问题保留

### 3.1 用户侧现象

真机拖动性格滑块时「闪退」。原样保留，未关闭。

### 3.2 桌面定位尝试（只观测，未改被测代码）

环境：Chromium 148.0.7778.96 headless，390×844，`isMobile`/`hasTouch`，本机地址 `http://127.0.0.1:3107`。
方法：进入 `它更像哪一种伙伴？` 步骤，对第一个滑块做 6 轮完整拖动，每轮 20 步 pointer move，每轮后取快照。

| 观测项 | 结果 | 指向 |
| --- | --- | --- |
| `h1` 文案 | 6 轮均为「它更像哪一种伙伴？」 | 未跳步、未回退 |
| 滑块数量 | 6 轮均为 6 | 组件未卸载 |
| `performance.getEntriesByType('navigation').length` | 恒为 1 | **无页面重载** |
| JS 堆 | 恒为 12 MB | 无内存增长 |
| `pageerror` | `[]` | 无脚本异常 |
| console error/warning | 无 | — |
| 长任务 | 拖动期间 1 次，92 ms | 有可感知卡顿风险 |

结论：**桌面端既没有页面重载，也没有面板退出，更没有崩溃**。因此在桌面上无法复现该问题，这一点不能用来关闭问题项。

### 3.3 单次拖动的实际开销

方法：从中间拖到最右（20 步），统计 `sessionStorage.setItem` 调用次数与长任务。

| 指标 | 实测 |
| --- | --- |
| `v25-adoption:*` 写入次数 | 10 次 |
| 累计写入字节 | 2186 字节 |
| 长任务 | 1 次，69 ms |

（补充：随后 5 轮快速往返拖动没有产生新写入，因为滑块已停在最大值 100，`onChange` 不再触发；该轮数据不具参考性，不作为结论。）

### 3.4 代码层观察（候选因素，**不是结论**）

- `components/app-shell/adopt-page.tsx:691` 每个 `onChange` 调用 `change()`。
- `change()`（188–194 行）做三件事：`setDraft`、`setGeneration(null)`、`persist()`。
- `persist()`（166–181 行）**每次同步写 `sessionStorage`**，序列化整份 draft + assembly。
- 同一 tick 还调用 `emitFeedback`（78–82 行），驱动角色反馈动画。
- 滑块 `step=5`，0–100 共 21 档。

在桌面上这些只造成一次 69–92 ms 长任务；iPhone 微信 webview 上的真实开销本轮**无法测量**。

### 3.5 目前能确认与不能确认的

- 能确认：桌面 Chromium 下不重载、不卸载、不崩溃。
- 不能确认：真机上究竟是 webview 进程被系统回收、页面内 JS 崩溃后重挂载，还是微信自身退出。三者现象都是「闪退」，现有证据无法区分。
- 需要：真机侧日志。建议 A 或 C 在 iOS Safari 远程调试 / 微信 X5 调试下复现一次，抓 `Page.crash`、`Runtime.exceptionThrown` 或 `didReceiveMemoryWarning`。

## 5. 开发工具「1 Issue」

用户截图中开发覆盖层显示 1 个 Issue。服务端控制台记录了浏览器上报的原文：

```
A tree hydrated but some attributes of the server rendered HTML didn't match the client properties.
...
<RootLayout>
  <html
    lang="zh-CN"
-   style={{-webkit-touch-callout:"none"}}
  >
```

即：服务端渲染的 `<html>` 没有该 style，客户端上多出 `-webkit-touch-callout:none`，造成 hydration 不匹配。

全仓库检索 `touch-callout`：**0 处**。因此这个 style 不是本项目代码写入的，来源在本项目之外（微信内置浏览器或其它注入）。

**不认定它是滑块闪退的原因。** 理由：该不匹配在 `/home` 就被上报，而闪退发生在 `/adopt` 的滑块步骤；两者只是同一会话中同时出现的现象，没有因果证据。

建议：A 可考虑在 `<html>` 上显式声明 `style="-webkit-touch-callout:none"` 或在挂载后同步该属性，以消除这条噪声；但这属于 A 的页面实现，E 未改动。
