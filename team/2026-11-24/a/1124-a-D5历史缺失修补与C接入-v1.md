# A接管：D5历史缺失修补与C接入 v1

基线：D `d5-history-1124@f772da675d7be6b675508b248806b0f44173b260`，包含6db1622。候选分支`a-d5-null-fix-1124`。本件替代旧D接入文档中仅调用toSnapshot的正式写入示例，旧档不修改。

## 改了什么

显式occurrenceFacts读取器返回null时，recentTrips不再补当前event.text，逐趟summary=null、textSource=unverifiable、historyFixed=false。无事件的旅途正常为空，不调用事实读取器。未传读取器的旧调用仍可看模板诊断，但不得通过新增正式转换入口。

新增`toFixedSnapshot(result, meta)`，接收完整DeriveResult，拒绝historyFixed非true或dog归属不一致，再复用原validateSnapshot。旧toSnapshot仍只检查形状，为旧诊断调用保留；不能再作为正式历史固定保证。

S20原先将“缺事实回退模板”写成预期，现改为缺失摘要留空。新4项回归进入tests：显式null不补模板、诊断拒正式转换、固定事实跨模板修改不变/来源保留、无事件正常为空；还覆盖错狗拒绝及调用者回滚示例。

CLI证据顶层textSource新增sources集合，替代原来固定写死column=event.text的说明；mutable由实际证据计算。仓库未找到textSource.column消费者，下游报告若有外部解析应同步调整。

## C唯一接入用法

在现有start写事务内、任何实际投递之前：

```ts
const result = deriveSnapshot(db, dogId, { occurrenceFacts: readFixedFacts })
const snapshot = toFixedSnapshot(result, {
  dogId,
  version: nextVersion, // C在同一写事务内分配
  createdAt: now,
})
// C：保存新版本、绑定本趟、开始和投递；成功共同提交，失败整体回滚。
```

readFixedFacts由C读发生时冻结的公开事实，返回{text,sourceId,capturedAt}或null，不查不到就读模板。禁止`toSnapshot(result.body, ...)`丢弃证据后当正式保护。重复/并发start必须先识别已绑定版本，返回首次版本，不再次派生。C7在running另行选择，不嵌套start事务。

本候选没有猜C v7 schema，也没有修改C4/C7/C8。C仍须完成读取器、迁移、主人/种子真实start接入、不可恢复旧记录处理策略与联合回归。缺失原文不能由A补造；当前正式转换会明确拒绝未固定历史，不能以摘要为空绕过historyFixed。
