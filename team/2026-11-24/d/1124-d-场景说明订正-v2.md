## 一、我错在哪（两条，都说具体）

### 1. 把「地点不限制」读成了「室内外也不限制」

v1 给书店内景列了 3 条白名单：`winter_bookstore_chair` + `autumn_birds` + `any_moon_ring`。
后两条 `place_tags='[]'`，我当时的理由写的是「白名单是完整的，两条不限地点的在两张图里都显式列出」。

**`place_tags='[]'` 只说明地点维度不限制**，这两条事件还有另一个前提：要**室外天空**（A 11/23 裁定第 3 条）。
挂到室内场景上的后果很具体 —— 狗坐在书店最里面的扶手椅上，快照里出现「树上的鸟换了位置」，
而画面里只有书架和一扇窗。这种错在界面上看起来完全正常，跟标签写错是同一类。

所以：**内景 3 条 → 1 条**。外景保留这两条（门口，抬头就是天）。

### 2. 把 `eventAllow` 说成了「标签能算出来的收敛」

v1 说「现在靠 d 的换算表兜住」，但 v1 第 1.3 节那段 SQL 只有 `place_tags` 交集，**连 `eventAllow` 都没用**。
照那段 SQL 跑，同为 `[bookstore]` 的两张图候选集合完全相同 —— 5 条和 1 条的差别一分都体现不出来。

而且这不是「换个写法就行」：

| 写法 | 结果 |
| --- | --- |
| `EXISTS (t.value IN scene.tags)` | **OR / 并集**。两张 `[bookstore]` 图完全等价 |
| 改成 `[bookstore, indoor]` 再求交集 | **仍然是 OR** —— EXISTS 还是「任一命中」，只是多了一个能命中的值 |
| 两个条件用 AND 强行拼 | 语义上说不通：一张图不会同时「是 bookstore 且是 indoor 事件」，事件根本没有 indoor 这个值 |

**结论：标签这一层不可能隔离室内外。** `eventAllow` 是给 C 的条件层用的**逐张白名单**，
必须被 C 真的读进去才生效；A 已裁定**不新增第五个 `place_tag` 值**，D 也不擅自改 `event` 字段。
这条已写进 `scene-place-compat.json` 的 `matchingBoundary`，脚本也会把它打印出来，避免下一个人再按标签去算。

## 三、酒馆从 2 条变 0 条：这是结论，不是漏填

酒馆内景是室内，但四值里没有「室内」，所以它的 `tags` 只能是 `[]`。而 `[]` 的语义是「地点不限制」，
于是两条天空事件会漏进来 —— 正是第一条错的同一个形状。分成两半看：

| 事件 | 为什么进不来 |
| --- | --- |
| 28 条带地点的事件 | 要街面 / 摊位 / 水岸 / 书店，室内吧台一条都不成立。给 `stall` 就会让栗子摊开在吧台边 |
| `autumn_birds` / `any_moon_ring` | 要室外天空，室内不成立 |

结果 0 条。按 C 已定的口径「无合适事件就不展示事件，旅途继续」，这是正常旅途，不是坏场景。
表里用 `eventAllow: []` + `eventAllowNote` 写死这个结论 —— 空数组不写理由，最像漏填。

## 四、数字重算（并且它们只是地点候选数）

| 口径 | 场景 | 合计条次 | 平均 | 无场景可用 |
| --- | ---: | ---: | ---: | ---: |
| 现行（12 张） | 12 | 119 | 9.92 | **3 条** |
| 采用 E 两张后（14 张） | 14 | 125 | 8.93 | **0 条** |

与 v1 的差：酒馆 −2、书店内景 −2（121→119、129→125）。平均降不是素材拖累 —— 是事件池里只有 3 条书店题材。

**这 16 / 23 / 6 都是地点候选数，不是「读通的事件数」。** 加上 A 的第二层语义后，实际可用只会更少：

- **社区公园** `street` 16 条 → 只放行 6 条（`summer_shower` / `autumn_ginkgo` / `winter_first_snow` / `winter_one_glove` / `any_street_music` / `any_slow_walker`）。其余街道文本依赖车底、晾衣、屋檐、饭馆
- **河流不等同海岸**：`summer_river_fish` 只允许桂林漓江；海岸 / 湖岸不承接「河边捞鱼」。`autumn_river_fog` 的对岸楼房、`winter_river_ice` 的结冰环境在当前 12 图未确认，暂不选中
- **`spring_first_green`** 含墙根 → 只在南头 / 深夜街角 / 北京路这类有城市建筑的环境；沙丘、湖海、酒馆不套
- **`summer_cicada`** 要「整条街」→ 白桦林有树也不算
- **鸟 / 月亮** 要室外天空 + 各自季节 / 天气 / 时段；不是「传个 night 就能显示月亮」
- **酒馆不出鸟 / 月**（本文第三节）

所以「现行 3 条无场景可用」指的是**粗标签口径**。语义条件加上去，数字只会更小，
但那是 C 的第二层，不是这张表能算的。

## 五、脚本新增的两道守卫（都做了反向验证）

1. **室内场景不得漏进天空事件。** 把 `autumn_birds` 塞回内景白名单再跑，脚本红：

同标签 + 不同 variant 必须配不同白名单的旧规则保留（外景 5 / 内景 1，仍然不同）。
