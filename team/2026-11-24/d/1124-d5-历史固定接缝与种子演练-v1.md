## 一、复现：已存版本没变，但同一次发生换了话

`node scripts/d5-history-probe.mjs`（新脚本，可复跑，自造数据、临时库、跑完即删）：

```
① 已存 snapshot 是否被改写
✅ v1 仍是当时那句
     当时：路口的风把梧桐叶吹得翻了个面。
     现在：路口的风把梧桐叶吹得翻了个面。

② 同一旧 trip 进**新版本**时，摘要是否稳定
❌ 模板改文案后，旧 trip 摘要不变  → 跟着变了
     v1：路口的风把梧桐叶吹得翻了个面。
     v2：（改过的文案）路口的风很大。
     来源标注：template_current（factSourceId null），本批 historyFixed=false
```

**退出码 1**。这不是脚本坏了，是缺口还开着 —— 我让它用退出码说事实，
而不是在报告里写一句「已知问题」然后一切照绿。

`--expect-open-gap` 是巡检用的：确认缺口**仍在**时退出 0，免得把已知未修误报成新故障。

为什么不在 `node --test` 里加这条：现在加进去，要么天天红（没用），
要么断言「文案会变」（等于把 bug 写进契约）。C 交事实读取之后，探针转绿，
那时再搬进 `tests/` 才是一条真回归。**现在的表达方式是探针 + 退出码**，
不是「用注释承认一下」。

## 二、D 侧接缝：D 要的东西其实只有三个字段

问题不在 D 读得不对，在**没有那份当时的文本可读**。所以 D 不猜表结构、不猜列名、
不碰 `trip_event`（那是 C 独占的写入面），只留一个注入点：

```ts
// lib/social/snapshot-derive.ts
export interface OccurrenceFact {
  text: string        // 当时进快照的那句公开叙述
  sourceId: string    // 来源标识（事件版本 id / 记录 id / code@version，形状你定）
  capturedAt: string  // 固定时刻
}

export type OccurrenceFactReader = (
  db: DatabaseSync, tripId: string, dogId: string,
) => OccurrenceFact | null
```

`deriveSnapshot(db, dogId, { occurrenceFacts })`。三点设计取舍：

1. **没有默认实现。** 不传就是「没有固定事实」，并如实标 `historyFixed: false`。
   如果给个「查不到就读模板」的默认实现，接缝会变成悄悄退化的地方 —— 那比不接更危险。
2. **`null` 有两种含义**，已经分开：这趟本就没事件（不调用读取器）/ 有事件但当时没固定下来
   （返回 null）。后者**不许**用今天的文本顶替，快照里那一句就是缺的。
3. **名字和形状都不由 D 定。** 你们定成视图、列、还是独立表，我只换这个函数体。
   改动范围：一个函数，两处调用点，其余零改动。

自检里已经用一张**测试专用**的固定事实表验证过接缝本身能用（S19）：
改模板 → 旧趟摘要不变、`factSourceId` 透传进证据。S20 验证存量记录不冒充有历史。
所以「接上就绿」不是许愿，是跑过的。

顺便说清楚 D 不需要什么：**不需要**事件全文版本管理、不需要历史回溯查到任意版本，
只要「这一趟发生时那句话」这一份。

## 三、正式生成链已上闸

A 说「未固定文本的派生先作为诊断，不挂正式生成链」。这条落到代码里是一道闸：

```
$ node scripts/d5-derive-snapshot.mjs --db <库> --sql-out x.sql --version 2
拒出 SQL：3 只（dog_seed_07 …）的摘要取自可变的事件模板。
  这不是格式问题，是内容问题：今天写进去的那句话，明天改文案就对不上「当时发生了什么」。
  等 C 交不可变事件事实、把 occurrenceFacts 读取器接上之后再出正式 SQL。
  如果只是做诊断，显式加 --allow-unfixed-history（产物自带未固定标注）。
```

- 报告照出（诊断要看），**要进库的 SQL 不给**。
- `--allow-unfixed-history` 也不是随便开：SQL 文件头会写「诊断产物，不可作为正式记录」。
- 证据 JSON 多了三个顶层字段：`historyFixed` / `historyUnfixedDogs` / `historyNote`，
  报告末尾也会点明是哪几只 —— 免得下一个人只看「20 只 0 趟」就以为是结论。

## 四、种子演练：可复跑，trip 可核，空结果有原因

`node scripts/d5-seed-drill.mjs`。它做三件事：把 C8 分支代码导到临时目录 →
在该目录里用 C8 的 `createSeedTripRunner`（**可信入口，不是往 trip 表插行**）跑 →
用 D 的派生器只读读一遍。

- C8 参考：`origin/c8-seed-trigger-1124` @ `3d26d81fe282`
- 时钟：受控步进（`2026-11-24T00:00Z` 起，每只间隔 1 小时），**造的不是真实时间**
- 库：临时隔离库，**不是验收库**

| 狗 | trip.id | seq | status | 时间 | 事件 | Find |
|---|---|---|---|---|---|---|
| dog_seed_01 | `trip_seed_intent_e5b62c00…3087f0` | 1 | done | 00:00→00:10 | — | — |
| dog_seed_05 | `trip_seed_intent_2eec9b8b…9e786e` | 1 | done | 01:00→01:10 | — | — |
| dog_seed_07 | `trip_seed_intent_eeb95442…69b5` | 1 | done | 02:00→02:10 | — | — |
| dog_seed_12 | `trip_seed_intent_1be06b48…b874` | 1 | done | 03:00→03:10 | — | — |
| dog_seed_18 | `trip_seed_intent_2509a06c…84bb` | 1 | done | 04:00→04:10 | — | — |

（trip.id 是 `trip_seed_intent_<hash>`，由 intent 幂等键确定性生成，重复跑得到同一个 ID ——
这正是 C8 幂等生效的证据，也是可复跑的前提。完整 ID 见 `--out` 落的 JSON。）

**空结果的原因，逐条说清**：5 只全部 0 事件、0 Find，因为本次链路里**没有 C7 场景选择器**
（未入主干）。这不是「狗出去了没看见」，是「事件条件链没接上」。
脚本每只都会打这行原因，不是留个 `-` 让人猜。

派生侧的输出：5 只各 1 趟、摘要 `[]`、`historyFixed=true`（没有事件，也就没有可变文本进过快照）、
`waiting null`。

**这不是 C8 验收，也不是 D5 联合验收。** 联合验收以 A 指定库为准。
