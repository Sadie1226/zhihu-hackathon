# 通用 · 分支、合并和取用（每个人都要读，先读这一节）

## 一条铁律

**`main` 只有 a 能改。别人禁止推 main，一次都不行。**

你要改的任何东西——代码、文档、素材——都走自己的分支，交给 a 合。

## 每天两步，别记错顺序

**第一步，早上开工前，从最新 main 切新分支：**

```bash
git checkout main
git pull
git checkout -b b4-chat          # 换成你今天的任务号
```

**第二步，晚上交（不是推 main）：**

```bash
git add -A
git commit -m "b4: 心愿可撤销"
git push origin b4-chat
```

然后群里说一句「我交了，分支 `b4-chat`，文件在 `team/11-20/b/`」。

## 不许做的事

| 不许 | 为什么 |
| --- | --- |
| `git push origin main` | main 只有 a 能改。这是唯一会被当场回退的操作 |
| 抱着一条分支写三天 | 你和 a 的合并一定会撞，而且你解决不了。每天切新的 |
| 第二天在旧分支上接着写 | 旧分支在 a 合并那一刻就已经作废。**每天从新的 main 切** |
| 手动改 a 已经合并进去的文件 | 你会和他改的打架。要改就新开分支，说明改什么 |

## 你改的东西被 a 动过了，怎么知道

a 每次合并会打一个 tag，并在 [`合并记录.md`](合并记录.md) 里留一行，写清改了谁的文件、改了什么、为什么。

**你只需要两条命令：**

```bash
git fetch --tags
git diff v1-1116 v2-1120        # 换成一你手上那个 tag 和最新的 tag
```

**只想知道你那部分改了什么：**

```bash
git log --oneline v1-1116..v2-1120 -- 'app/(b)/'
```

（把 `(b)` 换成你的字母。`(a)` `(b)` `(c)` `(d)` `(e)` 都能这么查。）

**当前最新的 tag 是哪个，看 [`合并记录.md`](合并记录.md) 最后一行。**

## tag 是什么，你不用管

a 每次合并打一个，格式 `v{序号}-{月日}`：`v1-1116`、`v2-1120`。序号只增不减。

**tag 是整个项目在那一刻的完整快照。** 你不用打，也不用记，只要知道「a 说 v2 了」的时候，`git fetch --tags` 一下就行。

**现在只有 `v1-1116`。** 下一个是 `v2-1120`（首次闭环那天）。

## 取用别人东西的时候

**一律从 main 取，从最新版本取。不要互相传文件，不要用别人电脑上的版本。**

- **文档、规则、线框** → 直接读 GitHub 上的：`https://raw.githubusercontent.com/Sadie1226/zhihu-hackathon/main/team/...`
- **代码、契约** → 你本地那份 pull 过就是最新的
- **a 刚合并完的新东西** → `git checkout main && git pull` 之后从它切分支

**没有「b 的版本」「c 的版本」这种东西。** main 是唯一当前版本，你电脑上那份只是工作副本。

## 你是唯一合并的人（每天或每个里程碑，流程一样）

**一、看有谁交了**

```bash
git fetch --all
git branch -r          # 看有哪些分支
git log main..origin/b4-chat --oneline     # 看这条分支改了什么
```

**二、验，不是看。** 至少做三件：
- `git checkout b4-chat && npm run dev` 能跑起来
- `node scripts/check-all.sh` 全绿
- 手动点一遍他声称做好的那一步

**三、合并**

```bash
git checkout main
git merge --no-ff origin/b4-chat -m "merge b4: 心愿可撤销"
```

**四、打 tag + 记一行**（这两件必须做，否则他会不知道你改了什么）

```bash
git tag -a v3-1120 -m "首次闭环跑通"
git push origin main --tags
```

然后在 [`合并记录.md`](合并记录.md) 加一行，**写清你动了谁的文件**：

```
1116 · v3 · 合 c3 契约 + b1 邀请十例 · 验：check-all 全绿、/adopt 能建狗 · 尾：照片上传未联调
改了什么：c 的 schema.sql reply 唯一索引补 exchange 路径（实测重复提交拦不住）
```

**五、通知被改的人。** 群里有谁的分支被改过，单独 @ 他一句「我动了你的 X，明天从新 main 切」。

## 你也不能长期分支

**你自己也每天从 main 切一条**，合并完就直接推 main。不要在自己那条上攒三天。
