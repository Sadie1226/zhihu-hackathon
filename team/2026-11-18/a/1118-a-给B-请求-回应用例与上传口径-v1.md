## 三、你真正的活：照片上传这条链是断的（这是重点）

我把整条链查了一遍，结论是——

### 3.1 现在的实际情况

`contracts/api.md` 第 6 节，回应接口长这样：

```
POST /api/replies
入： { exchangeId?, invitationId?, text?, photoUrl? }
```

**`photoUrl` 是客户端直接传进来一个字符串。** 也就是说，前端说 `/assets/photos/a.webp`，服务端就存这个字符串。

而全仓库**没有任何上传路由**：

```
app/api/ 下只有：health、dogs/[id]/trips、trips/[id]、trips/[id]/start、trips/[id]/finish
没有 upload，没有文件的接收端
```

我实测了契约对 `photo_url` 的实际把关程度（内存库 + 现有 schema）：

| 塞什么 | 结果 |
| --- | --- |
| `/assets/photos/6mb.jpg`（声称 6MB） | **插进去了** |
| `/assets/photos/a.exe`（不是图片） | **插进去了** |
| `''`（空字符串） | **插进去了** |
| `javascript:alert(1)`（伪协议） | **插进去了** |
| `/assets/photos/a.webp`（正常） | 插进去了 |

**换成人类的话：现在任何人可以让回应里带一张根本不存在的图、一个可执行文件、或者一段脚本。** 界面会裂，而且这是 11-29 冻结后要修的「伪造真实用户内容」类问题。

### 3.3 你要交的东西（四个小件，都是文档，不写代码）

**（1）上传接口的形状——写到能照着实现的程度**

```
POST /api/uploads/photo
入：multipart/form-data，一个文件字段（建议名 file）
出：{ "url": "/uploads/xxx.webp", "bytes": 123456, "mime": "image/webp" }
错：
  413 太大（给出上限，例如 5MB）
  415 格式不支持（只允许 jpg/png/webp）
  401 无会话
```

**要你定的三件事**（我不替你定，因为这是你的模块）：

- **上限多少**——你在 b3 里写了 ≤5MB，我建议就用 5MB，别改
- **要不要压图**——手机原图经常 3–8MB，压到 1600px 长边可能只有 300KB。**我建议压**，理由是演示时网速不可控；但**压图会丢画质，这是产品判断，你定**
- **存哪儿**——放 `public/uploads/`（gitignore 已备好），文件名用随机 ID 不用原文件名（原文件名会泄漏用户本地信息，比如「IMG_20261118_我家的猫.jpg」）

**（2）校验规则，写成表**

每一条都要能回答「不满足会怎样」：

| 检查什么 | 规则 | 不满足时 |
| --- | --- | --- |
| 大小 | ≤ 5MB（或你定的值） | 413，界面就地提示，**已输入的文字不丢** |
| 格式 | 只认 jpg/jpeg/png/webp，**看文件头不看扩展名** | 415。看文件头是因为改扩展名太容易 |
| 尺寸 | 比如最长边 ≤ 4000px（防解压炸弹） | 拒绝或压缩 |
| 归属 | 必须带有效会话；只能传到自己的空间 | 401 |

「看文件头不看扩展名」这条要写清楚——只查扩展名等于没查，`a.exe` 改成 `a.jpg` 就过了。我在上面实测过 `.exe` 那条能插进去，就是这个原因。

**（3）失败时的界面表现（你 b3 已经写了一半，补齐即可）**

b3 修订版里你已经写了：

> 照片失败就地提示体积/格式上限，**已输入文字不丢**；重复提交只产生一条回应（幂等）

这句是对的，保留。要补的是：

- 上传中显示什么（建议：不清空输入框、按钮禁用、给一个可取消的进度）
- 上传失败 vs 回应提交失败，**是两次不同的失败**，提示语要能分清（图没传上去 ≠ 回应没发出去）
- 断网时怎么办（建议：图可以先不发，纯文字也能提交——**这条是 P0 第 6 条「能回文字或照片」的兜底**）

**（4）`photoUrl` 的来源必须收口——这条是请求 c 的**

现状是客户端自报 `photoUrl`。**正确的做法是：`photoUrl` 只能来自上传接口返回的地址，客户端不许自己编。**

这需要 c 在 `POST /api/replies` 加一条校验：`photoUrl` 必须在「本人已上传」的清单里。**这条不归你写，但归你提**——你写进请求里，我帮你递给 c；或者你直接写给我，我并进给 c 的请求里。
