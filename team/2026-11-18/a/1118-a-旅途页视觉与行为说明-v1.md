# 旅途页视觉与行为说明（a 补的漏项）

> **出 a，2026-11-18。给 E 看（主要用于 e4），c、b 也要看。**
>
> **先说清楚这份文件为什么存在：** 「旅途主画面」这个名字在 02 和 e3 里出现了很多次，e4 的交付物里就有它，e1 也已经交了六张旅途稿——**但「它长什么样、显示什么、不显示什么」从来没有被定义过。** 这是我的漏项：11-15 那份《给E-标注与线框》里「旅途」这个词一次都没出现。E 那六张稿是自己发挥的，不是照规格画的。
>
> 用户 11-18 明确了两件事，这份文件把它们落成可执行的要求。**以后再有旅途页相关的争议，以这份为准；和 02/e3 冲突的地方，这份优先，因为它是用户当天拍的。**

## 一、用户 11-18 拍的两条（原话要点）

| # | 决定 | 后果 |
| --- | --- | --- |
| 1 | **倒计时不要** | 旅途页不出现「距离回家 01:59:42」这类任何形式的倒计时 |
| 2 | **旅途页走方案 B** | 出门期间不实时展示路上发生的事；归来了才看到全部发现 |
| 3 | **背景图「陌生地点感」可以由 AI 生成，不强制实时** | 空闲时提前生成几页存着，需要时放上去；**旅途页不承担实时功能** |

「方案 B」的含义，用一句话说：**旅途页是一个「它现在出门了」的画面，不是一个「它正在每分每秒走到哪」的直播。**

## 二、页面上有什么、没有什么

### 2.1 有的

| 元素 | 说明 |
| --- | --- |
| **一张场景画**（背景） | 侧视或正视的像素风景：阿尔卑斯山、故宫、陌生的老街、便利店门口。**这一张就是「它去了哪」的全部信息** |
| **刘看山** | 站在画面里，可以有一点原地小动作（呼吸、张望、摆尾）。**不要求逐帧走路动画** |
| **一句状态话** | 例如「出门走走」「在街上待一会儿」。**不带时长、不带倒计时、不带进度** |
| **归来后的发现** | `finds` 到了才显示：3–5 条，其中至少 1 条知乎内容带可点原文（P0 第 4 条） |
| **归来的一句话** | b 写的那句 `message` |
| **返回小屋的入口** | 旅途页不是死路，随时能回小屋 |

### 2.2 没有的（明确禁止）

| 禁什么 | 为什么 |
| --- | --- |
| **倒计时 / 「还剩多久」/ 进度条** | 用户 11-18 明确不要。禁词表里有 `还剩`，倒计时在功能上等价 |
| **实时地点**（「正在咖啡馆」） | 契约里 `trip` 表没有「当前地点」字段，只有 status 和几个时间戳。写「正在某处」就是编造，撞不变量四 |
| **实时滚动的发现列表** | 方案 B：发现攒到归来才给。c4 现在的实现就是「finish 只读已有 finds」 |
| **自动闪烁 / 摇晃吸引互动** | e1 v3 第 39 行：「本轮静态，不用自动闪烁或摇晃吸引互动」 |
| **催促类文案** | 禁词表：连续/打卡/天数/坚持/别忘/快回来/还剩/已过期/差一点/加油/你还没/已经很久/太棒 |

## 三、背景图怎么来（这一条回答「能不能 AI 生成」）

**可以，而且推荐。** 但要分清两件不同的事，之前混过一次，这里写死：

| | 实时生成（**禁止**） | 静态素材（**允许，推荐**） |
| --- | --- | --- |
| 什么时候出图 | 用户每次打开页面时现生成 | 开发/空闲时提前生成好，存成 PNG |
| 断网 | 白屏 | 正常显示本地文件 |
| 一致性 | 每次可能不一样 | 同一张 PNG，永远一样 |
| 成本 | 每次打开都要钱 | 一次性 |
| 出处 | 生图 SOP 第四步：降采样 → 量化到 16/32 色板 → 最近邻放大 | 同上，正是为固化素材服务的 |

**用户 11-18 的原话意思是第二种**：空闲时生成几页存着，需要时放上去。**这不是「每次渲染都生成」，所以 02 第 598 行那句「绝不能生成」不适用于这里**——那句防的是实时生成。

### 3.1 落地方式

- **谁是权威**：**E**。背景图的画风、色调、尺寸由 E 定，E 负责把它们做成正式素材（e2c / e12 的范畴）。
- **谁生成**：谁有生图通道谁生成，但**必须过 E 的画风核对**。未经 E 认可的图不进正式素材。
- **存哪**：**新开一个目录** `public/assets/journey/`，不放 e2 v2 已经规划好的 `public/assets/scenes/{far,mid,ground,props}/`。
  理由：那两个体系不是一回事——`scenes/` 是给 c11c 做多层拼装用的（远景/中景/地面/道具分层），旅途页用的是**单张整图**，混进同一个目录会让 c11c 误以为它是可分层的层片。
  命名沿用 e2 v2 第 3 节规则：`{场景}-{状态}-{宽}w.{格式}`，例如 `alps-day-1200w.png`、`oldstreet-dusk-1200w.png`。（正式目录名待 E 确认，**E 有命名决定权**；本条只提出「不要和 scenes/ 分层素材混放」这个要求。）
- **怎么切**：「陌生地点感」优先做成**单张整图**（一整幅风景），不做 02 那套「远景/中景/地面/道具」多层拼装。理由：旅途页只需要「换一张背景」，不需要组合。
- **要几张**：先做 **3–5 张**能覆盖 P0 演示的（一个山、一个城市、一个街区），不够再加。**不要一开始做 30 张。**

### 3.2 和 e2c 的关系

e2c（11-22，「场景分层素材约 30 张」）是 **02 原来的多层拼装方案**。**本文件不废除 e2c**，但明确：

- e2c 服务的是「需要组合变化的场景」（天气/时段/道具不同的同一个地点）
- **旅途页的「陌生地点」用单张整图就够，不必等 e2c**
- 如果 e2c 的素材能拼出旅途页，也可以直接用，但**不作为前置要求**

**这条的意思：e4（11-20）不要等 e2c（11-22）。** 先用现有概念图或 3–5 张单图把画面做出来。

## 四、页面结构（给 E 落布局用）

```
┌─────────────────────────────────┐
│  ← 回小屋                       │  ← 返回入口，一直可用
├─────────────────────────────────┤
│                                 │
│      ┌───────────────────┐      │
│      │                   │      │
│      │   场景画（背景）    │      │  ← 一张整图，撑满主区
│      │                   │      │
│      │    [刘看山]        │      │  ← 角色在画面内，可原地小动效
│      │                   │      │
│      └───────────────────┘      │
│                                 │
│      出门走走                    │  ← 一句状态话，不带时长
│                                 │
├─────────────────────────────────┤
│  它回来了吗？                    │  ← 归来前：这一块是空的/等着的
│  （归来后显示 3–5 条发现）        │     归来后：发现列表 + 一句话
│                                 │
└─────────────────────────────────┘
```

**关键尺寸要求**（02 的验收是「手机竖屏一屏内能做完」，这里给可测量的标准）：

- 手机 375×667 下，场景画高度 **不小于 320px**（占上半屏）
- 状态话一行，**不超过 20 字**
- **主要操作按钮（返回、回应）≥ 44px 高**，两侧留 ≥ 8px 间隔（e1 v3 第 38 行）
- 一屏内必须能同时看到：场景画 + 状态话 + 归来区域（或它明确的占位）

## 五、四态（02 对 e4 的验收就是这四条）

| 态 | 画面 | 文案约束 |
| --- | --- | --- |
| **空**（没有进行中的出行） | 小屋是主阵地，这里显示「它在家」或直接回小屋 | 不显示假的「出门了」 |
| **加载**（正在读 trip） | 场景画先显示，发现区给占位 | **不超过 2 秒**；不用转圈催 |
| **失败**（读取失败） | 场景画保留（它确实出门了），发现区说明读不到 | 「暂时读不到」+ 重试；**不允许 POST 新旅途来"修复"** |
| **降级**（断网/接口未接） | 已缓存内容可看，明示这是本地数据 | 不冒充最新；缺图用静态回退 |

**e3 v3 第 196 行原话**：「finds=[] 用『今天没找到合适的』；running 非空；GET 反馈 ≤2 秒；读取失败可重试读取，不能 POST 新旅途。」

## 六、轻动效（用户要的）

用户 11-18：「参考上图，但是添加一点动效」。允许的动效，**全部是装饰性的，不承载信息**：

| 动效 | 允许 |
| --- | --- |
| 角色呼吸/轻微起伏 | ✅ |
| 角色眨眼、摆尾 | ✅ |
| 背景里的飘叶、风、光线缓慢流动 | ✅ |
| 云缓慢移动 | ✅ |
| 自动循环切换背景（"走走停停"感） | ⚠️ 需 E 判断。**可以**，但它不能暗示"已经走到下一个地方了"——那是实时地点信息 |

**硬约束**：`prefers-reduced-motion` 开启时，去掉所有动效，**信息一个都不能少**（e1 v3 第 39 行）。

## 七、关于「走走停停、拍照、路过便利店」

用户 11-18 描述的游戏模式里有这些。**在当前方案下它们属于「归来后才知道的事」，不是「实时看到的画面」。**

具体说：

- **「它路过了便利店」** → 是一条 `find`（`kind='moment'`），归来了才显示
- **「它拍了张照」** → 也是一条 find，带 `asset_path`
- **「它停下来看了一会儿」** → 现在**没有对应字段**，除非做场景文案

**如果以后要做成实时可见**，需要 c 在 `running` 期间写 find，那是另一件事，要单独拍板。**当前不做。**

## 九、边界

- **这份文件不改任何契约**，`trip` 表不加字段，`find` 表不变。
- **不要求倒计时、不要求实时地点**——这两样都需要契约改动，用户已明确不要倒计时。
- **不废除 e2c**，只是明确 e4 不等它。
- **E 的画风决定权不变**。这份文件只管「旅途页有什么、没有什么」，不管「画成什么样」。
