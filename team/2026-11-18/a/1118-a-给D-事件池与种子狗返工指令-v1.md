## 一、你的 30 条事件 SQL 现在一行都进不了库（必须改）

**结论：`1117-d2c-事件池三十条-v0.sql` 原文件执行会直接报错，我已实测。**

c 的 `event` 表是 **12 列**，你的 SQL 列清单是 **13 列**，多的那一列是 `created_at`：

```
c 批的 12 列：
id, code, text, season, weather, time_of_day,
place_tags, match_tags, weight, cooldown_days, asset_refs, enabled

你的 SQL 第 11/19/27… 行（共 30 处 INSERT）：
..., asset_refs, enabled, created_at)      ← 多这个
```

**实测报错（我在 c 的分支上跑的原文件）：**

```
table event has no column named created_at
event 表里现在有: 0 条
```

**我按 c 的说明做过一次 12 列投影验证，证明确实只差这一处：**

```

event 行数: 30
enabled=1: 30
幂等再执行行数: 30
```

所以**不是数据要重写，是机械改两处**：删列清单里的 `created_at`，删每行 VALUES 末尾对应的那个时间值（`'2026-11-17T00:00:00Z'`）。30 条都要改。

**改完自己验一遍再推**，命令照抄：

## 二、你的 `ON CONFLICT DO UPDATE` 漏了 `asset_refs`（顺手改）

你文档里写「只更新 d 写的列」，但 SQL 末尾实际更新的是这 8 列：

```sql
text, season, weather, time_of_day, place_tags, match_tags, weight, cooldown_days
```

**漏了 `asset_refs`。** 它也是你的列（e2c 11-22 才填素材引用）。漏掉的后果：以后重跑导入时，已经填进 `asset_refs` 的素材引用**刷不进去**，等于白填。

补上就行。`enabled` 不用动——那是开关列，重跑不该把它改成 1。

改完末尾应该是：

```sql
ON CONFLICT(code) DO UPDATE SET
  text = excluded.text, season = excluded.season, weather = excluded.weather,
  time_of_day = excluded.time_of_day, place_tags = excluded.place_tags,
  match_tags = excluded.match_tags, weight = excluded.weight,
  cooldown_days = excluded.cooldown_days, asset_refs = excluded.asset_refs;
```
