## 数据与读写契约

| 增量 | 内容 |
| --- | --- |
| wish.source | owner / collection，NOT NULL，旧记录默认 owner |
| wish.source_url | owner 为 NULL；collection 为服务端校验、规范化的 HTTPS 知乎内容 URL |
| v_wish_active | 明确投影 8 列，唯一有效条件为 revoked_at IS NULL |
| uniq_wish_active_collection | 同一狗最多一条未撤销的 collection 心愿 |
| uniq_wish_collection_content | 同一狗、同一规范 URL 永久去重，包括已撤销记录 |
| trip.wish_id | 可空外键指向 wish；同狗约束，出发后不可改关联 |
| idx_trip_wish | 历史关联索引 |

心愿不物理删除；撤销使用 `WHERE revoked_at IS NULL` 条件更新，重复请求返回原记录和首次时间。
数据库拒绝覆盖首次撤销时间或恢复为 NULL。id/dog_id/source/source_url 创建后不改写，防止来源漂移。
没有冻结心愿 text 编辑，也没有把心愿原文或收藏来源放进 Snapshot。

规范 URL 支持：

- `https://[www.]zhihu.com/question/Q` → 统一 www 主机。
- `https://[www.]zhihu.com/question/Q/answer/A` → 保留问题及回答两个 ID。
- `https://zhuanlan.zhihu.com/p/P` → 保留文章 ID。

ID 是无前导零的正十进制字符串，不转 number；去除全部查询参数、fragment 和一个尾部斜杠。
协议与主机大小写归一。拒绝非 HTTPS、其他主机/子域、凭据、显式端口、编码路径/主机、
点路径、控制字符/空白/反斜杠、短链、个人/收藏列表和未纳入白名单的路径（包括 `/answer/A`）。
不跟随重定向，不猜内容 ID，不把回答折叠成问题。规范规则完整写在 `contracts/api.md` 心愿节。
地址校验不代表内容存在、收藏归属已验证或 OAuth 已完成。

## B / C / E 接入方式

`lib/wishes/contract.ts` 提供五个边界函数和来源字段映射：

| 调用 | 用途 |
| --- | --- |
| ownerWishFields(body) | 公共表单只允许 text/category，强制 owner/null，拒绝所有来源或 session 附加字段 |
| collectionWishFields(db, dogId, sessionId, verifiedSourceUrl) | 仅供已完成授权和收藏归属验证的服务端流程；检查狗归属、规范化 URL，不写数据库 |
| revokeWish(db, wishId, sessionId, serverUtcTime) | B 复用的条件撤销存储边界，自带 BEGIN IMMEDIATE；不可再包嵌套事务 |
| selectActiveWish(db, dogId, sessionId) | C5/C6 复用有效视图；owner 优先 collection，无候选为 null |
| readTripWish(db, tripId, sessionId) | 按历史 trip.wish_id 读取基础表，允许读到已撤销心愿，不用当前候选替换历史 |

B 的公共 POST/PATCH/GET 路由本次未实现。sessionId 必须来自共享 `lib/auth/session.ts`，不能由请求字段传入。
不存在和越权均 NOT_FOUND；参数、唯一约束和来源冲突用既有 CONFLICT，无新错误码。
B 收藏插入须在自己的 `BEGIN IMMEDIATE` 事务内检查归属并写入，使用普通 INSERT 和明确列清单；
不得用 INSERT OR REPLACE、删除重建或复活旧记录绕过历史保留。
收藏是否可导入、按收藏时间挑选哪条材料、提取失败如何处理，继续遵守 A 的 a3b 规则，未在此重复实现。

同来源候选按 created_at 的实际时间倒序、id 升序稳定选择，作为确定性的技术排序写入契约。
blocked_topics 仍是最高优先级；本函数只选择候选，C5 搜索前仍须执行既有屏蔽过滤。
E 读取持久化 Wish.source 显示来源，自动选择收藏主题也不能标成主人原话。

## 出行集成与历史

只在现有 `trigger='wish'` 的 start 写事务中增加有效心愿查询及 wish_id 绑定。
pending 创建时不锁定心愿；pending 期间的撤销会被实际出发前的重新读取排除。
归属、额度/间隔检查、选择、running/started_at 和信箱投递在同一个既有事务内。
并发撤销与出发按事务提交顺序决定：先撤销则不选；先出发则保留该趟历史关联。

五态转换、seq、上海日限额、六小时间隔、投递器唯一写 delivered_at、700ms 轮询均保持原逻辑。
没有候选时 wishId=null；重复 start/finish 不重选、不改关联。auto/friend 本轮不增加选题行为。
未来自动执行器选择心愿时可复用既有 wish trigger；不增加 collection trigger。
旧 trip 的关联保持 NULL，不根据当前心愿反推过去。撤销之后，历史仍能读到原来源和关联。
