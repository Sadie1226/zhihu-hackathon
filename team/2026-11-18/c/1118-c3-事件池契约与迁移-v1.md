## 数据库与类型

`event` 列顺序：

```text
id, code, text, season, weather, time_of_day,
place_tags, match_tags, weight, cooldown_days, asset_refs, enabled
```

没有 created_at。id 非空主键，code 非空唯一；text 1–40 字符，空字符串/纯空格拒绝。season/weather/time_of_day 使用已批准枚举。place_tags 与 match_tags 必须是 JSON 数组；INSERT 和 UPDATE 触发器拒绝未知值、null、数字、布尔、对象及嵌套数组。match_tags 只允许现有六类兴趣。

weight 为正数、默认 30；cooldown_days 非负、默认 7；拒绝非数值文本和 NULL。asset_refs 必须是 JSON 对象，默认 `{}`；enabled 为 0/1，默认 1。所有 12 列非 NULL。

`Event` 使用既有 camelCase 风格，JSON 字符串在读取边界解析，enabled 转 boolean；不重复定义 InterestCategory，不更改旧类型。assetRefs 暂为 `Record<string, unknown>`，内部素材键留给 E2c 对齐。

`trip_event` 只有 trip_id、event_id、dog_id、happened_at，四列非空；前三列分别引用 trip、event、dog。主键 `(trip_id,event_id)`，索引 `idx_trip_event_dog(dog_id,happened_at)`。happened_at 沿用 UTC ISO-8601；没有级联删除。C 后续写入方负责 dog 与 trip 的业务归属一致性；本轮不实现写入业务。

event 是 **D 维护的候选池**；trip_event 是 **C 写入的历史事实**。不能把尚未抽中的候选伪装成实际经历。

## 迁移验证

继续使用 C2 的 `PRAGMA user_version` 和 `BEGIN IMMEDIATE`，bootstrap 实现未修改。版本 2 迁移为纯增量 CREATE，不删除、清空或重建旧业务表。

新库先执行当前 schema，再通过同一迁移列表完成版本标记；新增对象使用 IF NOT EXISTS，避免重复创建。旧库从 version 1 直接执行固定版本 2 DDL，不重跑整份 schema。版本与 DDL 在同一事务提交。

实际测试使用独立临时文件和内存库，不操作用户 `data/app.sqlite`：

1. 用冻结的真实 v1 schema 建 10 表旧库，写入现有 fixture 的 2 只狗、3 次 trip、4 条 exchange。
2. 升级到 version 2；逐列比较这三类全部记录，逐对象比较原有 schema 定义，均保持一致；`PRAGMA foreign_key_check` 返回空数组。
3. 写入测试事件和历史后反复初始化、关闭重开，两张新表与旧业务数据均保留，重复初始化没有数据写入。
4. 与新空库初始化生成的事件表、索引、触发器比较，DDL 在统一换行后完全一致。
5. 在迁移末尾注入无效 SQL：version 保持 1、新对象全部回滚、旧数据保持；移除故障后重试成功。

旧 main 实际只有 `v_invitation_state` 一个视图，本次保持原样；没有为追随旧文档的“两个视图”说法另造视图。此次迁移仅增加事件基础，不顺带修复更早数据库的其他契约差异。

## D 的接入方法

1. 等 A 合并后从最新 main 开分支，通过 Node 24+ 的 `openDatabase()` 打开目标库，确认 `user_version=2`、foreign_keys=1；不要对已有库重跑 schema.sql。
2. 将 D 的 v0 SQL 从 13 列对齐为 12 列：移除 created_at 列和对应时间值，保留其他业务值与 code 的 UPSERT 语义。
3. 在同一个事务中导入，再检查 event 条数及 `PRAGMA foreign_key_check`；导入失败回滚，不修改 trip_event。
4. `place_tags=[]` 表示不限地点，不能作为未填占位。非空时与 availablePlaces 的交集非空才匹配；没有匹配时返回 null，非错误。这些是下一任务选择器的规则，本轮仅记录契约。
5. E2c 提供可用引用前 asset_refs 保持 `{}`；后续只更新素材引用，不为了素材问题抹掉地点语义。

本次实测输入为 D 分支提交 `e3a1c78` 中的 `team/2026-11-17/d/1117-d2c-事件池三十条-v0.sql`，blob `3751eeee3c8b251c262e9ef1d8580b3ddfdd5c91`。从 Git 导出到忽略目录后，在独立内存库装载其原 13 列数据，再原值投影批准的 12 列导入新表；没有重写 D 的源文件或业务数据。
