## 三、d 定死的口径（别人要照着对接）

### 3.1 四件事不许合并

```
id / from_dog / to_dog / kind / payload / deliver_after_trip_seq / created_at   ← d 写
delivered_at                                                                    ← c 独占（投递器）
replied_at                                                                      ← b 独占
read_at                                                                         ← e 独占
```

有人想「顺手在投递器里把 `replied_at` 也写了」，就是绕过 b，联调会出现「礼物到了但显示已回应」。

### 3.2 `deliver_after_trip_seq` —— d 不传，c 算

- **d 说「寄给谁、寄什么」，c 查收件狗当前 `seq` 再加一。**
- 这个 `+1` **谁都不许去掉**。去掉就是当场到达，不变量二当场破。
- 判断到达用 `isDeliverable()`（`types.ts` 里已有），不要写 `now > 某时间戳`。

### 3.3 关系类事实只有 d 写

e 的朋友圈、b 的「它记得你回应过」、a 的验收表，**全部只读 d 写下的那一份**。
两处各算一遍 = 两个版本 = 用户觉得被骗（不变量五）。

对外只暴露两个读口（c3 v2 定义）：

| 接口 | 谁调 | 返回 |
| --- | --- | --- |
| `GET /api/dogs/:id/relations` | e | `{ relations: RelationView[] }`，含 `otherDog` 四字段白名单 + 对方最新 snapshot |
| `GET /api/exchanges?from_dog=:id` | e | `{ exchanges: Exchange[] }`，发件全量，`createdAt DESC` |

**注意：`GET /api/relations` 不是规范路由**，没有全局关系列表——那会越权。

### 3.4 种子狗的边界（e 最容易踩）

- `is_sample = 1`、`session_id = 'seed'`，就在 `dog` 表，**没有第二个池子**
- **不伪造主人回应**：种子狗收到的 `co_owner_message` 永远不会有回应。界面在**发出去那一刻**就要写「这是一位示例伙伴，可能不会回话」
- 每只种子狗**必须至少有一条 `seq=1` 且 `startedAt` 非空的 trip**，否则寄给它的东西**永远显示「在路上」**，演示像坏了

### 3.5 邻居匹配（d2 定，e/a 只读）

排除自己 → 排除同 session → 排除已拉黑 → 优先没交换过的 → 标签有交集的桶内**真随机** → 一次只遇一只。

`relation` 表有 `CHECK (dog_a < dog_b)` 字典序约束，**写入必须 `MIN()/MAX()` 排序**，否则 SQLite 当场拒写。

### 3.6 payload 白名单（c 校验时用同一个口径）

`payload` 只允许契约里那几个键，**多一个键就拒**。这样「塞一句主人聊天原文进去」不用语义识别就能拦住——`chatText` 不在名单上，内容根本不会被读。

四种形状见 `api.md` 第三节，d 的 `rules.ts` 会做运行时校验。

a 在 `b60fe24`（11-16 晚）改了契约，**三处直接影响对接口径**：

### 4.1 装配单：六键 → 四键

```diff
  {
-   "base": "tpl-a",
-   "skin": { "color": "brown", "pattern": "solid" },
    "cloth": "jacket",
-   "hat": "none",
+   "hat": null,

```

- 删 `base`（体型）/ `skin.color` / `skin.pattern`。理由：刘看山 IP 只有一种体型一套配色，**边界不留位置**
- 剩下四键：`cloth` 6 + `hat` 4 + `glasses` 4 + `face` 4 = **18 张部件、384 种组合**
- `d2` 第 180、207–224、237 行的六键写法**全部作废**，20 只种子狗的分布表要按四键重排

### 4.2 `gift` payload 新增 `imagePath`

```jsonc
{ "kind": "gift", "giftName": "...", "note": "...", "imagePath": "/assets/gen/xxx.webp" }
```

三样（名字、附言、图）**必须同一步定稿一起落库**，`imagePath` 可空；空时界面退纯文字，不留空白框。

### 4.3 `find` 表新增 `assetPath`（表字段，不是 payload）

三种 `kind` 都可空，**空不等于失败**——生成失败退纯文字，界面不留空白框。
