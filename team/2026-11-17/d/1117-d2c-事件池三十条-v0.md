## 二、三个口径要先钉住，否则表建出来是错的

### ① 列数是 13，不是 12

C 说「12 列和你提的一字不差」。我 11-16 提的是 **13 列**：

```
id  code  text  season  weather  time_of_day
place_tags  match_tags  weight  cooldown_days
asset_refs  enabled  created_at
```

少的那一列请点名。我的建议是**删 `created_at`，别删 `enabled`**：

| 如果删的是 | 后果 |
| --- | --- |
| `created_at` | 无所谓。30 条一次性写入，没人按时间查 |
| `enabled` | **e2c 说某个素材做不出来时，我没有别的办法关掉那一条**。只能改 `place_tags` 或删行，两种都会破坏语义 |

`enabled` 是「这条暂时不上」的唯一开关，我 11-16 的文档第 67 行写的就是它。

### ② `place_tags` 不能留空——空不等于「还没填」，等于「任何场景都成立」

我的 CHECK 里 `'[]'` 的语义是**这条事件不挑场景**，不是占位。30 条里我只让 4 条是 `'[]'`（草绿、蝉、鸟、月亮，本来就不依赖道具）。

如果为了等 e2c 把 `place_tags` 全填 `'[]'`，结果是：**抽到「冰淇淋摊」时，这一趟根本没有摊位，场景合成器只能硬塞一个摊，或者丢弃。**

正确做法是现在就填语义标签（`street / stall / riverside / bookstore`，就是你批的值域，**不是素材名**）：

- 填了 → 抽签时按「本次出行可用场景 ∩ `place_tags` ≠ ∅」过滤
- e2c 说某个场景做不出来 → 把受影响的事件 `enabled = 0`，**不是**把 `place_tags` 抹掉

**要等 e2c 的只有 `asset_refs`（素材引用），不是 `place_tags`（语义标签）。** 两者别混。

### ③ `weather` / `time_of_day` 不需要素材，不用等 e2c

C 把 `morning`、`snow` 也列进了「e 现有素材清单里还没有」。这两个是**抽签的过滤条件**（这一刻是早上吗、在下雪吗），不是要渲染的图。

只有两样要跟 e 对齐：`place_tags`（有没有这个场景图）和 `asset_refs`（具体引用哪张）。`weather` 列写 `snow` 不需要 e 画一张雪。

如果 e 真的做不出雪景，那是 `asset_refs` 的事——把雪天事件指向一个通用冬景，或者关掉。**列的值域不用改。**

## 四、我需要 c 的抽签函数给我什么

C 说函数他写、我直接调。那接口得先说清，不然他写完我调不上。

**入参**

```ts
pickEvent({
  dogId: string,
  tripId: string,
  context: {
    season: 'spring' | 'summer' | 'autumn' | 'winter',
    weather: 'clear' | 'rain' | 'snow',
    timeOfDay: 'morning' | 'dusk' | 'night',
    availablePlaces: string[],   // 这次出行实际有的场景标签，来自 a

```

**三条行为要求**

1. **`place_tags = '[]'` 视为不限**，不参与交集判断；非空时必须与 `availablePlaces` 有交集。
2. **返回 `null` 是合法的**，不是错误。这一趟没有合适的事件就不出——a 的验收允许「有些出门什么也没遇到」，界面不许因此报错或补一句「今天没有新鲜事」。
3. **`trip_event` 由 c 在这条函数里一起写**（`trip_id` / `event_id` / `dog_id` / `happened_at`）。d 只读，不写——一个事实一个写入方。

`availablePlaces` 为空数组时，只有 `place_tags = '[]'` 的 4 条能出。这是对的：没有场景素材，就只能讲不依赖道具的事。
