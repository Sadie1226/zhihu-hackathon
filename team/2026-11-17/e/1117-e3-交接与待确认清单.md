## 1. 三个核心页面：关系与跳转

### 1.1 三页定位

三张关键稿与页面的对应关系：

| 页面 | 关键稿 | 一句话主题 | 首屏主信息 | 主操作 | 明确不是 |
| --- | --- | --- | --- | --- | --- |
| **小屋** `/home` | `1116-e1-小屋关键稿-视觉层级-v2.png` | 陪伴与生活 | 角色／在家或归来状态、归来一句话、已有邀请 | 看看来信、翻手账、查看状态 | 不是任务面板、不是出门按钮、不是签到 |
| **旅途** 从小屋进入 | `1116-e1-旅途关键稿-视觉层级-v2.png` | 探索与发现 | 路景意象、归来一句话、发现列表 | 看这次发现、查看已有邀请 | 不是地图、不是路径追踪、不是出行控制台 |
| **朋友来信** `/mailbox` | `1116-e1-朋友来信关键稿-视觉层级-v2.png` | 情感与交流 | 收发列表、已到内容、邀请区、朋友入口 | 打开已到内容、回应、捎话 | 不是即时聊天、不是 Exchange 第五种 kind |

- 三页同一世界、同一像素基线、同一套主导航；**信息结构不同**，不互相替代。
- 主导航保持四项：**小屋／来信／手账／朋友圈**；旅途从小屋进入，不占第五项；朋友、珍藏、交流放在相应上下文。
- 三页都不显示红点、未读计数、连续天数、进度条、倒计时或“对方正在输入”。
- 本文以三张关键稿对应的核心页为主；E3 的完整页面集合还包括领养、手账、朋友圈、各详情与面板，它们在 §1.2 的跳转表中作为相邻页出现。

### 1.2 跳转与返回

返回总则（来自 E3 v3 §4）：

1. **有可靠应用内来源就回来源**；直接链接或刷新丢失来源时，用上表兜底。
2. 禁止无条件 `history.back()` 把用户送到站外或空白页；不劫持浏览器原生返回。
3. 外链原文与产品内返回分开；开外链不丢当前阅读位置。
4. 失效详情给返回入口，**不重发写请求“修复”**。
5. 邀请从来信、旅途、手账打开时分别回对应入口，**不能固定跳小屋**。

### 1.3 三页之间不能做的事

- 旅途页不能“再出门”：查看、刷新、返回只允许 GET，不触发出行三个 POST（创建／开始／结束）或新邀请。
- 来信页不是聊天页：主人不能在这里与对方主人即时对话；捎话必须经一次投递。
- 打开来信列表、滚动、预取都**不写已读**；只有真正打开已到内容才 `PATCH read`。
- 手账不重建经历：只合并已有 trip／find／exchange／invitation，按 ID 去重。
- 朋友圈没有主人发帖、点赞、评论按钮；数据来源未决前只做空态或显式示例。
- 草稿只属于本机当前上下文；切换伙伴或主人时不能串入另一只狗／另一位主人。

## 2. 两条核心流程

完整流程图见 `1116-e3-页面流程-v3.md` §2（主人导航，20 节点／44 边）与 §3（伙伴自主生活，13 节点／14 边）。下面是可以直接对照实现的步骤表。

### 2.1 主人操作流程（页面上的边）

| 步 | 主人看到／做什么 | 页面／面板 | 读或写 | 归属 |
| --- | --- | --- | --- | --- |
| 1 | 进入产品 | 无有效伙伴 → 领养；有 → 小屋 | 读伙伴上下文 | A |
| 2 | 起名、选 2–3 个喜好、点“就这样吧” | `/adopt` | `POST /api/dogs` | A |
| 3 | 看到角色、状态、归来一句话、已有邀请 | 小屋 | `GET dog`、`GET trips`、`GET invitations` | C 数据，E 呈现 |
| 4 | 点“说话”，输入近况 | 交流面板 | B 接口未决 | B |
| 5 | 说心愿、撤销心愿 | 心愿面板 | `POST/PATCH/GET wishes` | B |
| 6 | 点“查看状态”，看本次旅途与发现 | 旅途／归来 | `GET trips`、`GET finds`；700ms 轮询 | C |
| 7 | 点“看看来信”，打开一条已到内容 | 来信 → 详情 | `GET inbox`；打开时 `PATCH read` | C 读，E 写 readAt |
| 8 | 回应邀请／交换，或写一段捎话 | 回应面板／捎话表单 | `POST replies`、`POST exchanges` | B／D 规则，C 门槛 |
| 9 | 翻手账、看朋友圈 | 手账／朋友圈 | 本地记录＋已有读取 | E |

关键边界：

- 第 3、6、7 步的“看”不产生新的出行、不生成邀请、不写已读。
- 第 8 步“捎话保存成功”只表示记录已创建、在路上；**不说“对方已收到”**。
- 回应是 B 的唯一能力；E 不另写 `repliedAt`，不把空回应或校验失败当成功。

### 2.2 伙伴与服务端的自主生活（页面外的边）

| 步 | 执行者 | 发生什么 | 写入 |
| --- | --- | --- | --- |
| 1 | B | 已保存心愿、主人回应成为材料 | 心愿／回应 |
| 2 | C（D 提供事件／朋友） | 伙伴自主选择出行 | 计划，不落库 |
| 3 | C | 创建 `pending` 出行，`seq` 自动 +1 | Trip |
| 4 | C | 启动出行：`running`＋`startedAt`；同一事务投递 | Trip；`deliveredAt` |
| 5 | C＋D | 沿途发现、结识、交换 | Find；Exchange |
| 6 | C | 结束出行；B 写归来一句话 | Trip 状态；Message |
| 7 | C | 返回 `done／timeout／failed` 与真实结果 | 结果 |
| 8 | B | 生成具体邀请；待回应已 3 条时返回 `wentAlone` | Invitation |
| 9 | B | 主人可回应，也可不回应 | Reply |
| 10 | B → C | 回应成为下次材料；D 的交换经 C 计算投递门槛 | 下一轮材料 |

投递支线：D 创建交换 → C 计算 `deliverAfterTripSeq`（收件狗当前 seq＋1）→ 收件狗**下一次出行开始**时写 `deliveredAt` → 来信显示“已到”。

### 2.3 一次完整闭环的验收点

1. 它出门 → 带回发现 → 发出具体邀请 → 主人可回应 → 回应成为下次材料。
2. 一次出行目标 3–5 条发现，至少一条 `kind='zhihu'` 且 `sourceUrl` 可点。
3. 零发现、`timeout`、`Message=null` 都必须能平静呈现，不补假内容。
4. 延后到达按“第几次出行”计算，不按时间；演示时拨一次出行就到。
5. 邀请永不过期；待回应上限 3 条，第 4 条改“它自己去了”。
6. 已回应也算已读（`readAt` 或 `repliedAt` 有值）。
7. 屏蔽主题在 C 搜索、D 交换、E 展示三处都过滤；E 不解释原因。
8. 种子伙伴不伪造主人回复；不显示“正在打字／刚刚活跃”。
9. 在路上不是空状态：`pending／running` 时信箱、手账仍可打开，不催、不空白。
10. `timeout` 是一次正常结束，不是报错；`failed` 要区分实际失败与页面读取失败，保留经历。

### 2.4 两条流程的分界

- 主人只能导航、提交、返回；**不能命令伙伴出发、强制归来或催人回应**。
- E 页面不触发出行三个 POST（创建／开始／结束），也不调用 `POST /api/dogs/:id/invitations`；这些是 C/B 的编排。
- 页面轮询只读进行中的 Trip；结束态停止；不用 SSE。

### 3.3 数据结构与页面边界

- **HTTP 是 camelCase，数据库／fixtures 是 snake_case。** 正式接口在实现边界转换；fixture 加载也要统一适配，不是“只换读取地址就自动接好”。E 页面不各写一套不一致的库行转换。
- **`PublicDogSummary` 只有 `id`／`name`／`assembly`／`isSample`。** 不展开完整 Dog，不展示别人的 `sessionId`、`blockedTopics` 或私有记录。
- **`Message` 与 `Trip` 分表。** `finish` 响应里的 `message` 只属于本次结束；历史读取接口未定义前，手账／旅途历史不能声称能读到旧话。
- **`InvitationView.state` 只从 `v_invitation_state` 来。** 没有 `status`、没有 `expiresAt`、不会返回“已过期”。
- **已读判定：`readAt` 或 `repliedAt` 有值。** E 只写 `readAt`；`repliedAt` 是 B 的。
- **`payload.kind` 是契约要求。** 当前分支 `exchange.json` 四条 payload 缺 `kind`；c3 v2 已补。加载边界不能静默补字段冒充原始数据合格。
- **四种 payload 形状见 `api.md` §三。** 捎话是 `kind='co_owner_message'`，payload 含 `message` 与 `fromOwnerOf`；主人原话只留在这里，不进 Snapshot。
- **排序由接口提供。** 发件按 `createdAt DESC, id DESC`；关系按 `lastMetAt DESC, id ASC`。页面不自己重排成另一套。
- **`deliverAfterTripSeq` 不是时间戳。** 客户端不写；页面只读 `deliveredAt` 判断在路上／已到。
- **屏蔽主题在 E 展示前也要过滤。** 被屏蔽内容不进结果集，不显示、不解释。

### 3.4 还没有读取契约的页面能力

以下不是 E 可以自己补的接口，必须由对应负责人确认：

1. 历史归来一句话、历史回应正文（B/C）。
2. 日常交流与记忆边界（B）。
3. 朋友圈动态集合、种子伙伴集合（A/C/D/E）。
4. 珍藏／笔记的存储与同步（E/C）。
5. 单条发现／单条邀请的读取与深链接（C/B）。
6. 照片上传、永久 URL、失败恢复（C）。

### 3.5 错误与状态的页面口径

| 情况 | 页面表现 | 不能做 |
| --- | --- | --- |
| `NETWORK` | 如实说这次没连上；有缓存则局部降级，没有则失败＋读取重试＋返回 | 不把缺数据说成“不存在” |
| `NOT_FOUND` | “这条已经不在了”＋返回来源／小屋 | 不泄露另一 session 是否有该记录；不返回空集合冒充正常 |
| `CONFLICT` | 就地说明具体哪一条不对，保留已输入内容 | 不统一吞掉；不把校验失败当成功 |
| `BLOCKED` | 什么都不显示，也不解释原因 | 不告诉用户“这个词被屏蔽了” |
| `TIMEOUT` | 一次正常结束的归来 | 不做成红色报错／空状态 |
| `RATE_LIMITED` / `AUTH` | 按 C 的降级路径，内容改用 cache／fixture 并如实标来源 | 不重试限流；不暴露鉴权细节 |
| POST 丢响应 | 说明“提交结果尚未确认”，保留草稿 | 不自动重复 POST；不假称成功或失败 |
| 已读 PATCH 丢响应 | 正文仍可读，`readAt` 保持最后确认值；可手动重试 | 不无限重发；不把未确认当已读 |

状态判断顺序：先看业务态（Trip／Exchange／Invitation），再看页面四态；**不能用一个“加载中”盖住已经在路上的生活**。
