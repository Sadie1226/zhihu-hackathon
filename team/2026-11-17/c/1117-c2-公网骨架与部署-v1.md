依赖直接版本固定，并提交 package-lock.json。实际本机 Node `v24.15.0`、npm `11.12.1`；Next `16.4.6`、React `19.3.1`、TypeScript `5.9.3`。

首页只有项目名、基础服务说明和健康检查链接，供确认服务可打开；最终视觉与组件仍由 E 接入。
唯一新增 HTTP API 是 `/api/health`，不模拟领养、聊天、搜索、社交或其他业务接口。

## 4. 本地启动

在仓库根目录使用 Node.js 24+：

```bash
npm install
npm run dev
```

生产模式：

```bash
npm run lint
npm run test
npm run build
npm run start
```

Windows PowerShell 如阻止 npm.ps1，使用 `npm.cmd`，无需修改执行策略。
默认地址 `http://localhost:3000/`，此地址仅为本机地址，不是公网交付地址。
可从 .env.example 复制非秘密配置到未跟踪的 .env；已有 .env 不得覆盖。本次验证无需知乎密钥。
Next 的监听端口从进程环境 PORT 或命令行 `--port` 读取，不能只把 PORT 写进 .env；DATABASE_PATH 可由 .env 加载。
`dev` 与 `start` 均监听 `0.0.0.0`。

## 5. 数据库初始化与后续迁移

- DATABASE_PATH 默认 `./data/app.sqlite`，自动建立父目录；数据库与 WAL/SHM 不进入 Git。
- 每条连接开启 foreign_keys，busy_timeout=5000ms，请求 WAL；本机实际返回 wal。
- 仅对无用户对象、application_id/user_version 均为 0 的空库执行现有 contracts/schema.sql。
- 用 `BEGIN IMMEDIATE` 串行化检查、建库和版本推进；失败回滚。标记 `application_id=0x5a484831`、`user_version=1`，没有新增业务表。
- 已初始化库不重复执行 CREATE，也不重新读取基线 SQL；重复请求复用成功连接。多进程初始化有专门测试。
- 非空无版本库、其他应用的库、比当前代码新的库与非 SQLite 文件均拒绝打开，不覆盖、不删除、不自动接管。
- 后续在 migrations.ts 从版本 2 起顺序追加已审查 SQL；迁移与版本号一同提交，失败保留原数据与版本。C3 v2 的额外索引未在本次提前加入。
- 不加载 fixture 到运行环境。测试中引用的 fixture 装配单仅用于隔离测试及本机明确标记的持久化检查，不作为 live 数据返回；人工检查标记已清理。

## 6. 健康检查

`GET /api/health` 明确设置 `runtime='nodejs'`、`dynamic='force-dynamic'`，响应 `Cache-Control: no-store`。
执行真实 `SELECT 1 FROM dog LIMIT 1`；连接初始化之后没有业务写入。

成功 HTTP 200：

```json
{"ok":true,"service":"zhihu-hackathon","database":"ok"}
```

失败 HTTP 503：

```json
{"ok":false,"service":"zhihu-hackathon","database":"unavailable"}
```

失败响应不包含异常、路径或配置。ZHIHU_ACCESS_SECRET 不进入客户端配置，原有知乎变量继续保留为空的模板项。
