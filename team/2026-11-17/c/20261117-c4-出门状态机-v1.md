## 3. API 与状态转换

所有成功响应 HTTP 200；缺少/不匹配 session 或记录不存在为 404 / NOT_FOUND；参数、额度、状态冲突为 409 / CONFLICT；数据库不可用为脱敏 503 / NETWORK。所有响应 no-store。

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| `POST /api/dogs/:id/trips` | `{ trigger: 'auto'|'wish'|'friend' }` | `{ trip }`，pending，seq = MAX(seq)+1 |
| `POST /api/trips/:id/start` | `{}` | `{ trip, delivered }`，仅本次投递的 exchanges |
| `POST /api/trips/:id/finish` | `{ status: 'done'|'failed'|'timeout' }` | `{ trip, finds, message: null }` |
| `GET /api/trips/:id` | 无 | `{ trip }`，不改变状态 |
| `GET /api/dogs/:id/trips?limit=10` | limit 为 1–100 整数，默认 10 | `{ trips }`，按 seq DESC；无记录为空数组 |

```text
pending → running → done / failed / timeout
```

创建拒绝同一狗存在另一个 pending/running。仅 pending 能首次 start；running 的 start 重试返回原 trip 与空 delivered，started_at 保持原值。终态不可重新 start。

仅 running 能首次 finish；同一终态重试返回既有 trip/finds，ended_at 保持原值；切换到其他终态返回 CONFLICT。finish 只读取已经存在的 finds，保留 assetPath/sourceMode，不生成发现；B 的归来表达尚未接入，所以 message 为 null。开始与结束均不写 replied_at/read_at。

## 4. 事务、每日次数与时钟

创建、开始、结束使用 `BEGIN IMMEDIATE`。创建事务包含所有权、活跃任务检查、每日额度检查、seq 分配、插入。开始事务重新检查额度与间隔，写 started_at/running 后调用原 `deliverOnTripStart`；投递与状态同时提交，任何一步失败都回滚。事务没有网络调用或 await。

用户在本次会话明确传达 A 的裁定，已落实：

- 所有时间仍存 UTC ISO-8601；上海自然日以 SQLite `date(started_at, '+8 hours')` 计算。
- 只统计实际出发的 started_at，pending 不扣额度。failed/timeout 只要已出发就计入。
- 跨午夜按出发所属日，不按 created_at 或 ended_at。
- 每日上限复用 `TRIPS_PER_DAY_MAX=2`；额度耗尽统一 CONFLICT，修正 api.md 原来的 RATE_LIMITED 表述。
- 出发时复用已批准的 `TRIP_MIN_GAP_HOURS=6`，不会因跨日自动绕过最小间隔。
- 服务端 `createTripService(db, { now })` 可注入时钟，生产默认真实时钟，HTTP 不接受客户端时间。C11 后续应推进模拟现在供新出行使用，不重写历史时间。C4 未实现拨盘，也未设置演示免限额开关。

## 5. 超时与轮询

显式 `finish(status='timeout')` 已实现并测试。服务端执行器入口 `timeoutIfDue(id, sessionId, timeoutMs)` 支持注入阈值；不传阈值即禁用，阈值必须为正整数毫秒。到达阈值后在写事务里结束 running，重复调用不改终态时间。**没有擅定时长，没有自动调度器，GET 不产生超时写入。** 时长由 A 待定，调度属于 C10。

`pollTrip` 立即查询一次，每次非终态响应后 700ms 再查，避免请求重叠。done/failed/timeout 停止；HTTP/网络/无效响应报 onError 后停止，不无限重试。返回停止函数，并接受 AbortSignal；卸载时取消定时器与在途 fetch，忽略迟到的响应。

```tsx
useEffect(() => {
  return pollTrip(tripId, { onTrip: setTrip, onError: setError })
}, [tripId])
```

这是给 E 的接入示例，不修改 E 的组件。

## 6. 会话隔离与队友接入

32 字节密码学随机 cookie，HttpOnly、SameSite=Lax、Path=/，生产 Secure。数据库存 cookie 的 SHA-256 派生 ID，不存 bearer 原值。只使用服务端解析的 cookie 验证 dog.session_id，拒绝 body/query 中的 session_id；未知 cookie 在领养时重新随机签发，不允许客户端指定新会话。

- **A**：领养直接复用 `ensureAnonymousSession(request, db)`，将返回的 sessionId 写库，成功响应附加 setCookie，DTO 不暴露 sessionId。详见 `lib/auth/README.md`；本次没有实现 A 的领养路由。
- **B**：结束返回 message:null；后续接归来表达能力，不在 C4 伪造内容。C4 不触碰回应字段。
- **D**：继续写交换业务字段；C4 开始出行时复用现有投递器，以 seq 投递。
- **E**：用五个契约路由及 pollTrip；生产 cookie 使用 Secure，需要 HTTPS 环境完成浏览器会话联调。HTTP 生产冒烟通过显式 cookie 请求头验证接口，不等于浏览器 HTTPS 已部署。
