# 看山项目功能与交付结构

本文包含两棵树：功能树说明产品由哪些体验与功能组成；交付结构树说明实施时需要准备哪些方案、规范和约定。具体人员安排、任务编号、时间线、依赖和验收标准另见《02-团队实施与验收安排.md》。

## 功能树

产品以治愈、低压力的陪伴为主。狗拥有自己的生活，主人的心愿会影响它；当天的发现与延后到达的礼物穿插发生，主人可以参与和干预。

```text
治愈系自主生活伙伴
│
├─ 1. 伙伴塑造
│  ├─ 1.1 初次领养：命名、初始偏好设定
│  ├─ 1.2 个性生成：结合收藏喜好与随机性生成性格标签
│  └─ 1.3 个性变化：经历逐渐影响兴趣、习惯和表达
│
├─ 2. 主人与狗的陪伴
│  ├─ 2.1 日常交流：聊天、倾听、分享近况
│  ├─ 2.2 心愿表达：告诉它最近想看、想了解的事情
│  ├─ 2.3 归来分享：主动用一句话讲述值得关注的经历
│  └─ 2.4 主人参与：回应邀请、提供照片或文字、表达偏好与边界
│
├─ 3. 狗的自主生活与旅行
│  ├─ 3.1 自主出行：围绕主人心愿、自身兴趣、朋友牵挂行动
│  ├─ 3.2 沿途发现：风景、知乎内容、生活片段
│  ├─ 3.3 偶然事件：陌生相遇、捡到漂流瓶等
│  └─ 3.4 旅途收获：带回纪念物、照片和可分享的发现
│
├─ 4. 狗的社交关系
│  ├─ 4.1 结识朋友：在旅途中认识新伙伴
│  ├─ 4.2 伙伴交流：交换发现、近况和话题
│  ├─ 4.3 持续来往：重访、共同经历、逐渐熟悉
│  └─ 4.4 礼物与托付：传递邀请、照片、礼物，等待后续回应
│
└─ 5. 生活记录与呈现
   ├─ 5.1 朋友圈：自己与朋友的动态、合影、点赞和留言
   ├─ 5.2 消息与来信：伙伴对话、邀请、延后到达的礼物
   ├─ 5.3 旅途手账：回看与珍藏旅途和关系中的经历
   └─ 5.4 好友概览：了解朋友，以及彼此发生过的故事
```

## 交付结构树

五个功能板块分别形成实施包，产品运行规则、美术规范、技术约定和协作验收作为公共支撑。树中的负责人说明责任类型，实际人员与执行安排在另一份文档中确定。

```text
项目实施方案
│
├─ 00 产品总纲                       队长负责
│  ├─ 产品定位与体验原则
│  ├─ 核心体验闭环
│  ├─ 本次交付范围与优先级
│  └─ 时间、预算、决策记录
│
├─ 01 功能实施包                     每包一个负责人
│  ├─ A 伙伴塑造
│  ├─ B 主人与狗的陪伴
│  ├─ C 自主生活与旅行
│  ├─ D 狗的社交关系
│  └─ E 生活记录与呈现
│
├─ 02 产品运行规则                   产品负责人汇总，队长裁定
│  ├─ 时间与出行
│  ├─ 探索与目的地
│  ├─ 相遇与关系
│  ├─ 内容、礼物与分享
│  └─ 主人干预与异常处理
│
├─ 03 美术与交互规范                 设计负责人
│  ├─ 视觉方向与静态主画面
│  ├─ 页面关系与核心操作路径
│  ├─ 角色、场景、物品资产清单
│  └─ 状态表现与交付格式
│
├─ 04 技术与接口约定                 技术负责人
│  ├─ 代码结构与模块所有权
│  ├─ 数据模型与接口契约
│  ├─ AI、记忆与任务执行
│  ├─ 知乎能力、模型与资产接入
│  └─ 部署、费用与故障恢复
│
└─ 05 协作与验收                     集成负责人维护，全员执行
   ├─ 任务认领与交付
   ├─ 分支、合并与接口变更
   ├─ 每日集成与体验检查
   └─ 里程碑、测试与提交材料
```
