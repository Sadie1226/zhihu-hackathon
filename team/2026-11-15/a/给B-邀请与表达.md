## 一、禁词表（不变量三的机器可查版本）

**任何一个字出现在用户可见的地方都算违规，包括按钮、空状态、toast、页面标题、报错文案。**

```
连续  打卡  天数  坚持  别忘  快回来  还剩  已过期
差一点  加油  你还没  已经很久  太棒
```

**「太棒了」也在里面** —— 表扬同样是评价，会让「不回应」显得像做错了事。

### 校验脚本（放仓库根 `scripts/check-words.sh`）

```bash
#!/usr/bin/env bash
PAT='连续|打卡|天数|坚持|别忘|快回来|还剩|已过期|差一点|加油|你还没|已经很久|太棒'
if grep -rnE "$PAT" src/ ; then
  echo "❌ 上面这些词不许出现在用户可见的地方"
  exit 1
fi
echo "✅ 禁词检查通过"
```

**提交前跑一次。有输出就是没做完，不是「文案后面再润色」。**

## 二、12 个标签怎么影响表达（三层，顺序不能反）

### 第一层：先影响「选什么」，不是「怎么说」

**这是最重要的一条。** 两只狗同主题出行，差别要体现在**带回的是哪一条**，不能只换语气。

- `看物` 和 `看人` 两只狗都去「秋天」：一只带回银杏树，一只带回在树下坐着的人的故事。
- `好奇` 和 `恋家` 两只狗：好奇去新地方，恋家重访熟悉的地方。

这一层主要是 c 和 a6 在管，但**你写邀请时要读它** —— 邀请必须接它自己的兴趣。

### 第二层：影响「怎么说」，用字数区间，不用感觉

**这是你能直接写进代码的部分。** 不写区间，AI 每次生成的语气都会飘。

| 标签 | 硬约束 | 怎么检查 |
| --- | --- | --- |
| `话痨` | 一句话 **20–35 字** | `text.length`（中文字符数） |
| `寡言` | 一句话 **8–15 字** | 同上 |
| `自来熟` | 主动提问（句末有疑问或邀约） | 人工看 |
| `慢热` | 只陈述，不提问 | 人工看 |
| `直给` | 结论在前，第一句就是结论 | 人工看 |
| `婉转` | 先说看到了什么，再说想到什么；允许一个比喻 | 人工看 |

**字数区间的校验函数（直接抄）：**

```ts
const LEN_RANGE: Record<string, [number, number]> = {
  '话痨': [20, 35],
  '寡言': [8, 15],
}

export function checkLength(text: string, tags: string[]): { ok: boolean; fix?: string } {
  const clean = text.replace(/\s/g, '')
  for (const tag of tags) {
    const range = LEN_RANGE[tag]
    if (!range) continue
    const [min, max] = range
    if (clean.length < min) return { ok: false, fix: `太短了，${tag}要 ${min}–${max} 字，现在 ${clean.length}` }
    if (clean.length > max) return { ok: false, fix: `太长了，${tag}要 ${min}–${max} 字，现在 ${clean.length}` }
  }
  return { ok: true }
}
```

**字数怎么数（先说清，否则你和我数出来不一样）：**
只去掉空格和换行，**标点算一个字**。就是 `text.replace(/\s/g, '').length`。不按汉字数、不按词数、不算英文单词为一个。上面那个校验函数就是这个口径。

**生成失败时重试一次；第二次还超，就截断或补一句，不要让超长的句子出去。** 一只寡言的狗说了 60 字，整个角色设定当场崩掉。

## 三、邀请必须满足三条，缺一条重写

**这是核心闭环的入口，P0 第 6 条。** 一条邀请不合格，整条「邀请与回音」就落空。

| 必须有 | 长什么样 | 不合格长什么样 |
| --- | --- | --- |
| **一个具体动作** | 「下次看到晾着的被子，拍一张给我」 | 「多陪陪我」「要不要一起玩」 |
| **一个理由** | 「你说过想看老城区，我想知道别人家阳台上晾什么」 | 没有理由，或理由跟它自己的兴趣无关 |
| **一个不做的余地** | 「不方便就算了，我下次自己看」 | 隐含催促，或者不说可以不做 |

### 三个状态不能少

| 状态 | 界面必须做到 |
| --- | --- |
| **它在等** | 明确的回应入口，一屏可达 |
| **已回应** | 能看出它记下了（不是「发送成功」四个字） |
| **没回应** | **安静地留着，不催、不惩罚、不显示任何指标** |

### 两个合格的例子（直接当测试用例）

**例 1（好奇 / 看物 / 直给，无字数约束）：**
> 想请你帮个忙。下次看到别人家阳台晾着被子，拍一张给我。我最近老路过那些楼，看不出住的是谁，被子大概能看出来。不方便就算了。

- 61 字（含标点）—— 这只狗没有话痨/寡言标签，**不受区间约束**，长一点没关系 ✅
- 具体动作：拍一张晾着的被子 ✅
- 理由：接它自己的好奇（想知道住的是谁）✅
- 余地：「不方便就算了」✅
- 直给：第一句「想请你帮个忙」就是结论 ✅

**例 2 不合格的（寡言 / 慢热 / 看人）：**
> 看到楼下修鞋的师傅了吗。我想知道他一天坐多久。

- 23 字，**寡言区间是 8–15，超了 8 字** —— 这是故意写给你看的不合格例子
- 还有一处错：末句是提问，慢热标签要求「只陈述，不提问」

**例 2 改好的：**
> 楼下修鞋的师傅。他一天坐多久？

- 15 字 ✅ 落在寡言区间内
- 但严格说这个问句仍违反「慢热只陈述」—— 真正合规的写法是：
> 楼下修鞋的师傅。坐了一整天。

- 14 字 ✅，纯陈述，不提问 ✅

**这三条既是写法示例，也是 b2 的验收用例的起点。注意我故意留了不合格的那个 —— 它比合格的有用，因为它能当场判死。**

## 四、三条已经拍好的口径（免得你自己猜）

| 口径 | 裁定 | 对你的影响 |
| --- | --- | --- |
| **邀请永不过期** | 未回应就一直留着，界面**绝不出现「已过期」**。同时待回应最多 3 条：第 4 条不再生成邀请，改成「它自己去了」；更早的那些不删，移进手账「它问过的事」 | 你不用写过期逻辑。要写的是「最多 3 条」的判断，和手账的那个入口 |
| **回应是唯一实现，d 会来调你** | 回应邀请、回应朋友送来的东西 —— 两个入口，同一个提交能力，你做一次 | 你的接口要能吃 `exchange_id` 和 `invitation_id` 两种来源 |
| **屏蔽优先于心愿** | 只要主人屏蔽了某个主题，它不再出现在任何地方 | 你写的 `blocked_topics` 是全局最高优先级过滤器，比心愿高 |

### 主人参与的边界（2.4）

**回应支持两种：文字、照片。** 不做语音、不做表情包、不做快捷短语。

- 照片：限制体积（建议 ≤5MB）、限制格式（jpg/png/webp），失败要能重试且**不丢已输入的文字**。
- 文字：上限 200 字。
- **不回应也能继续** —— 下次出门照常，不许出现「它有点失落」这种文案（那就是惩罚）。

### 日常交流（2.1）的唯一硬约束

**每一句闲聊不落成长期任务。** 说完就说完，不能变成「你要每天跟它说话」、不能生成提醒、不能进任何统计。

## 五、回应验收用例（b2 的 10 条，按这个写）

**5 条正常：**

1. 文字回应，正常提交 → 成功，狗那边能看出「记下了」
2. 照片回应 → 成功，照片能回看
3. 文字 + 照片同时 → 成功
4. 回应后撤回 → 撤回成功，**不报错、不出现「已过期」**
5. 隔了一周才回应 → 成功，邀请还在

**5 条异常：**

6. 只写了一半就关闭页面 → 重开后输入还在（或明确说没保存）
7. 图片太大 → 就地提示体积上限，**已输入的文字不丢**
8. 重复点击提交 → 只产生一条回应（幂等）
9. 完全不回应，继续出行 → 一切正常，**界面上没有任何变化**
10. 回应一条已撤回的邀请 → 友好提示，不崩

**每一条都要可复现，这是 11-28 回归的底本。**

## 六、我唯一会拦你的两件事

①出现禁词表里的任何一个词 —— 不变量三，直接打回。
②邀请是「要不要一起玩」这种没有具体动作的话 —— P0 第 6 条落空。

其余第三层的东西（句式怎么变、卡片放第几个、语气轻重）**你自己定，不用问我**。03 里写了：只影响你自己那块的决定，直接做。
