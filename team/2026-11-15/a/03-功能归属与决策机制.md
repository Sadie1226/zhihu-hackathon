## 一、一个决定归谁

**问一句：「我定的这条，别人违反了会怎样？」**

- **别人得返工** → 找 **a**
- **只影响他自己那块** → **他自己定，别去问人**

| 层 | 归谁 | 例子 |
| --- | --- | --- |
| **一、不变量**（违反了就不是这个产品） | **a** | 不回应不惩罚 |
| **二、判断口径**（会牵动别人模块） | **a** | 邀请永不过期；礼物隔一次出行才到；一天出行几次 |
| **三、具体值与实现**（填什么、怎么落地） | **功能负责人** | 邀请说什么话、语气、卡片放哪、存哪张表怎么实现 |

**领域基线**：产品→a、美术→e、架构→c。**基线人只定第二层，不定第三层长什么样。**

e 定卡片结构和视觉语言，负责人选用哪版。c 定技术做法，负责人不能自己新建表。

## 四、怎么发提案

**只影响自己 → 直接做，不用提案。**

**会让别人返工 → 群里发六行，不用写文档：**

```
【提案】一句话说清是什么
影响谁：
为什么是现在：
备选：至少一个，写清代价
我打算怎么做：三步以内
什么时候能看到：具体日期
```

## 五、怎么回应

**24 小时内，三种回应：**

| 回应 | 怎么写 |
| --- | --- |
| **同意** | 一个 👍 |
| **异议** | **必须写「为什么」+「一个替代方案」**。只写「不行」不算异议，视为同意 |
| **idea** | 「另一种思路是……」，记录但不阻断当前提案 |

**24 小时没人异议 → 默认通过，直接开工。** 不要等所有人表态。

## 六、谁能拦

| 谁 | 范围 | 拦了必须给什么 |
| --- | --- | --- |
| **a** | 产品范围、是否偏离中心、优先级 | 替代方案，或明确说砍掉 |
| **c** | 契约、数据表、部署、依赖、密钥 | **替代实现**，不能只说不行 |
| **e** | 视觉一致性、资产锚点规范 | **替代样式** |
| **b / d** | 仅自己功能 | 说清哪一步会坏 |

**只否决不给方案 = 把自己的活推给别人，站会上点名。**

## 七、基线人打架

| 冲突 | 结果 |
| --- | --- |
| 产品 vs 美术 | 产品赢，e 可要求换一种不牺牲可用性的表达 |
| 产品 vs 架构 | 产品赢，c 可要求分两步走 |
| 美术 vs 架构 | c 有一票技术否决，其余听 e |
| 还定不了 | **a 当天给结论**，不许拖到第二天 |

## 八、每个决定记一行

写进仓库 `DECISIONS.md`，只写一行，谁提谁写：

```
2026-11-18 · a · 延后礼物按「隔一次出行」到达 · 理由：一出行一投递，可数可演示
2026-11-18 · b · 邀请句式统一成「下次看到 X，拍一张给我」
```

不写背景，不写讨论过程。

## 九、提 idea

**随时可以提，但必须有人认领才能变成任务。无人认领 24 小时后进 P1 冷宫。**

句式：

> 「有个想法：______。**我可以做** / **我希望谁做**（后者得他自己说愿意）。」

## 十、什么时候不能改

| 阶段 | 能改什么 |
| --- | --- |
| 11-15 → 11-29 | 走提案即可 |
| **11-29 之后** | **只修阻断缺陷** |

**阻断只有五种**：主流程走不完、越权看到别人的数据、重复投递、伪造真实用户内容、泄露密钥。

冻结后要加功能，只有一条路：**a 和 c 同时同意，并写明砍掉哪个已承诺的东西来换。** 有换才有加。

## 速查卡

> 只影响我 → **直接做**
> 会让人返工 → **六行提案，等 24 小时，没人反对就开工**
> 有人反对 → **他要给替代方案**
> 两个基线人打架 → **产品优先，架构有技术否决**
> 还定不了 → **a 当天给结论**
> 11-29 之后 → **除了阻断缺陷，什么都不改**
