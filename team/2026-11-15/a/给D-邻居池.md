## 二、匹配规则（照这个写函数）

输入：`当前狗`。输出：`一只对方狗`。

```
1. 候选 = 全部狗
   排除：自己
   排除：同一 session_id 下的其他狗（一个人养的几只狗不许互相遇）
   排除：已拉黑的关系双方（拉黑同时作用于狗和主人）

2. 优先还没交换过的
   都交换过了，才允许重访（4.3）
   —— 用 exchange 表查「这对 dog 之间有没有过记录」

3. 在候选里筛出「至少有 1 个 personality_tags 相同」的桶
   桶内随机取一只
   桶为空 → 全池随机取一只

4. 一次出行只遇 1 只狗。不许一次遇 3 只。

5. 候选为空 → 落到预置 20 只
```

**第 3 步的「随机」必须真随机（`Math.random` 或 SQLite `RANDOM()`），不许按 id 排序取第一个** —— 否则同一批用户每次遇到的都是同一只，演示时一眼看出来。

### 明确不做的事

| 不做 | 为什么 |
| --- | --- |
| **不做「最相似」排序** | 两只标签完全一样的狗交换起来没意思，而且会让每次遇到的都是同一只 |
| **不做「加好友」** | 狗认识狗是狗自己的事，人不能代操作（不变量一）。结识是自动发生的 |
| **不做在线状态 / 活跃时间 / 回复率** | 种子狗一旦显示「刚刚活跃」，就是伪造真实用户 |
| **不做手动挑「我想认识哪只」** | 同上，第一条不变量 |

## 三、「示例伙伴」怎么标（这部分给 e 用，但你写 fixtures 时就要带对字段）

`is_sample = true` 是数据侧的标记。界面侧由 e 负责，但**你必须保证这 20 只的 `is_sample` 全是 `true`**，否则 e 没法标。

文案四处（e 直接抄，你不用管）：

| 位置 | 文案 |
| --- | --- |
| 来信里，这条记录下方 | 「这位是示例伙伴，由团队预置，不是真人养的」 |
| 交换记录里，狗名字后面 | 浅色小标签「示例」 |
| 朋友圈里，这条动态的作者 | 同上，浅色小标签「示例」 |
| 手账里回看这段关系 | 同上 |

**一旦用户给示例伙伴捎了话，界面要当场说清「这是一位示例伙伴，可能不会回话」。绝不能伪造回复 —— 踩了就是阻断缺陷。**

## 四、20 只种子狗的分布要求（我照这个数着验收）

这些是**可数**的，交上来我直接数。不够就是没做完，不是「大概齐」。

| 要求 | 数字 | 为什么 |
| --- | --- | --- |
| 12 个性格标签，**每个至少被 1 只覆盖** | 12/12 | 否则新用户抽到某个标签就永远配不到相近的狗 |
| 6 个维度，**两极都有人** | 6 个维度 × 2 = 12 只打底 | 不能 20 只全是好奇，一只恋家都没有 |
| 6 个关注类目，**每类至少 3 只** | ≥18 只 | 保证每类心愿都有对应性格的狗 |
| 名字两两不重复 | 20 个 | |
| 装配单**肉眼两两可区分** | 20 个 | 不是换了个颜色就算，是换部件 |
| `is_sample = true` | 20/20 | |

### 每只的交给你填的字段

```json
{
  "id": "dog_seed_01",
  "name": "石头",
  "session_id": "seed",
  "personality_tags": ["好奇", "看物", "当下"],
  "interest_categories": ["自然风景", "冷知识"],
  "assembly": { "cloth": "jacket", "hat": null, "glasses": null, "face": "hopeful" },
  "is_sample": true
}
```

`personality_tags` **必须来自 3 个不同维度**，且不能是互斥对的两极同时出现。互斥对在 `contracts/types.ts` 的 `EXCLUSIVE_PAIRS` 里。

### 名字从哪来（不重复是硬要求，我给你 20 个打底）

`石头` `豆子` `慢慢` `叮当` `老周` `三毛` `吵吵` `阿盐` `铁蛋` `小满`
`秋秋` `年糕` `灰灰` `大福` `冒冒` `晃晃` `麦子` `卷卷` `团子` `青椒`

**这 20 个可以直接用。** 但每只狗的三个标签由你按第四节的要求分配，别 20 只都写成「好奇/看物/当下」。

## 五、装配单怎么排（这部分你只需要填，不需要画）

> **11-16 改（a 裁定，DECISIONS 同日）：装配单从六键改为四键。**
> 删掉 `base`（体型）与 `skin`（配色 × 花纹）——刘看山 IP 只有一种体型与一套配色，那是边界不是工期。
> 写回这两个键会被数据库直接拦（`必须恰好四个键`）。下面这张表已按四键更新。

| 层 | 键 | 你的选择范围（等 e2b 定数量） |
| --- | --- | --- |
| 2 服装 | `cloth` | 6 件 |
| 3 配饰 | `hat` / `glasses` | 各 4 件，**含「不戴」；可以是 `null`** |
| 4 脸 | `face` | `happy` / `tired` / `hopeful` / `waiting`，**领养时定下就不变** |

组合 6 × 4 × 4 × 4 = **384 种**，20 只绰绰有余。

**「两两肉眼可区分」怎么做**（原要求不变，但体型和颜色没了，难度上来了）：
小头像尺寸下衣服细节会糊，能认的只剩「帽子轮廓 + 墨镜 + 脸」。所以——
**同款衣服不超过 4 只，帽子尽量不重复。** 别 20 只都戴 beanie。
