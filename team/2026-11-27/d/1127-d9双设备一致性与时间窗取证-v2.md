## 三、三边读数（正题，结论不变）

同一条 exchange，三个视角各读一次：甲的发件箱（dev1）、甲的第二台设备（dev1b）、乙的收件箱（dev2）。

| 字段 | 三边是否相等 | 值 |
| --- | --- | --- |
| `id` | 一致 | `ex_…` |
| `kind` | 一致 | `co_owner_message` |
| `payload` | 一致 | 原话 + `fromOwnerOf` 整块相等 |
| `createdAt` | 一致 | 同串 |
| `deliveredAt` | 一致 | = 乙狗 `startedAt` |
| `repliedAt` | 一致 | 同串 |

**范围限定**：只逐值比较了上面这六个字段，**没有扩大到「其它字段的值也都相等」**。另有一条独立断言 `三边字段集合完全相同（不对称字段数 = 0）` —— 这是我本轮新加的，v1 里 `asymmetricFields` 只记录、不参与判定；现在字段集合一旦出现差异会直接判红。

- 第三方 owner 的收件箱里没有这条；第三方读甲的发件箱 → 404

## 四、时间窗反例：读 body 期间撤销

你 `cdb9eb5` 修的是 D6 留下的 TOCTOU。我 d7 那三条反例全是横向越权，没有一条带时间窗。

取证坑：未登录抛 `SendError('NOT_FOUND', '这条记录不在这里')`，复验失败抛**同一句**。状态码、detail 完全一样，光看响应分不出两者。

做法（如实描述，不夸大）：

1. body 分两截发，第一截出去后等 500ms
2. 此刻用**同一个会话**再打一条完整写入 → 200，说明**撤销时点会话有效**
3. 撤销该 owner 全部活会话
4. 放行后半截 → 404

**这条推断的力度**：它排除的是「撤销发生在请求还没被受理之前」这种平凡解释。挂起请求是否精确命中 `await request.json()` 窗口，HTTP 层不能严格保证，所以本项标 `supporting`；确定性保证引用已合 main 的进程内回归。对照组（同样的分块发法、不撤销 → 200）留着。
