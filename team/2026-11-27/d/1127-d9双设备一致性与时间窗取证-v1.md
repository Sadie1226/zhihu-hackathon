## 二、三个设备身份

| 身份 | owner | 怎么来的 | 模拟 |
| --- | --- | --- | --- |
| `dev1` | 甲 | `POST /api/auth/development`（真 HTTP） | 否 |
| `dev2` | 乙 | 同上（真 HTTP，另一个 owner） | 否 |
| `dev1b` | 甲 | `issueOwnerSession()` 给同一 `provider_subject` 签第二个会话 | **是** |

**为什么 dev1b 要绕一层**：`startDevelopmentSession()` 在没带 cookie 时会 `issueOwnerSession({subject: randomUUID()})` —— 每次登录都新建 owner，HTTP 层拿不到「同一个人的第二台设备」。所以只能直接调服务端同一个签发函数、用同一个 subject。证据里 `dev1b.simulated = true`，不当真机。

验到的东西：dev1b 的 `/api/session` 返回的 `dog.id` 与 dev1 相同（同一只狗），两套 cookie 不同（真是两个会话）。

## 三、三边读数（正题）

同一条 exchange，三个视角各读一次：甲的发件箱（dev1）、甲的第二台设备（dev1b）、乙的收件箱（dev2）。

| 字段 | 三边是否相等 | 值 |
| --- | --- | --- |
| `id` | 一致 | `ex_9e4fa487c25d2c9f77057ae4…` |
| `kind` | 一致 | `co_owner_message` |
| `payload` | 一致 | 原话 + `fromOwnerOf` 整块相等 |
| `createdAt` | 一致 | `2026-11-27T09:43:19Z` |
| `deliveredAt` | 一致 | `2026-11-27T09:43:23.588Z`（= 乙狗 `startedAt`） |
| `repliedAt` | 一致 | `2026-11-27T09:43:26.972Z` |

另外 `asymmetricFields: []` —— **三个视角返回的字段集合完全相同**，没有「发件箱有、收件箱没有」的字段缺口。这条是顺带查出来的，不在预期内。

还有三条配套断言：

- 乙点开两次，`readAt` 第二次与第一次**完全相等**（重复点开不改历史）
- 库内该 exchange **1 行**、reply **1 行**（不是每台设备一份；快照里也核了「寄件狗寄出的条数 = 1」）
- 第三方 owner 的收件箱里没有这条；第三方去读甲的发件箱 → 404

## 四、时间窗反例：读 body 期间撤销

你 11/26 补的 `cdb9eb5`（事务内复验 live session）修的是 D6 留下的 TOCTOU。我 d7 那三条反例（重放 / 未送达 / 替别人回）**全是横向越权，没有一条带时间窗**，所以挡不住这个。

**取证上有个坑**：未登录时抛的是 `SendError('NOT_FOUND', '这条记录不在这里')`，复验失败抛的**也是同一句**。状态码、detail 完全一样 —— 光看响应，分不出「撤销太早，请求根本没通过首验」和「首验过了，是复验拦的」。

所以做法是让它自证：

1. body 分两截发，第一截出去后服务端卡在 `await request.json()`
2. 此刻用**同一个会话**再打一条完整的写入 → **200**（证明会话此刻有效，那个挂着的请求首验必然已过）
3. 撤销该 owner 的全部活会话
4. 放行后半截 → **404**

**负验证**（证明这条反例真的在测修复，不是走过场）：把 `cdb9eb5` 的复验临时注释掉、同一脚本重跑 ——

| | 有复验（`470da99`） | 去掉复验（临时） |
| --- | --- | --- |
| 挂起期间同一会话写入 | 200 | 200 |
| 撤销后放行后半截 | **404** | **200** |
| 库里残行 | 0 | **1**（脏数据写进去了） |

去掉复验后 `读 body 之前撤销 → 写被拒` 与 `被拒的那条没留在库里` 两条断言同时变红（23/25）。产品代码验证完已用备份还原，`git diff` 为空。

对照组也留着：同样的分块发法、不撤销 → 200，证明失败不是流式 body 本身造成的。

## 五、边界（比结论重要）

## 六、两处实测发现（顺手记下，省别人一次踩）

1. **会话接口是 `/api/session`，不是 `/api/auth/session`**。后者返回 404 HTML，`JSON.parse` 直接炸在 `<` 上。
2. **`issueOwnerSession()` 判命名空间读的是 `process.env`，不是库里的值**。脚本进程没有 `NODE_ENV` / `APP_IDENTITY_PROVIDER` / `DATABASE_PATH`，直接调会抛 `Identity namespace unavailable` —— 这不是权限问题，是环境没对齐。补上临时环境变量即可（用完还原）。
