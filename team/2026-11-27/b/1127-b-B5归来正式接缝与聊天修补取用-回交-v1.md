## 事务边界与自动 ID

- `generate` 在 C 的写事务外运行；输入形状严格为 `{ scope, finds }`，多一个字段或跨 trip 的 Find 一律拒绝。Find 的内容哈希与 `trip_discovery_receipt` 成员、当前 blocked topics 均再次比对；生成正文也按当前屏蔽复核。
- `writeMessageInTransaction` 先断言 `db.isTransaction === true`，全程没有 `BEGIN`/`COMMIT`/`ROLLBACK`，只有一次普通 `INSERT`。失败抛错交给 C 回滚；成功返回 `undefined`。
- writer 只接受 C 指定的 `msg_auto_return_v1_<64位小写 sha256>`，不再生成随机 ID，也不接受覆盖已有行。按精确 ID 执行一条 `SELECT` 回读，不参与“最新一条”投影。
- 自动主键命名空间与 C `lib/trips/return.ts` 已发布格式一致：`msg_auto_return_v1_` 加 SHA-256，摘要绑定 owner/seed、owner ID、dogId、tripId 与发现 intent。B 不另占迁移号，不加全局 `message.trip_id` 唯一约束。
- 普通 Message 仍为 `msg_<UUID>`；`createMessageStore().write` 继续每趟可写多条，`get` 继续按 `julianday(created_at) DESC, id DESC` 取最新。本次没有 UPDATE/DELETE 历史消息的代码路径。

## 主人与种子边界

- owner：generator 要求 trip 对应狗 `is_sample = 0` 且 `owner_id` 非空；授权仍由 C 的 `Request`/会话在写事务内复核。
- seed：generator 要求 `is_sample = 1` 且 `owner_id` 为空；没有 `Request`、`sessionId`、邀请或回应的入参，不能借种子路径伪造主人会话。`createTripReturn(...).seed` 的 intent→Trip 确定校验仍由 C 执行。
- draft 只接受 `{ text, mentionsFindId }` 两键；额外带 `ownerId`、invitation 或 reply 字段会被拒绝。种子路径专项验证 `invitation` 与 `reply` 表均为 0 行。
