## 一、三句话

1. **`asset_refs` 30 条保持 `{}`，这次不填。** E2c 交的是背景图，不是事件配图；而「哪个地点用哪张图」E 已经给过一份映射（`scene-map.json` 的 `place → file`），在每条事件上再写一遍就是第二份事实。
2. **真正挡路的不是 `asset_refs`，是换算。** `place_tags` 是四个抽象值，e2c 给的是 12 个具体地名；a 算 `availablePlaces` 时若拿「南头古城」去和 `street` 求交集，**交集恒为空**——最后只剩 4 条不限地点的事件会出，而且不会报错，只会「怎么老是这几条」。
3. **换算表已交，结论不太好看**：`bookstore` 零覆盖 → 3 条事件在现有 12 张素材下永远出不来；3 张图（鸣沙山、白桦林、酒馆内景）名义上只承载那 4 条不限地点的事件，而那 4 条里 2 条文本写着「墙根」「整条街」，**真能读通的只有 2 条**；平均每张图 11.4 条。

## 二、为什么 `asset_refs` 不填（而不是「还没填完」）

三条理由，按强度排：

**① 没有可引用的东西。** E2c 的交付清单里只有 12 张 750×640 背景、衣柜部件、以及 Gift 64×64 / Moment 1200×1200 两个夹具。E11 的三类生图提示词是 **Gift / Moment / Scene**——没有 Event。事件级配图这件事，素材侧还没立项。填什么都是编。

**② 填场景路径会造一个假事实。** 一条 `street` 事件（比如「电线杆上贴着寻狗启事」）能落在南头古城、深夜街角、北京路、社区公园**四个**场景里。`asset_refs` 只有一个格子，写死其中一个，等于宣布另外三个场景不能出这条——而这条限制没有任何产品理由，纯粹是表格形状造成的。

**③ 同一份事实写两遍，迟早不一致。** `place → file` 的映射 E 已经在 `scene-map.json` 里给了（含脚底点，那边才是渲染要用的）。事件表里再存一份，改图时就得改两处。这个坑本周已经踩过一次：我照着工作区旧 `seed_20.sql` 把青椒写成「恋家」，仓库里早就是「看人/婉转/当下」了——是 `JOIN dog` 比对才抓出来的。

契约本来就是这么写的，不是我在解释：

- `contracts/schema.sql:523`：`asset_refs 等 E2c 提供可用引用前保持 {}，不能用清空 place_tags 代替。`
- `contracts/api.md:702`：`JSON 对象，默认 {}；E2c 交可用引用前保留 {}。`
- `contracts/api.md:709`：`asset_refs 的对象内部结构待 E2c 的素材引用对齐。`

**什么时候才填**：E 真的交了「事件配图」（一张图对应一条事件，而不是背景）之后。届时形状建议 `{"illustration": "events/<code>.png"}`——**键名由 c 定**，我不先写死；我只会坚持一条：里面不能出现场景文件路径。

## 三、两层关系：四个抽象值 vs 十二个具体地点

`PlaceTag` 只有四个值（`contracts/types.ts:81`）。加上判据之后，每个具体地点该给哪些值就不是口味问题了：

| 标签 | 判据（事件文本在这个画面里成不成立） |
| --- | --- |
| `street` | 有可走的室外路面（街、巷、步道），且街面上会有人/车/门面可看 |
| `stall` | 有正在营业的摊、铺或门面，能发生买卖、递东西、讨价还价 |
| `riverside` | 有水岸或水面，能看水、沿水走、听水声 |
| `bookstore` | 有书架、书报、能翻的东西 |

按这个判据过一遍 e2c 的 12 张（依据逐张写在 JSON 的 `why` 里，没写依据的会被脚本拦住）：

| 场景 | 文件 | 标签 | 依据（看图） |
| --- | --- | --- | --- |
| 长白山天池 | `scenes/changbai.png` | riverside | 火山口湖面 + 岸线卵石坡 |
| 阿勒泰·喀纳斯 | `scenes/kanas.png` | riverside | 湖岸草甸与水边空地 |
| 三亚海滩 | `scenes/sanya.png` | riverside | 海岸线、沙滩、遮阳伞 |
| 深圳南头古城 | `scenes/nantou.png` | street + stall | 石板街巷 + 沿街门面与灯笼 |
| 深夜街角 | `scenes/late-night-corner.png` | street + stall | 斑马线与路面 + 便利店门面 |
| 敦煌鸣沙山 | `scenes/dunhuang-mingsha.png` | **（无）** | 纯沙丘，无街、无摊、无水、无书 |
| 大兴安岭白桦林 | `scenes/greater-khingan-birch.png` | **（无）** | 林间小径，无街面（贴启事、屋檐躲雨都不成立） |
| 盘锦红海滩 | `scenes/panjin-red-beach.png` | riverside | 湿地水道与滩涂 |
| 桂林漓江 | `scenes/guilin-li-river.png` | riverside | 江岸卵石与水面 |
| 广州北京路 | `scenes/beijing-road.png` | street + stall | 步行街 + 沿街商户 |
| 城市社区公园 | `scenes/city-community-park.png` | street | 园路、长椅、有人 |
| 街角小酒馆内景 | `scenes/corner-tavern-interior.png` | **（无）** | 室内吧台与桌凳；四值里没有「室内」 |

**多对多，不是一对一。** 一张图可以同时是 `street` 和 `stall`（南头古城就是）；同一个 `riverside` 也有 5 张图。谁想给它排一张「一对一映射表」，一定会排出「鸣沙山算 riverside」这种谎言。

**标签是必要条件，不是充分条件。** 四值只保证「这个场景装得下这一类事」；某条具体事件读着自不自然，由那 40 个字自己撑，不靠标签。所以我不给白桦林 `street`——林子里的「电线杆上贴着寻狗启事」是假的，而那正是 `street` 会放进来的东西。

## 四、算账（脚本输出，可复跑）

```
node scripts/d2c-scene-coverage.mjs
```

| 场景 | 标签 | 可出事件 |
| --- | --- | --- |
| 长白山天池 / 喀纳斯 / 三亚 / 盘锦 / 漓江 | riverside | 各 8 条 |
| 南头古城 / 深夜街角 / 北京路 | street + stall | 各 23 条 |
| 城市社区公园 | street | 16 条 |
| 鸣沙山 / 白桦林 / 酒馆内景 | （无） | 各 4 条 |

| 标签 | 能承载的场景数 |
| --- | --- |
| riverside | 5 |
| street | 4 |
| stall | 3 |
| **bookstore** | **0** |

三个发现：

**① `bookstore` 零覆盖 → 3 条事件永远出不来。** 不是「少」，是「永远」：

- `summer_bookstore_ac` 书店的冷气从门口漏出来，站一会儿就凉了。
- `autumn_book_box` 书店门口摆了个纸箱，写着「随便拿，看完放回来」。
- `winter_bookstore_chair` 书店最里面的角落有张椅子，椅背上搭着一件外套。

第 4 条带 `bookstore` 的 `any_shop_cat`（店门口的猫认得每个进门的人，只对熟的抬头）因为还有 `stall`，在南头古城这几张里出得来——标签写两个不是冗余，是**这条事件有两条活路**。

**② 3 张图空转，而且比看上去更空。** 鸣沙山、白桦林、酒馆内景能给的事件只有那 4 条 `place_tags=[]` 的。但这 4 条里也有两条**自己写着场景**：

| `place_tags=[]` 的 4 条 | 文本里的隐形条件 |
| --- | --- |
| `spring_first_green` | 墙根的草冒了一点绿，昨天还没有。——**要有墙** |
| `summer_cicada` | 树上的蝉叫得整条街都听见，忽然一起停了。——**要有街** |
| `autumn_birds` | 天上有一队鸟往南飞，队形一直没散。——真的不限 |
| `any_moon_ring` | 月亮边上有圈淡淡的光，据说第二天要起风。——真的不限 |

所以跑到沙丘、白桦林、酒馆里，真能读得通的只有 **2 条**（`autumn_birds` / `any_moon_ring`）。「不限地点」被当成了万能兜底，但文本里写着墙根和整条街——这不是 `place_tags` 填错，是**四值这个粗筛表达不了这个粒度**，加第五个值也表达不了。修法在素材和文本侧（见第五节），不在标签侧。

**③ 平均每张 11.4 条。** 30 条事件、12 张场景，`(8×5 + 23×3 + 16 + 4×3) / 12 = 137 / 12`。这个数会随冷却和权重再降——所以「每张图能出十几条」是上限，不是体感。

**明确不做的事：为了配图去改 `place_tags`。** 契约原话是「不得为凑素材清空 place_tags」（`api.md:709`）；反过来为了凑图去**加**标签同样不行——那是把「这条事件需要什么条件」改成了「我们有什么图」。

## 六、顺带回 E 的一条（11/23 群消息）：贝壳 Gift 当视觉夹具没问题，但别写进 `imagePath`

E12 的 `gift-shell.png` 我核了：64×64，colorType=6（RGBA）。d 侧的 `gift` 业务只要求 `imagePath` 这个**键在**、值可为 `null`（`lib/social/gift.ts:168`），不校验尺寸、不校验格式——所以换个夹具不牵动任何代码。

但 `imagePath` 的语义是「**这次**礼物的生成图路径」，不是「礼物图统一放哪」。把那个固定夹具的路径写进 `imagePath`，等于让每一份礼物都声称自己有专属生成图——和契约里那条「不因有图片或 URL 就把档位改成 live」是同一个形状的假话。夹具要出现在页面上，走前端静态资源，不进 `imagePath`。
