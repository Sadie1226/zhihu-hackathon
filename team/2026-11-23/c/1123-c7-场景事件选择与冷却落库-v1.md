## 服务接口与事务

`lib/events/select.ts` 提供同步内部入口 `createTripEventSelector(db, { now?, random? })(input)`。调用方必须在服务端完成身份解析，传入 C4 的归属键。v5 已绑定狗的该兼容键是已验证 owner ID。可信执行器后续可按下列形状接入。

```ts
const pickEvent = createTripEventSelector(db)
const occurrence = pickEvent({
  tripId: runningTrip.id,
  dogId: runningTrip.dogId,
  sessionId: auth.ownerId,
  conditions: verifiedTravelConditions,
})
```

`verifiedTravelConditions` 为 `{ sceneFile, season, weather, timeOfDay }`。缺少可信条件时传 `null`。返回值为 `{ tripId, eventId, dogId, happenedAt }` 或 `null`。数据库和受控时钟由服务端注入。具体 Trip 必须已由 C4 启动。

- 在同一 `BEGIN IMMEDIATE` 内复查 C4 归属、狗和 running 状态，再检查已写事实或过滤当前启用候选。按时间和天气、粗标签、场景语义、兴趣和屏蔽主题、同狗冷却筛选后，按事件 code 稳定遍历并做加权随机。空 `match_tags` 或 SQL NULL 兴趣不限制匹配，原值保留。
- 冷却按同一狗其他 Trip 中对应事件的最新 `happened_at` 计算。满 `cooldown_days × 24h` 才恢复候选。写入时间为服务端 UTC 时间，且不早于 Trip 开始时间。
- 仍在 running 的同一 Trip 已有一条一致记录时，直接返回原四字段，跳过抽签和取时。冲突的历史事实显式报错并回滚。无可用事件返回 `null`，也可以在可靠条件补齐后重试。跨狗与越权按 C4 的 `NOT_FOUND` 处理，未开始或已结束按 `CONFLICT` 处理。数据库异常原样抛给可信调用方。
- 写入只使用既有 `trip_event`。同趟一条由 C7 写事务保证，现有主键仍为 `(trip_id,event_id)`。复用 C4 查询和 C6 屏蔽匹配，事务内全程同步。接口契约见 `contracts/api.md` 第七节。
