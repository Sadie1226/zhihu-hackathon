## 执行器接口

`createTripDiscoverySearch(db)(tripId, sessionId)` 复用 C6 Phase 2 从 Trip 读取心愿或兴趣、处理屏蔽并调用 C5 的路径。成功返回该次查询的进程内 `proofs`，既有单条入口仍使用第一条。执行器先完成异步搜索，随后同步调用 `createTripDiscoveryComposer(db)(tripId, sessionId, { searchProofs, observations })`。身份参数取可信服务端归属键。搜索失败维持 C5 的内部错误，执行器可单独提交已经验证的本趟场景和片段。

`observations` 仅供可信服务端传入已核实的观察事实，包括稳定来源 ID、Trip ID、狗 ID、发生时间、类型、标题、摘要及可选资源引用、主题。调用方负责验证观察事实的实际来源。拼装器核对归属、类型和发生窗口。E2c 交付的图片和地点映射是素材清单，尚无 Trip 发生事实，调用方需要另有匹配本趟的观察依据。独立 Moment 和 Scene 走观察接口，TripEvent 由拼装器直接查本趟记录。

事件池只读。事务内连接 `trip_event` 与 `event`，筛选当前 Trip、当前狗及真实出发至提交时点之间的记录。事件池中的候选以及其他趟次的已发生事件不会进入本趟。Scene 和 Moment 的 `sourceMode` 为 `null`，无原文 URL。知乎沿用 C5 证明携带的原文路径，已存的 `live/cache/fixture` 原样返回。[D 事件池 SQL](../../2026-11-18/d/1118-d2c-事件池三十条-v1.sql) · [E2c 场景交付](../../2026-11-22/e/e2c/E2c-scene-map.md)

## 事务、结果与重试

- 复用 `createFindStore` 的规范化、确定性 ID 和插入逻辑。整批使用一个 `BEGIN IMMEDIATE`，在锁内重新核对 Trip 归属、running、开始时间、当前 `blocked_topics` 及来源证明。写入任一条失败，整批回滚。C5 搜索期间不持有 SQLite 写锁。
- 按知乎原文规范化 URL 或 Scene/Moment 的稳定来源键去重。同一来源的重试保留首条入库的内容、来源标签和时间。选入优先考虑已有真实来源的知乎记录，再按权威性、点赞数及稳定键排序。一次拼装最多返回 5 条。
- `complete` 要求至少一条原文链接有效、标记为 `live` 或 `cache` 的知乎 Find，且至少 3 条非夹具事实。候选不足返回 `partial` 及 `NO_REAL_ZHIHU`、`INSUFFICIENT_FACTS` 中适用的原因。暂缺真实知乎时最多入库 4 条，为同一 running Trip 后续核验到的知乎来源保留一席。既有记录完整保留。
- 已存标题和摘要仍参与本轮屏蔽过滤。TripEvent 与本次提供的观察事实可继续用其主题过滤。历史表未增主题或来源快照字段，未重新提交的独立观察只可按已存标题和摘要过滤。历史 GET 继续按公共契约读取已保存记录。
