## 一、修补 1：代码身份不再「你说我记」

**原来的问题**：`--code-sha` 只是把参数原样抄进证据。传什么就记什么，于是「这份证据跑在 X 上」这件事**从来没有被验证过**。

**现在**：

| 项 | 做法 |
| --- | --- |
| 实际 HEAD | `git rev-parse HEAD` 现场取 |
| tracked dirty | `git status --porcelain` 现场取，只算 tracked；untracked 不算（本次产物本就是新文件） |
| 本次产物 | 库、`-wal`/`-shm`、`.evidence.sqlite`、证据 JSON **显式从 dirty 清单剔除**，不自己给自己制造脏 |
| 期望 SHA | `--code-sha` 改名 `--expected-sha`，**严格相等比较**，不等即拒绝出证据、退出 1 |
| 源码脏 | 默认拒绝出证据；`--allow-dirty` 可放行，但证据标 `formal: false`，不能当正式通过证据 |
| 找不到 git | 先试 `GIT_EXE`（队里既有兜底），再试 PATH，都没有就明确报错 —— 不静默记 `unknown` |

证据里新增 `code` 段：`head / expected / matchesExpected / dirty / dirtyFiles / formal / server / login / replyTransport / node / command / repoRoot / capturedAt`。

## 二、修补 2：快照要自己过一遍，不拿源库的检查结果盖章

**原来的问题**：`VACUUM INTO` 之后，`integrity_check` 跑在**源连接**上，然后直接给生成的快照文件算哈希。核的是源库 —— 快照漏拷、截断，一样「通过」。

**现在**：关掉源连接 → **`readOnly` 打开快照本体** → 核这几样 → 全对上才允许算哈希：

1. `PRAGMA integrity_check`
2. `PRAGMA foreign_key_check`
3. 本批核心行与源库已记录事实逐项比对：
   - `exchange` 行（id / from / to / kind / payload / seq / created / delivered / replied / read）
   - `reply` 行 与 `reply` 条数
   - `trip` 行（收件狗全部行程，按 seq）
   - 未送达那条的 `reply` 数必须仍是 0

任何一项不过 → `evidence.verdict` 置为失败、退出非零、不出 pass。证据里写 `db.checkedOn = "snapshot（不是源库）"`、`db.openedReadOnly = true`。

**为什么非核核心行不可（负例实测）**：我把本次快照拷一份、删掉 `reply` 全部行，再按同样方式只读核：

```
integrity_check : ok          ← 删一行不破坏结构，照旧 ok
foreign_key     : 0 条        ← 也不违反外键
reply 行数      : 0（应为 1）  ← 只有核心行核对抓得住
```

**结论：只核 integrity + fk 是拦不住坏快照的。** 这正好是 A 要求补「该批核心 exchange/reply/Trip 事实」的原因。

> 注：这个负例是**外部拷一份**做的，不碰 `_d7-run3` 的正式快照，也不碰 c01。正式快照 `98ad5c43…` 的自核结果是 `problems: []`。
