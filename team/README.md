# team/ · 当日交付存放区

> 一句话：**交付走你的分支。文件放 `team/日期/你的字母/`，放完不要再改。**
>
> ⚠️ **目录位置是推荐的写法，不是验收门槛。** 验收看的是「东西有没有、名字认不认得、在不在你的分支上」，不看它落在哪个文件夹。
> 详见下面第三节「五条硬规矩」第〇条。
> 索引看 [`STATUS.md`](STATUS.md)，那个只有 a 改。开工前读 [`指南-交付与取用.md`](指南-交付与取用.md) 里你自己那一页。

---

## 一、目录长什么样

```
team/
  2026-11-15/
    a/    ← a 当天交的东西
    b/
  2026-11-16/
    a/  b/  c/  d/  e/    ← 空着的是还没到那天
  ...
  2026-12-05/
  STATUS.md             ← 索引，只有 a 改
  指南-交付与取用.md     ← 五页分人，一人一节
```

全部 21 个日期文件夹（11-15 → 12-05）已经建好。空文件夹里有 `.gitkeep`，**是为了让空目录能被 git 收进来**，不是垃圾文件，别删。

## 二、文件名规则

```
日期-任务号-内容-版本.后缀
```

| 段 | 怎么写 | 例子 |
| --- | --- | --- |
| 日期 | 交的那天，不用横杠 | `1116` |
| 任务号 | 任务表里的编号 | `c3` `e2b` `d7` `b1` |
| 内容 | 两到六个字说清是什么 | `契约五文件` `种子狗设定` |
| 版本 | 从 `v1` 开始，改一次加一 | `v1` `v2` |
| 后缀 | `.md` `.png` `.json` `.ts` | `.md` |

**合格：** `1116-c3-契约五文件-v1.md`　`1118-e2b-锚点规范-v2.md`　`1115-b1-邀请十例-v1.md`

**不合格：**

| 名字 | 为什么不行 |
| --- | --- |
| `新建文本文档(2).md` | 不知道是谁的、什么时候的、是什么 |
| `最终版.md` | 一定有下一个最终版 |
| `真的最终版.md` | 同上 |
| `狗.png` | 哪只狗、哪一层、哪个配色 |
| `1116 c3 契约.md` | 带空格，链接会断 |

图片同理：`layer2-cloth-hoodie-red.png` ✅ ｜ `未命名.png` ❌

## 三、五条硬规矩

### 〇、交付单位是分支，不是文件夹

**你交东西 = 把你的分支推上去，然后在群里说一句。** a 拉你的分支、验、合并。

`team/日期/你的字母/` 是**放文件的推荐位置**，让你和别人都好找。它**不是验收条件**。

| 会被接受 | 不会被接受 |
| --- | --- |
| 东西在 `team/` 里，位置不太对 | 东西只在你本地，没推分支 |
| 文件名格式不规范，但能看出是什么 | 文件名是「最终版」「新建文档」，看不出是什么 |
| 放在根目录或别的日期文件夹 | 没在群里说过一句，a 不知道你交了 |

**判断标准一句话：a 能不能根据你的交付说明找到东西、看懂是什么？** 能，就成立。

**为什么这么定：** 五个人都是往自己分支上推，路径合规检查的成本高于收益，而且拦住的是格式而不是内容。**真正会丢东西的是「没推」和「说不出在哪」，不是「放错文件夹」。**

### 一、日期按「交的那天」算

不按任务编号里的截止日算。你今天交的 e2b，就放 `2026-11-18/e/`，不管任务表上它写的是哪一天。

**这条的本意是「不要放回更早的日期」** —— 防止有人把 11-20 交的东西塞进 `2026-11-16/` 假装自己早交了。**它不要求按墙上时钟精确到小时。**

判断标准一句话：**别人会去哪一天找你？** c 在 11-15 深夜交的 c3 放 `2026-11-16/c/`，因为 b/d/e 会按时间线去 11-16 找契约 —— 那就放那里。**文件位置服务于「别人找得到」，不是服务于打卡。**

### 二、放进去就不再改

发现写错了，**再放一个新文件，文件名加 `-v2`**。旧的留着。

两个理由：它是「那天你交了什么」的证据，改了就说不清是谁的问题；它同时是备份，11-29 主干出事时这里还在。

**删文件要 a 同意。**

### 三、这里放什么，不放什么

| 放 | 不放 |
| --- | --- |
| 规则、线框、文案、案例 | **代码**（按 README 目录归属进 `app/` `lib/`） |
| 素材清单、资产规范 | 素材原图（进 `public/assets/`） |
| 要给别人用 / 要给 a 看的东西 | 方案长文、讨论记录 |

**判断标准一句话：它是不是「拿来做什么」，但还没变成代码？** 是就放这里。

### 四、交付物和请求分开

**交付物 = 别人拿到就能直接干活的东西**（规则、规范、清单、线框、示例）。
**请求 = 我发现了问题、我要别人决定或改什么**（问题清单、加表请求、字段核对表）。

**两种都放在 `team/日期/你的字母/`，但请求必须在文件名里带出来，不能混进交付物里。**

| 类型 | 文件名带什么 | 例子 |
| --- | --- | --- |
| 交付物 | 任务号 | `1116-d1-交换规则十例-v1.md` |
| 请求 | 任务号 + **给谁** + 请求什么 | `1116-d0b-给c-契约问题清单-v1.md`｜`1116-d2c-事件池加表请求-v1.md` |

**为什么分开：** 合并的时候 a 要把交付物收进索引、把请求转给对应的人。混在一起，请求会被当成「已经做完的东西」，然后就没人回它了。

**请求不占任务号，也不进 STATUS 的「已交」栏。** 它是过程材料，不是交付。

## 四、交完之后

在群里说一句「我交了，分支 `d1-d3-social`，文件在 `team/2026-11-16/d/`」——**分支名必须说，因为 a 要拉它。** 然后 a 会在 `STATUS.md` 里加一行。

**你自己不要改 `STATUS.md`。** 那个文件的 `✅` 只有一个含义：**a 已经读过了，并且索引里加了路径。** 你自己不能标 ✅。
