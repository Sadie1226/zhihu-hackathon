# team/ · 当日交付存放区

## 一句话规则

**往 `team/日期/你的字母/` 里放东西，放完不要再改。** 索引看 `team/STATUS.md`，那个只有 a 改。

```
team/
  2026-11-15/
    a/    ← a 当天交的东西
  2026-11-16/
    c/    ← c 当天交的东西
    b/
  2026-11-18/
    e/
  STATUS.md  ← a 维护，指向最新可用的那一份
```

## 三条硬规矩

**一、日期按「交的那天」算，不按「任务编号里的日子」算。**
你今天交的 e2b，就放 `2026-11-18/e/`，不管任务表上它写的是哪天的截止。

**二、放进去就不再改。** 发现写错了，**再放一个新文件**，文件名加 `-v2`。旧的留着。
理由有两个：它是「那天你交了什么」的证据；它同时是备份，11-29 主干出事时这里还在。
删文件要 a 同意。

**三、文件名不带空格、不带版本混乱。** 用中文名可以，但要说清是什么：
`给C-契约输入.md` ✅ ｜ `新建文本文档(3).md` ❌ ｜ `未命名.png` ❌
图片同理：`小屋-主画面-v1.png` ✅

## 不是所有人都往这里放

**这里放的是「要给别人用 / 要给 a 看」的东西** —— 规则、线框、文案、素材清单、案例。

**代码不放这里。** 代码按 README 的目录归属直接进 `app/` `lib/` 那些地方。这里只放「拿来做什么」还没变成代码的东西。

## 交完之后

在群里说一句「我交了，在 `team/11-16/d/`」，然后 a 会在 `STATUS.md` 里加一行。

**你自己不要改 `STATUS.md`。** 你改了，a 判断「谁的交期到了」就不准了。
