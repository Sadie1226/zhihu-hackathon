## 数据和迁移

| 对象 | v5 约束和用途 |
| --- | --- |
| `owner` | 内部随机 ID。`namespace, provider, provider_subject` 唯一。provider subject 按原字符串保存，超出 JavaScript 安全整数范围的 UID 可无损保存。 |
| `owner_session` | 每次签发生成 32 字节随机 token，SQLite 仅存 SHA-256 摘要。有效期七天。时间列使用 Unix 毫秒。退出仅撤销当前设备的会话。 |
| `dog.owner_id` | 可空外键。部分唯一索引限制每位 owner 最多一只狗，种子狗不能绑定。历史 `session_id` 值原样保留。 |
| `adoption_receipt` | `owner_id, request_id` 唯一。请求内容哈希和狗在同一写事务落库。组合外键保证收据只能指向同 owner 的狗。 |

只追加 `005-owner-session.ts`，正常启动将 `user_version` 从 4 增至 5。迁移在现有 SQLite 写事务内增加表、列、索引和触发器，失败时 DDL、数据、版本号一起回滚。独立测试覆盖故障注入、重试、再次打开及种子狗和历史 Trip 保留。已有匿名狗条目保持未绑定，旧匿名 Cookie 不会恢复其访问权。开发退出或过期后重新进入会签发新的开发身份。历史测试狗不自动绑定到正式账号。

## HTTP 和业务接入

- `resolveAuthContext(request, db)` 统一处理 Cookie、过期、撤销、owner 存在性及命名空间。`assertOwnedDog` 和 `assertOwnedTrip` 用稳定 owner 校验资源。领养、查狗、改名、C4 出行、C6 发现、Message 和 Wish 撤销已接入。
- 既有 B 薄路由经 `readSessionId` 兼容入口调用同一解析器。v5 新狗的旧归属列保存同一稳定 owner ID，数据库防止未绑定狗占用该归属键。Wish 列表及创建、邀请、回应、照片上传无需改变业务文件。照片链接 GET 沿用现行持链接读取语义。
- `POST /api/auth/logout` 撤销当前有效会话后清除 HttpOnly Cookie。重放旧 Cookie 时私有路由返回 401 或 404。有效的第二设备会话继续可用。`GET /api/session` 返回公开狗信息和现有草稿隔离键，响应不含 owner ID、UID、token 或 token 哈希。
- 开发入口需同时满足非生产、`APP_IDENTITY_PROVIDER=development`、实际连接到独立的 `a5-development*.sqlite`。正式库仅识别 `zhihu` 命名空间。在受信任的服务器适配器完成 UID 验证后调用 `issueOwnerSession(db, { provider: 'zhihu', subject })`。测试使用模拟 UID，真实 OAuth 的凭证、HTTPS 回调、state 校验和提供方验证仍待联调。
- C8 信箱仍在独立分支，未纳入本轮生产构建。C8 合并时可沿用公共解析器和 owner 归属边界。现有兼容入口也只接受 v5 有效会话。

```http
POST /api/auth/logout HTTP/1.1
Host: mailbox.example
Origin: https://mailbox.example
Cookie: __Host-zhihu_session=<当前会话凭据>
Content-Length: 0
```

成功返回 `200 {"ok":true}`，并以 `Max-Age=0` 清除生产 Cookie。当前会话撤销后，用原 Cookie 请求 `GET /api/trips/:id`、`GET /api/trips/:id/finds` 或 `GET /api/trips/:id/message` 均返回 `404 NOT_FOUND`。
