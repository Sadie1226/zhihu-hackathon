## 接口行为

```text
GET /api/trips/:id/message
200 { message: Message | null }
```

成功 Message 保留现有五字段 camelCase：`id`、`tripId`、`text`、`mentionsFindId`、`createdAt`。只有“已存在且归属当前会话的 trip 没有 Message”才返回 200 / null。数据库错误不能当作空值。

- `readSessionId(request)` 取得 cookie 哈希会话，SQL 通过 dog.session_id 验证 trip 归属。没有/非法/重复 cookie、非法/缺失/跨会话 trip、query 覆盖参数返回 404 / NOT_FOUND。
- pending/running/done/failed/timeout 均可读取已经存在的记录；不更改出行状态。failed/timeout 的正常归来/独立历史展示仍由 A 负责。
- 所有 handler 成功和错误响应有 `Cache-Control: no-store` 与 `Vary: Cookie`。
- SQL、数据库连接和不合法已存数据统一脱敏 503 / NETWORK，retriable=true；响应没有 SQL、路径、私有配置，也没有假 `message:null`。
- 路由只导出 GET；Next 对 POST 返回 405。handler 本身拒绝非 GET，不实现写操作。

fixture 响应形状示例（不是 B5 生成结果）：

```json
{
  "message": {
    "id": "msg_001",
    "tripId": "trip_001",
    "text": "巷子里那面墙红透了，只有靠窗那块还是绿的。",
    "mentionsFindId": "find_s1",
    "createdAt": "2026-11-16T01:04:00Z"
  }
}
```

## 一致性和隐私

单条 SELECT 在同一 SQLite 读取快照中完成归属、Message 选择及 Find 引用检查，没有写事务，也不调用 create/start/finish 或生成能力。通过只读 DatabaseSync、全表事实比较、total_changes 与 user_version 不变验证读取无业务写入。复用通用 getDatabase 初始化入口，不另建数据库或迁移机制。

所选 Message 的非空 mentionsFindId 必须真实存在且 `find.trip_id` 等于当前 trip；同主人另一趟也不允许。越界或丢失引用返回 503，不返回该引用 ID 或 Message 内容，不回退旧行，不修改数据。SQL 不读取关联 Find 的标题/摘要/URL。B 需保证写入归属正确。

**暂行最新记录行为，待 B/A 确认**：历史多条 Message 使用 `julianday(created_at) DESC, id DESC LIMIT 1`，实际时间相同以 ID 倒序稳定选择；例如 Z 与 .000Z 相同时不按字符串格式误排序。所有历史行仍保留，不增加“一趟一条”约束，不物理删除旧记录。
