## 3. 服务端接入边界

```ts
import { createTripDiscoverer } from './lib/trips/discover.ts'

// db 是已有 DatabaseSync；sessionId 由现有 readSessionId(request) 验证取得。
// 服务端执行器已通过 C4 create/start，让该 trip 进入 running。
const result = await createTripDiscoverer(db)(tripId, sessionId)
```

不增加公开 POST，不在 GET 中搜索或写入，不改 C4 start/finish 的行为，不自动开始/结束任务，也不替 A 接页面 wiring。后续服务端执行器应在 start 后调用上述函数，再按自身收尾策略调用原 finish。调用方不得把 HTTP body 的 sessionId/provider/query/sourceMode 传入该边界。

- 有归属且 running 才可搜索；无/跨会话是 `NOT_FOUND`，非 running 是 `CONFLICT`。
- wish trip 使用 C4 出发时固定的 `wishId` 和 `readTripWish`；不因新心愿或重试改写历史关联。已出发后撤销不回写历史；未来出行仍由已有有效心愿选择规则控制。
- 无已关联心愿时，从现有兴趣和 `CATEGORY_KEYWORDS` 按既有顺序取首个未屏蔽关键词；NULL 兴趣表示不限制六类，不转换成空数组。不在本次实现朋友牵挂选择或新的自动调度。
- 心愿空白、超过 200 字或含控制字符拒绝。搜索前检查 query 和 category；有已关联但被屏蔽的心愿时返回空集合，不绕过该心愿继续搜索。
- 屏蔽采用 NFKC、大小写归一后的非空主题子串匹配；结果标题/摘要也过滤。不声称完成语义审核或同义词识别。
- C5 请求最多 3 条，本次只保存排序后首条合法且未屏蔽的结果；没有结果返回成功空集合，绝不补造。
- 种子/示例狗不能通过此路径获得 live 来源；普通 fixture 写入路径保持不变。

## 4. verified provenance 和事务

默认 provider 动态调用已有 `lib/zhihu/index.ts` 的 `searchZhihu`，鉴权和响应解析完全复用 C5。新代码不读取 Secret，不重新实现客户端。

只有实际 await 成功、HTTP 2xx、有效 fetchedAt 且所有返回条目 URL/标题/摘要/来源模式/权威等级/赞数通过校验后，才建立 `SearchProof`。URL 复用已有 `canonicalZhihuContentUrl`；不把 URL 形状当真实性证据。

凭据是冻结对象，在模块私有 WeakMap 中绑定 trip、session、固定 query/category 和复制冻结的 Find 输入。序列化、克隆、构造相同键、自报 `sourceMode:live` 都不能成为有效凭据。`writeVerified(proof, sessionId)` 从该凭据取数据，不接受调用方替换元数据。

`provider` / `now` 注入仅是可信服务端测试配置，不能由请求决定；离线测试故意注入合成 C5 响应验证 live 分支，其成功不构成真实联网证据。凭据保护的是请求/客户端输入边界，不是对恶意服务端代码的沙箱。

网络期间没有 SQLite 事务。收到结果后，存储端 `BEGIN IMMEDIATE` 内重新核对 trip 归属、running/startedAt、isSample 和最新 blocked_topics，再校验凭据并插入。期间 C4 finish 或狗归属变化将阻止写入；新屏蔽也阻止提交。失败完整回滚。

继续使用 Phase 1 的 SHA-256 ID（trip + kind + 规范来源）、旧 ID 来源查重及字段一致性检查。相同内容重试返回原记录和首次时间；同来源元数据变化返回 CONFLICT，绝不覆盖。旧 fixture/cache 不会升级成 live。scene/moment 的 NULL mode 规则未改变。

历史 GET 返回原存储来源，不宣称每次历史读取都重新搜索；保持 camelCase、会话归属、no-store、Vary Cookie、纯读取。C4 finish 读取同一 Find，不改 Message=null。
