## 二、逐条对照 c 的 6 条要求

### 1｜`rules.ts` 的正式白名单 + 来源类型校验

`PAYLOAD_KEYS` 里 find / gift 各加 `sourceFindId`、`sourceMode`（**必需键**，无来源写 `null`）。
`PENDING_KEYS` 清空 —— 那个集合的语义是「放行键名、不校验」，留着就等于给来源开后门。

新增 `validateProvenance()`，只验**形状**：

| 情形 | 判定码 |
| --- | --- |
| 两键只给一个 | `MISSING_FIELD` |
| `sourceFindId` 是 `''` | `EMPTY_STRING` |
| `sourceFindId` 带首尾空格 / 不是字符串 | `WRONG_TYPE` |
| `sourceMode` 不在 `live/cache/fixture` | `WRONG_TYPE` |
| `sourceFindId=null` 但 `sourceMode=live` | `PROVENANCE_MISMATCH`（新增码） |

**三处不许做的推断**（都是 K v4 明确否掉的）：

1. 不许由 `sourceUrl` 推断 `sourceMode` —— 原话「sourceUrl 也不是来源证明，不能依据 URL 外形或客户端参数推断 live」。
   **11-19 我在 `validateFind` 的 TODO 注释里猜过「sourceUrl 非 null 时 sourceMode 必须非 null」，那是错的，已连同注释一起删掉。**
2. 不许把缺失的 `sourceMode` 补成 `live`。
3. 不许把 scene/moment 的 NULL 改写成 `live`。

### 2｜`gift.ts` 的次序：先验来源，再完整校验

11-19 的写法是 `validate()` 先跑、来源字段后追加（`INCLUDE_PENDING_KEYS`）。**那等于新增字段绕过了白名单。**
现在 `send()` 的顺序是：

```
入参白名单 → 拉黑检查 → 查库核实来源并派生 mode → 拼进 payload
→ validate(完整 payload) → 幂等键 → 落库
```

`INCLUDE_PENDING_KEYS` 与 `PENDING_FIELDS` **已删除** —— 留一个开关就等于留一个「能不能绕开来源校验」的旋钮。

### 3｜捎话不许带来源

`CoOwnerMessageInput` 删掉两个字段（类型层面就传不进来）；
运行期若有人用 `any` 硬塞，入参白名单会拒，且报错文案点明「来源字段只属于 find / gift」。

### 4｜来源查验与插入在同一个一致性边界

新增 `lib/social/provenance.ts`，`resolveProvenance()` 一份实现，两个写入路径共用：

- `store.getFindSource(findId)`：**逐字用 api.md 给的那句 JOIN**
  ```sql
  SELECT f.id, t.dog_id AS dogId, f.source_mode AS sourceMode
  FROM find f JOIN trip t ON t.id = f.trip_id WHERE f.id = ?
  ```
  `find` 表**没有 dog_id**，归属只能经 trip 反查 —— 所以接口不接受调用方传 dogId。
- 内存实现按同一语义（`finds` 预置表），SQLite 实现是真 JOIN。**两种实现给出同一个答案**，这是 Mock 阶段还能验到归属的原因。

**关键修正（写测试时抓到的）**：一开始把核查放在 `meet()` 的组装层，`recordExchange` 直接调用时**穿过去了** ——
一条「find 带假来源」的用例照样落库。已改成在 `recordExchange` 内部做，它是所有 exchange 写入的唯一出口。
`meet()` 现在只透传 payload。

## 五、留给 C8 接入的三句话

1. **`store.getFindSource()` 是来源的唯一入口。** C8 的 HTTP 层如果自己查一次再传 dogId 进来，归属校验就白做了。
   适配器实现必须照 api.md 那句 JOIN 写。
2. **`transaction` 对 HTTP 是个真问题。** 相遇要写 relation + exchange，HTTP 没有事务。要么 C8 提供原子接口
   （`POST /api/meets`），要么适配器把三个写合并成一次请求。
3. **`sourceMode` 由服务端派生，不接受客户端传值。** 契约原话「客户端/模型不得自行指定」。
   调用方给错了，d 的写入侧会拒（`PROVENANCE_MISMATCH`），不会静默纠正。
