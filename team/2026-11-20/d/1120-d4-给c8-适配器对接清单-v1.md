## 一、11 个方法

| 方法 | 读写 | 必须做到 | 最容易错的地方 |
|---|---|---|---|
| `insertExchange(row)` | 写 | 同 `id` 再来返回 `'duplicate'`，**不覆盖、不报错** | 用 `ON CONFLICT(id) DO NOTHING` 看 `changes`；不要先 SELECT 再 INSERT（并发下会双写） |
| `readExchange(id)` | 读 | 没有则 `null`；**返回库里那份**，不是调用方刚传的 | 重放时把本次 draft 当结果返回 → 界面显示一条不存在的消息（11-19 踩过） |
| `upsertRelation({dogA,dogB,at})` | 写 | 首次 `metCount=1` 且 `firstTime=true`；之后 `metCount+1`、`lastMetAt` 更新、**`firstMetAt` 永不改** | 用 `INSERT … ON CONFLICT(dog_a,dog_b) DO UPDATE` + `RETURNING`；`firstTime` 由「刚插入」判断，不要用「传进来的 count」猜 |
| `readRelation(a,b)` | 读 | **顺序无关**；没有则 `null` | 只按 `(a,b)` 查，传反了就读不到 |
| `isBlocked(a,b)` | 读 | 双向一致 | 只查一个方向 |
| `currentSeq(dogId)` | 读 | 这只狗**当前第几趟**；没出行返 `0` | **不许自增**，也不许把「下次趟次」算在这里 |
| `isSample(dogId)` | 读 | `dog.is_sample = 1` | 这条是红线闸门：「种子狗不伪造主人回话」在写入侧只有这一处能拦 |
| `hasDog(dogId)` | 读 | 不存在返 `false` | 不能一律返回 `true`（Mock 默认放行是 Mock 的事） |
| `getTrip(tripId)` | 读 | 返 `{id, dogId, status, seq}`；没有则 `null`；`status` 原样返回 | 在这里过滤状态 → 业务层拿不到准确错误码（`TRIP_NOT_OPEN` 就废了） |
| `getFindSource(findId)` | 读 | **`JOIN find → trip`** 拿归属，`source_mode` 原样 | 把 `dogId` 当入参 = 让客户端自证归属，K v4 明令禁止 |
| `transaction(fn)` | 事务 | 抛错整体回滚，成功透传返回值；**不暴露 commit/rollback 句柄** | 真库用 `BEGIN IMMEDIATE`（先拿写锁）；不要在回调外 commit |

### `getFindSource` 的 SQL 只有这一句是合法的

```sql
SELECT f.id AS id, t.dog_id AS dogId, f.source_mode AS sourceMode
FROM find f JOIN trip t ON t.id = f.trip_id
WHERE f.id = :sourceFindId;
```

`find` 表**没有** `dog_id`。归属只能经 `trip_id` 反查——这是「来源必须真实发生过」唯一的证明方式。

## 二、三条禁止（不是风格问题）

1. **不许有 `setDelivered()`**。`delivered_at` 归你（c）的投递器，适配器不许直接标「已到」。
2. **不许有 `now()`**。时间由调用方传进来。适配器自己造一个「当前时间」再决定到达，演示时延后礼物会永远不到。
3. **不许有 `nextTripSeq()` 自增**。只给 `currentSeq` 读数，`+1` 在业务层算（`meet.nextDeliverSeq`）。这样 Mock、SQLite、你的适配器算出来的 `deliver_after_trip_seq` 必然一致。

## 三、怎么验：一条命令

`lib/social/store.contract.test.ts` 把上面 11 个方法的行为写成 13 条断言，**同一套跑在 MemoryStore 和 SqliteStore 上，两套必须完全一致**（现在 26/26 绿）。

接入时照着改三行就行：

```ts
// lib/social/store.contract.test.ts 里的 SCENES
for (const scene of [memoryScene(), sqliteScene(), c8Scene()]) { … }
```

你的 `c8Scene()` 只需要两样：一个 `store`，和两个行数读数（`countExchange` / `countRelation`，回滚用例要用）。

```bash
node --experimental-strip-types lib/social/store.contract.test.ts
```

全绿 = 可以直接换；有红灯 = 差异在你那一行，不用改 `meet.ts` / `gift.ts`。

## 四、两处已知差异（都不是 bug，但要知道）

1. **`hasDog`**：MemoryStore 不配 `dogs` 时一律返回 `true`（Mock 只验写入逻辑，不验领养流程），SqliteStore 查 `dog` 表。契约测试里两边都显式配了狗，所以一致。你的实现请按真库语义。
2. **`relation.id` 形状**：`rel_<a>__<b>`（`store.relationId()`，字典序拼）。`meet.ts` 已统一到这一份；id 没有外部引用，换成别的形状也不影响读取（读靠 `(dog_a,dog_b)` 而不是 id）。
