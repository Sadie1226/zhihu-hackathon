## 三、两个新增读取契约

### 1. GET /api/dogs/:id/relations

返回 `RelationsResponse`，其中每项为：
`{ relation: Relation, otherDog: PublicDogSummary, snapshot: Snapshot | null }`。

- 请求狗必须属于服务端当前匿名 session；不存在、越权或没有有效服务端 session 均为 NOT_FOUND。
- 客户端不能指定或覆盖 session 归属。请求参数仅指定狗 ID。
- 返回请求狗位于 dog_a 或 dog_b 的关系；otherDog 是另一端。
- 保留 isBlocked，包括已拉黑记录；这是读取，不触发匹配或修改关系。
- 对方快照按最大 version 选取；不存在时返回 null。
- 排序：lastMetAt DESC，然后 relation ID ASC。
- 空结果：`{ relations: [] }`。
- PublicDogSummary 仅含 id、name、assembly、isSample；不暴露 sessionId、blockedTopics 或其他私有狗字段。
- `GET /api/relations` 不是规范路由，本次不增加全局关系集合。

### 2. GET /api/exchanges?from_dog=:id

返回 `ExchangesResponse = { exchanges: Exchange[] }`。

- from_dog 必须且只出现一次，是非空白单个字符串；不强制 UUID，fixture 短 ID 仍合法。
- 缺失或无效参数为 CONFLICT；请求狗不存在或不属于当前服务端 session 为 NOT_FOUND。
- 只读指定发送狗的记录，包含所有投递状态，三个状态时间原样返回。
- 排序：createdAt DESC，然后 ID DESC。
- 空结果：`{ exchanges: [] }`。
- 不新增 `GET /api/exchanges?to_dog=`；收件继续用 `GET /api/dogs/:id/inbox?filter=onTheWay|arrived|all`。
- 手账读取同一只狗的 outbox + inbox（filter=all），按 exchange ID 去重；无 from_dog 的 GET /api/exchanges 不是全局手账接口。

两个 GET 的归属检查与查询在同一只读事务中执行，SQL 也重复限定 session。
HTTP 层参数校验、可信 session 接入和 DTO 序列化仍需在后续路由实现中接入；本次不声称已做网络层鉴权验收。

## 四、类型、索引与数据转换

新增类型定义见 `contracts/types.ts`，不复制 Dog / Relation / Snapshot / Exchange 实体。
PublicDogSummary 的 id、name、isSample 引用 Dog 字段类型，assembly 复用 Assembly。
`Snapshot | null` 表示没有快照，不改变 Snapshot 内部 interestCategories 的定义。

新增索引：

```sql
CREATE INDEX idx_exchange_outbox ON exchange(from_dog, created_at DESC);
CREATE INDEX idx_relation_dog_a_recent ON relation(dog_a, last_met_at DESC, id);
CREATE INDEX idx_relation_dog_b_recent ON relation(dog_b, last_met_at DESC, id);
```

新库按 schema.sql 建库；已有库部署时只追加这三条索引，不重建表，不把整份建库脚本重复执行。

数据库 / fixtures 使用 snake_case；API 使用 camelCase。接口实现方在读取边界转换 JSON 文本与 0/1 布尔值。
D 的 rules.ts 以 camelCase 为唯一入口，测试加载 fixture 可使用 fromDbRow() 适配；不要求 E 在页面中转换库行。
