## 一、7 处类型错误：逐处对应

a 报的 7 处，两类根因。

### 1.1 `tx.concurrency.test.ts` 五处：闭包赋值不被控制流分析采纳

```text
tx.concurrency.test.ts(196,30) TS2339 Property 'blocked' does not exist on type 'never'
tx.concurrency.test.ts(197,37) TS2339 Property 'message' does not exist on type 'never'
tx.concurrency.test.ts(197,84) TS2339 Property 'message' does not exist on type 'never'
tx.concurrency.test.ts(290,30) TS2339 Property 'blocked' does not exist on type 'never'
tx.concurrency.test.ts(383,30) TS2339 Property 'blocked' does not exist on type 'never'
```

**根因**：`let attackResult: X | null = null` 之后，赋值只发生在传给 `attackingStore` 的
回调里。TS 的控制流分析不把闭包内赋值算进当前路径，读到该变量时类型仍是 `null`；
`assert.ok(attackResult !== null)` 于是被理解成「断言 null 不为 null」，`asserts` 签名把
不可能的那支收掉，剩下 `never`。`!` 非空断言对 `never` 也没用。

**改法**：换成容器对象的属性。

```ts
interface AttackOutcome {
  blocked: boolean
  message: string
}

const attack: { result: AttackOutcome | null } = { result: null }
// 回调里
attack.result = tryWrite(() => { /* 另一连接动手 */ })

// 断言处：先落成局部常量，再断言
const outcome = attack.result
assert.ok(outcome !== null, '攻击必须在查来源之后触发，否则这个用例没测到东西')
assert.equal(outcome.blocked, true, '…')
```

属性访问的类型是声明类型 `AttackOutcome | null`，不会被窄化成 `null`。**运行断言一条没减**：
「攻击确实触发」（`outcome !== null`）、「被拦/没被拦」、「被拦原因是锁冲突」都还在，
C1/C2b/C3 三处共 6 条断言原样保留。

没有用 `as`、没有 `any`、没有关 `strict`。

### 1.2 `scripts/e2e-d4.ts` 两处

```text
scripts/e2e-d4.ts(61,76) TS2345 Argument of type 'unknown' is not assignable to parameter of type 'SQLInputValue'
scripts/e2e-d4.ts(219,82) TS2698 Spread types may only be created from object types
```

**第一处**：`const one = <T>(sql: string, ...args: unknown[])` 直接 `db.prepare(sql).get(...args)`。
`unknown[]` 解到 `SQLInputValue` 形参上不成立。改成

```ts
import { DatabaseSync, type SQLInputValue } from 'node:sqlite'

const one = <T>(sql: string, ...args: SQLInputValue[]): T =>
  db.prepare(sql).get(...args) as T
```

`SQLInputValue` 是 `node:sqlite` 自己导出的绑定值联合（`null | number | bigint | string | 视图`），
比手写一个同形别名更贴运行时。

**第二处**：`sendGift({ …, ...(extra as never) })`。`extra` 是 `Record<string, unknown>`，
展开进对象字面量时值类型是 `unknown`，`never` 也不是可展开类型 —— 这是为了绕过类型检查写的，
本身就该删。改成按 `GiftInput` 的真实字段声明：

```ts
type GiftProbe = Partial<
  Pick<GiftInput, 'sourceFindId' | 'sourceMode' | 'idempotencyKey' | 'imagePath'>
>

const tryGift = (label: string, extra: GiftProbe): string | null => { … }
```

四条「非法入参」在**运行期**非法（假 id、别人的发现、谎报档位、显式 null 与库冲突），
在**类型层**完全合法 —— 所以本来就不需要 `as never`。故意非法的验证一条没删，还多了一步：
把返回的错误码接住交给断言（见第二节）。

## 二、E2E 跨平台：不再假设存在 `/tmp`

**原写法**：`const DBFILE = '/tmp/d4_e2e.db'`，存在就 `unlink`。Windows 上 `Error: unable to open
database file`（`ERR_SQLITE_ERROR`，errcode 14）。同名文件也不允许两份同时跑。

**现写法**：

```ts
const RUN_DIR = fs.mkdtempSync(path.join(os.tmpdir(), 'd4-e2e-'))
const DBFILE = path.join(RUN_DIR, 'd4_e2e.db')
```

每次运行一个新目录，跑完在 `finally` 里删：

```ts
try {
  main()
} finally {
  // 先关句柄再删目录：Windows 上文件还开着就删不掉。
  db.close()
  fs.rmSync(RUN_DIR, { recursive: true, force: true })
}
```

主体包进 `main()` 是为了让「中途抛错」也走清理路径 —— 原来末尾一句 `db.close()`，
前面任何一步抛错都到不了。清理失败不应盖掉断言结果，但 `rmSync` 放在 `finally` 里
已经是最后一步，抛错会盖掉退出码，所以顺序是**先 close 再 rm**（实测两次运行后
`%TEMP%` 下没有 `d4-e2e-*` 残留）。

## 三、E2E 的结论要可信：28 条断言 + 非零退出

原来「居然写进去了（错）」只是打印，脚本照样 `exit 0` —— 读者得自己从一屏文字里看出哪句是缺陷。
现在全部改成断言：

```ts
let failures = 0
const expect = (label: string, actual: unknown, wanted: unknown): void => { … }

// main() 末尾
if (failures > 0) {
  console.error(`\n${failures} 项断言未通过`)
  process.exitCode = 1
} else {
  console.log('\n全部断言通过')
}
```

**28 条**，覆盖：

| 组 | 断言 |
| --- | --- |
| 首次相遇 | 不是重放 / exchange 1 条 / relation 1 条 / met_count = 1 |
| 同趟重发 | replayed / exchange 仍 1 条 / met_count 仍 1 |
| 换一趟再遇 | met_count +1 / first_met_at 不动 / last_met_at 更新 |
| 反向发起 | relation 仍 1 行（字典序归对）/ met_count = 3 |
| 礼物延迟 | 新插入 / 趟次 = 4 |
| 礼物重发 | inserted = false / 趟次不变 / exchange 仍 4 条 |
| 种子狗 | 能收话 / 不能以自己主人名义发话 / 拒因 `SEED_OWNER_SPEAKS` |
| 来源（K v4） | 真来源 id 落库 / mode 由库派生为 `live` / 假来源、跨狗、谎报档位、显式 null **四条全拒** |
| 无来源 | 两个键都在、值都是 `null` |
| 收尾 | exchange 6 行 / relation 1 行 / met_count 3 |

**故意失败验证**（证明断言真会红）：

```bash
# 把「met_count = 1」的期望改成 2，其余不动
sed "s/rel().met_count, 1)/rel().met_count, 2)/" scripts/e2e-d4.ts > scripts/_e2e-broken.ts
node --experimental-strip-types scripts/_e2e-broken.ts; echo "exit=$?"
#   ✗ 第 1 次相遇：met_count = 1：期望 2，实际 1
#   1 项断言未通过
#   exit=1
```

正常跑：`全部断言通过`，`exit=0`。
