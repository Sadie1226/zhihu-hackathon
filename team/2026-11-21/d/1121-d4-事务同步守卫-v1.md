# 事务回调必须同步 —— 把 A 的口头接入条件变成会立刻炸的检查

2026-11-21。分支 `d4-async-guard-1121`，从 `4a6e0bb`（main v7-1121）直接切。
只改 `lib/social/store.ts`、`lib/social/sqlite-store.ts`、`lib/social/store.contract.test.ts` 与本文档。
不动生产规则、不动契约、不动 `gift.test.ts`（A 的 lint 清理）。

## 一、为什么现在做

A 11-21 的接入条件第 3 条：

> 事务调用须保持同步并复用同一 SocialStore 实例。当前 DatabaseSync 事务包装只覆盖同步回调；
> 不要在回调中 await 网络调用。

这句话在注释里已经写了两遍，但**注释不会拦人**。C8 联调时最自然的写法恰好就是错的：

```ts
// C8 很可能这样写
store.transaction(async () => {
  await assertWritable(sessionId, fromDog)   // ← 一 await，事务就散了
  sendGift({ ... })
})
```

## 二、错在哪（不是「不支持」，是会静默出错）

`transaction(fn)` 的语义是「`fn` 跑完，一次 `COMMIT`」。

`async` 函数在**第一个 `await`** 处就把控制权交回去并返回一个 Promise —— 对调用方来说，
`fn()` 在那一刻「已经返回了」。于是：

1. 外层拿到 Promise，立刻执行 `COMMIT` —— 提交的是**还没发生任何写**的空事务；
2. `await` 之后真正的写，全部落在**事务之外**（autocommit），一条一条各自提交；
3. 任何一步失败都不会回滚已经落下的那部分，调用方还以为整笔是一个原子操作。

所以它不是「功能缺失」，是**事务看起来在工作、实际什么都没保护**。这类缺陷在单测里
（同步回调）永远看不到，只在 C8 真实接入后才出现，而且要等数据对不上才会发现。

## 三、改法：一句检查，两套实现都过

`lib/social/store.ts` 新增：

```ts
export class AsyncTransactionError extends Error {
  readonly code = 'ASYNC_TRANSACTION'
  // 消息里直接给修法：异步步骤放到事务外，先取事实，再进事务只做写
}

export function assertSyncResult<T>(value: T): T   // 有 then 就抛
```

`SqliteStore.transaction` 在外层 `COMMIT` 之前、内层 `RELEASE` 之前各过一遍；
`MemoryStore.transaction` 在快照恢复的 `try` 里过一遍。两套实现必须给出同一个错误码，
否则「换适配器后行为变了」又会出现一次。

三个实现细节，都是刻意的：

| 细节 | 原因 |
| --- | --- |
| 判据是「有没有 `then`」，不是 `instanceof Promise` | 跨 realm 的 Promise、手写 thenable 都该拦；`async` 函数返回的是真 Promise，但 C8 也可能包一层 |
| 抛之前给那个 Promise 挂一个空 `catch` | 事务已经判失败，那个 Promise 之后还会跑完；不挂 catch 它会变成 `unhandledRejection`，把 `ASYNC_TRANSACTION` 这条真正该看的错误埋掉 |
| 外层检查放在 `COMMIT` **之前** | 放在之后没有意义 —— 那时候已经提交了 |

## 六、边界（说清楚，别当成解决了）

- **拦的是「回调返回 thenable」这一种形状。** 如果有人在**同步**回调里 `void someAsync()`（不返回、
  不等），这里看不见 —— 那本来也不是事务能管的事，属于调用方主动放弃原子性。
- **已经开始的异步体不会被中止。** 抛错只保证「事务回滚 + 调用方立刻拿到异常」，
  `await` 之后那些写仍会各自落库（autocommit）。所以这条检查的价值是**在第一次联调就打住**，
  而不是事后清理 —— 真出现了，那几行要人工核。
- **不改 `transaction` 的签名。** 没加 `transactionAsync`：给了它，等于承认「事务里可以 await」，
  而 SQLite 单连接上做不到真正的异步事务。要异步，就把 IO 挪到事务外。

## 七、给 C8 的一句话

不用改任何调用方式 —— 只要**不把 `async` 函数交给 `transaction`**：

```ts
// 对：异步的在外面，事务里只有同步写
const ok = await assertWritable(sessionId, fromDog)
if (!ok) throw ...
store.transaction(() => sendGift({ ... }))   // 同步

// 错：会抛 ASYNC_TRANSACTION，且不会留下半截数据
store.transaction(async () => { ... })
```
