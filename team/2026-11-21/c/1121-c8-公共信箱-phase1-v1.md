## 接口

| 方法和路径 | 成功 | 行为 |
| --- | --- | --- |
| `GET /api/dogs/:id/inbox?filter=onTheWay\|arrived\|all` | 200 `{ exchanges: Exchange[] }` | 省略 `filter` 时取 `all`。`arrived` 包含已读和已回应记录，两种筛选按 `delivered_at` 是否为 NULL。 |
| `GET /api/exchanges?from_dog=:id` | 200 `{ exchanges: Exchange[] }` | 恰好一个非空狗 ID。按 `created_at DESC, id DESC` 排序。 |
| `PATCH /api/exchanges/:id/read` | 200 `{ exchange: Exchange }` | E 打开某封已送达来信时提交 JSON `{}`。重复调用返回真实的首次 `readAt`。 |

生产服务的 HTTP 请求示例，使用运行环境实际发放的 Cookie。生产浏览器会话使用 HTTPS。

```http
GET /api/dogs/dog_owner/inbox?filter=arrived HTTP/1.1
Host: mailbox.example
Cookie: __Host-zhihu_session=<session-cookie>
```

```http
GET /api/exchanges?from_dog=dog_owner HTTP/1.1
Host: mailbox.example
Cookie: __Host-zhihu_session=<session-cookie>
```

```http
PATCH /api/exchanges/ex_message/read HTTP/1.1
Host: mailbox.example
Origin: https://mailbox.example
Cookie: __Host-zhihu_session=<session-cookie>
Content-Type: application/json
Content-Length: 2

{}
```

下面是一次 PATCH 的响应形状，两个 GET 将这类 Exchange 放在 `exchanges` 数组内。

```json
{

```

## 权限和数据

- 使用 `readSessionId` 取服务端 Cookie，再由 SQL 绑定 `dog.session_id`。收件和已读核对 `to_dog`，发件核对 `from_dog`。缺失或无效会话、指定对象不存在、跨会话均返回 404 `NOT_FOUND`。有归属的空集合返回 200 `{ "exchanges": [] }`。
- 无效编码、未知或重复参数、空白 `from_dog`、未送达已读及无效 PATCH 请求返回 409 `CONFLICT`。PATCH 核对 Origin 与目标 Host，拒绝跨站和跨源浏览器请求。数据库错误返回脱敏 503 `NETWORK`。接口响应带 `Cache-Control: no-store` 和 `Vary: Cookie`。
- 两个 GET 的业务 SQL 仅执行 SELECT。SQLite 投影输出 camelCase 和原时间戳。四种 payload 只返回 K 声明的字段。历史 `find`、`gift` 缺少来源键时保持原形状，K v4 来源 ID 和档位按原值返回。来源 ID 保持为引用，响应无私人 Find/Trip 展开、会话标识和 Cookie。
- K 契约第 7 节规定 C 实现信箱接口，E 的 E3 流程和交接约定只有打开已到详情才调用 PATCH。C 的事务在写锁内核对收件狗、送达状态和首次时间，更新范围限于 `read_at IS NULL` 的该行，随后返回完整行。损坏 payload 会使整个事务回滚。[K 契约](../../../contracts/api.md) · [E3 流程 v3](../../2026-11-16/e/1116-e3-页面流程-v3.md) · [E3 交接](../../2026-11-17/e/1117-e3-交接与待确认清单.md)

## 延迟投递和种子狗

C4 `start` 与现有 `deliverOnTripStart` 在同一事务内完成真实出发和投递。测试读取 `started_at` 和自动写入的 `delivered_at` 核对时间相等。已读、回应、历史 Trip 的状态与时间均有断言。

| 场景 | 临时 SQLite 实测 |
| --- | --- |
| seq 0 → 1 | `is_sample = 1` 的狗起初无 Trip。门槛 1 的交换在 pending 阶段在路上，C4 第一次 start 后到达。 |
| seq 1 → 2 | 门槛 2 的交换在 seq 1 和 seq 2 pending 时在路上。过早 start 返回冲突。两个 SQLite 连接并发调用合法 seq 2 start，只有一个调用实际投递，重试保留首次时间。 |
| overdue 补投 | 测试构造 seq 1 漏投，`isArrived` 报告 overdue，信箱 GET 保持在路上。下一个合法 start 经原投递器按 `<= seq` 补投。 |
| 历史与恢复 | seq 1 历史原样保留，`read_at` 和 `replied_at` 仍为 NULL，`reply` 为 0 行。关闭并重开 SQLite 后复核成功。 |

生产 HTTP 用实际的 Next 构建和临时数据库，验证陌生 Session 对种子狗出行入口返回 404。种子测试通过内部服务和专用夹具身份启动，生产可信服务端身份、内部触发入口以及 C10 调度均待验收。

本地生产 HTTP 联调发现 C4 旧 POST 对 `127.0.0.1` 请求携带的同源 Origin 有 409 情况，因为既有校验直接使用 Next 内部 URL。本轮 C4 调用沿用服务端测试客户端不带 Origin 的方式。C8 PATCH 已按目标 Host 验证同源与不同源。C4 的最小后续修订是在现有 HTTP 层统一 Origin 与 Host 校验并补浏览器回归。
