## 四、建议的正式契约文本（供 A/C 裁定，B 不自行写入 contracts）

重复回应的幂等语义建议固定为：

- 同一 `exchangeId` 或 `invitationId` 重复提交 → **HTTP 200** + `{ reply: <库中真实记录>, duplicate: true }`，不新建行、不改首次内容、不改首次 `replied_at`。
- 首次提交 → HTTP 200 + `{ reply }`（无 `duplicate` 或 `duplicate: false`）。
- 约束/送达/归属失败 → 409 / 404 / 401，按现有 Route 分态；**不返回假 ID**。
- `contracts/api.md` 及 B6 说明中「重复回应 409」的旧句建议改为上述 200+`duplicate` 口径；历史存档不回改，以新版本存档为准。

如 A/C 裁定正式契约仍保留 409，则 B 需配套改 Route 与调用方文案——但这会触碰「不改回假 ID、不覆盖首次」的红线，B 不单方执行，等三方结论。
