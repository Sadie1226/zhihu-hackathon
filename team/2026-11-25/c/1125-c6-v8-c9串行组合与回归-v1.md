## 确认、TTL 和重放

- 主人搜索通过 v8 的同一读事务复验身份、归属、running、当前屏蔽和稳定意图。合法回执直接得到可见成员和确认元数据。损坏回执、意图冲突和终态都在 provider/cache 前处理。此时外部 I/O 为零。
- 无回执时调用一次 C5。成功响应生产 live 证明并可写缓存。写缓存异常保留合法 live。RATE_LIMITED/AUTH 尝试缓存，AUTH 保留内部告警；NETWORK 延用可重试错误，cache miss 为空候选。缓存读写均在事务外，种子路径不用主人缓存。
- 缓存记录仍按 provider/version、owner、查询、类目和数量隔离，可供同 owner 后续符合条件的 Trip 复用。每次从合法记录新签的执行证明绑定消费方 owner、dog、Trip、intent。复制、序列化、历史 SQL 行或来源标签都无法获得证明。
- 从异步读取返回后以当前时间检查一次，首次提交在 `BEGIN IMMEDIATE` 内检查第二次，窗口均为 `0 <= age < 24h`。写锁内先处理已有回执，再评估在途证明。同意图并发失败者即使持有刚过期的缓存证明，也回交赢家结果。
- 首次采用的 cache Find 保持 `sourceMode='cache'`。完整批次回执用私有项 `['cache', normalizedQuery, normalizedCategory, originalFetchedAt]` 保存获取时刻，整份回执 SHA-256 覆盖该值。初次确认时刻另存 `completed_at`。重放最多验证两个持久时间之间的历史采用资格，当前时间及原缓存记录均不参与已完成事实。Find、回执和顺序仍由单事务保证。当前主题可以过滤到零条，完成状态仍为 complete。
- cache 项是现有私有 JSON 带类型项的兼容扩展。没有新增 SQL 字段、迁移或公共 DTO，`hash_version=1` 的字段、顺序、UTF-8 和算法原样保留。原 v8 live 回执可直接读取。上线组合后，旧 C6 v8 二进制遇到 cache 成员将按未知类型安全拒绝；A 若需回退应使用相应数据库备份。原始凭据、Cookie、请求头及额外私人原文未加入回执或缓存。

## 实际回归

Node 24.15.0，数据库及构建使用独立临时文件。所有提供方结果走真实 C5 解析器处理受控响应。未调用线上知乎，未访问正式五狗库。

| 交叉用例 | 观察结果 |
| --- | --- |
| live 冷进程重放 | 第一次达到 3 条并确认，第二个进程 provider/read/write 全为 0，成员、顺序、哈希和完成时刻逐字段一致 |
| 429 与 401 缓存首次确认、到期冷进程重放 | 各由子进程内 C5 成功响应先生产缓存，再触发降级，AUTH 保留告警。SQLite 真正写入 cache 成员与原始 `fetchedAt`，新进程超过 24 小时仍零 I/O 重放。GET 只返回原 Find，并验证当前屏蔽清空可见结果时仍 complete |
| 双进程混合竞争 | 两个独立 PID 都拿到不同候选，分别放行 live 或 cache 先确认。每种次序只留赢家的 3 条和 1 份回执。live 先确认的场景中，丢弃到锁内才过期的进程证明，失败者仍重放 |
| 作用域与首次过期 | 同 owner 和同查询可取得缓存，但消费方 proof 被绑定到新 intent。跨 intent 提交拒绝。首次缓存选择有效、写锁时恰好 24 小时，结果为 partial，只有 2 条可用场景且无回执 |
| 完整性与其他意图 | 错 intent、被改写的原始取得时间和缺失的确认成员均在外部 I/O 前明确失败 |
| 单条兼容竞态 | 在异步缓存读取时，由另一连接先确认完整批次；单条入口锁内返回赢家成员，保留已经发生的 AUTH 内部告警 |

原用例覆盖 owner/query/category 隔离、错 Trip 和复制证明、种子零 provider/cache、撤销和结束、当前屏蔽、故障回滚、旧档位保护、G3 快照与投递。首轮组合专项发现两处夹具假设不合 v8，分别调整先前提前于 start 的时钟和主题证据。交叉专项初次运行时，SQLite 行与 IPC 序列化对象的原型不同，调整为同形状逐字段严格比较后复跑。
