## 生产、选择与持久化

1. C4 start 和 C7 occurrence 提交后，主人路径检查稳定 owner、非种子狗和 Trip。通过 bound wish 或兴趣确定查询，先应用当前屏蔽。C5 最多调用一次。
2. C5 成功且整批内容校验通过后，用固定 provider/version、owner、规范化查询、类目及请求数量计算 HMAC 索引。记录保存规范 URL、标题、摘要、权威等级、赞数、原始 UTC `fetchedAt` 及成功响应的来源档位。进程内密钥生成索引，原始心愿、聊天、凭据及请求头不进入索引明文或日志。
3. 通过缓存写入的冻结记录由私有 WeakSet 登记来源。读取要求原对象身份，且 key 与 owner 都匹配。拷贝、序列化重建、历史 SQL 行、夹具或单独档位无法生产缓存证明。写入异常时 live 证明仍可用，失败写入即使留下适配器暂存对象也不会被采信。
4. 缓存选择使用异步读取完成后的服务端 UTC 时间，Find 提交使用 SQLite 写事务内的 UTC 时间。两处均要求 `0 ≤ now - fetchedAt < 24h`。恰好 24 小时、超窗、未来、缺时间及无效时间均不得作为缓存。读取和重试保留原始获取时间，不续期。C5 网络和缓存 I/O 均在写锁外。
5. C6 提交仍重新核对 owner、dog、Trip、running、Cookie 和当前屏蔽。可信证据精确决定 `sourceMode`。同 URL 的历史 Find 维持首存 ID、内容、时间及档位。当前缓存证明仅核验同内容的旧缓存行，档位或内容不符的旧行保留供历史读取。种子仍走独立受限入口，provider 与缓存方法均不可达。
6. 已确认完整批次以首次提交时间核验其原证明，并使用当前权限和屏蔽重放其成员。TTL 后仍可回放当时合法的缓存 Find，已在途的新 URL 无法扩充确认集合。终态使用历史 GET。重开数据库可读持久化 Find，完整批次的跨进程回执由 C10 接入。

| C5 结果 | C9 行为 |
| --- | --- |
| 成功 | 当次有效内容提供 live 证明，写缓存失败不影响 live。成功空集合可替代该键旧内容。 |
| `RATE_LIMITED` 或 `AUTH` | 无自动上游重试。可信缓存命中提供 cache 证明，未命中为空候选，既有 fixture 路径未自动启用。内部 `degradation` 保留错误类别和告警位，AUTH 保持 `alert: true`。 |
| `NETWORK` | 断网、超时、普通 5xx 或畸形响应延续网络错误及可重试语义，缓存适配器不参与。 |

## C10 调用接口

主人执行使用 `createTripDiscoverySearch(db, provider?, { cache?, now? })`，先在锁外等待结果。HTTP 来源把同一个原始 `Request` 交给搜索和 composer，以便提交时重验会话。成功时将 `result.proofs` 与可信场景交给 `createTripDiscoveryComposer(db, { now? })(tripId, scope, input)`，零证明也可以按已知场景得到 partial。C10 在服务端消费 AUTH 告警位和 NETWORK 重试语义。终态和完整批次沿用 C6 行为。B5/Message、邀请、部分补齐、跨进程完成回执及 finish 编排待 C10 联调。

### 持久化后端提案

请 A 评审独立的服务端缓存后端。可复用部署基础设施提供专用 Redis 命名空间，索引改用服务密钥 HMAC，缓存值用带版本和密钥 ID 的认证加密封装，绑定 provider、owner、索引、原始 `fetchedAt` 与内容。限权服务账号通过原子按获取时间更新，TTL 由原始时间计算，读取不续期。只有通过完整性、作用域和 UTC 窗口检查的记录才可重新产生进程内证明。验收覆盖跨进程重启命中、伪造值、错 owner、时钟边界、密钥轮换及错序写入。当前内存实现通过原对象身份核验，后端恢复证明按该提案单独实现。本轮无 v8 或附加迁移。
