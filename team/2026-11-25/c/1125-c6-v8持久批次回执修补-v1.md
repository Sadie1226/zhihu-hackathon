## P1 根因和执行时序

原 C6 完整确认存于进程内 `confirmed`、`confirmedFiles` 和 `confirmedBatches`。进程退出后，另一进程仍能搜索不同 URL 并追加到已完成旅途。本轮移除这些确认状态，搜索前和写入时都以同一 SQLite 回执为准。

1. 主人执行传可信服务端 `intentId`，同时传已认证 owner ID 或原始 Cookie Request。旧内部调用若省略意图，使用按 Trip 确定生成的 `c6-owner:` 加 SHA-256 ID，跨请求与进程稳定。种子沿用 G3 已核验的 `dogId/tripId/intentId`。意图用于绑定执行，授权仍来自真实身份和 Trip 归属。C5 的进程内 proof 另绑定同一个意图。
2. 搜索前，同一读事务内认证、验证 running 和读取当前屏蔽及持久回执。合法回执直接返回重放，损坏回执返回内部完整性错误，已确认的另一意图返回冲突。该读事务结束后才调用 C5；种子无搜索入口。
3. C6 取得现有 `BEGIN IMMEDIATE` 写锁后再次认证并读取回执。已有合法回执时直接按其成员回放，忽略在途搜索结果。另一意图失败，无新行。当前 SQLite 初始化保持 WAL、外键和 5000 ms busy timeout，错误向上返回。
4. 无回执时沿用 C6 拼装和 partial 持久化。首次达到原 complete 门槛时，写完 Find 后在同一事务插入回执，再读取所存成员做一致性核对。Find、回执 INSERT 或 COMMIT 任一失败均回滚。返回首次 complete 之前须已 COMMIT。
5. 重放逐项校验已存成员存在、在同一 Trip、内容哈希及私有核验结构有效。事件成员还通过 G3 唯一冻结事实 adapter 验证。重新应用当前屏蔽，保留原顺序和完成时刻。当前可见成员不足三条甚至为零时，原完成状态仍为 complete。终态继续通过已授权历史 GET 回看。

## 表、哈希及私有核验

v8 仅添加 `trip_discovery_receipt`，权威 fresh schema 和运行时 DDL 相同。表使用 SQLite STRICT，`trip_id` 主键及外键唯一关联 Trip，`dog_id` 和可空 `owner_id` 分别外键绑定狗和主人。种子 owner 为 null。其他字段为 `intent_id`、规范 UTC `completed_at`、`hash_version`、`members_json` 和 `receipt_hash`。

- 数据库约束检查意图格式、时间、版本、摘要格式及 3–5 项 JSON 数组。触发器验证 running、实际狗、owner/示例状态和出发时间，并拒绝替换、更新与删除。事务及重放代码核对 JSON 项结构、逐项归属、唯一 ID、成员哈希、成员顺序及完整性。JSON 内部跨记录关系由应用在事务内核验。
- `hash_version=1`。成员内容 SHA-256 的输入是固定顺序 JSON 数组，UTF-8 编码，先放域 `c6-find-content`、版本，再放 `id, tripId, kind, title, excerpt, sourceUrl, sourceMode, authorityLevel, voteUpCount, assetPath, createdAt`。按持久化原值使用字符串，包含 URL 字节及时间表示，不再 trim 或改时区；可空字段显式编码 null，缺失值或类型错误拒绝。整份回执摘要另绑定版本、Trip/狗/owner、意图、完成时刻和有序成员数组。摘要用于检测损坏和变化，具有任意数据库写权的主体可以同时篡改摘要，真实来源仍由 C5/C6 证明和 G3 冻结事实支撑。
- 每个成员为 `[Find ID, 内容 SHA-256, 屏蔽核验信息]`。知乎只存现有屏蔽算法所需的 NFKC、zh-CN 小写查询及类目，不额外存心愿对象或历史原文副本。观察只存可信主题；未传主题时存 null，与有证据的空数组区分。事件只存冻结发生时刻，历史主题保持未知。当前存在屏蔽规则且主题无法核实时，保守过滤。Cookie、密钥、请求头和无关私人数据不进入回执，私有核验信息不进入 DTO、GET 或错误信息。
- 完成时刻使用服务端毫秒 UTC ISO。公开 Find 和读取契约保持原形状。已有 Find 可能属于旧 partial，也可能来自曾在 v7 进程内确认的批次，缺少可信历史证据，v8 不自动补回执。切换前建议 A 对仍 running 且有旧候选 Find 的 Trip 暂停自动重跑，逐趟人工决策历史回看或结束；已结束读原历史。

## 给 C10/B5 的内部调用

```ts
const search = createTripDiscoverySearch(db, provider)
const selected = await search(tripId, originalRequest, trustedIntentId)
if (!selected.ok) return selected
const result = createTripDiscoveryComposer(db)(tripId, originalRequest, {
  intentId: trustedIntentId, searchProofs: selected.proofs, observations,
})
```

搜索重放返回 `replay: { finds, confirmation }`，`proofs: []`。调用方可直接消费该只读结果，或经 composer 在锁内复验。composer 现有 `status/finds/reasons` 保留；complete 带 `confirmation: { completedAt, replayed, visibilityReasons }`，partial 无 confirmation。过滤原因只有 `BLOCKED_TOPICS`、`TOPIC_EVIDENCE_UNAVAILABLE`，不返回被过滤成员。权限失败使用 `NOT_FOUND`，running/意图冲突使用 `CONFLICT`，损坏使用内部 `DISCOVERY_RECEIPT_INVALID`，禁止据此重搜。单条 C6 兼容入口在未确认时仍按原规则写一条，已确认时返回可见重放。Find GET 不返回回执。
