## 2. 本轮两项修复

### 2.1 读取失败覆盖旧屏蔽词

- 根因：`PATCH /api/dogs/:id/blocked-topics` 是整列覆盖。上一版读取失败时 `phase='error'` 但 `topics` 仍是空数组，输入框与按钮仍可用；用户此时新增/删除会以空列表（或不完整列表）为基准 PATCH，把服务端已存旧词清掉。
- 修复：新增纯守卫 `canWriteTopics(phase, active)`，只有 `phase==='ready'` 且面板可见才允许写。错误态改为独立渲染：显示错误与提示「读取成功前不能改写」，只提供「再读一次」重试，不再渲染可写输入与列表。
- 效果：读失败/读中/保存中/面板隐藏四种态一律拒绝写入，杜绝用不完整快照覆盖服务端真值。

### 2.2 面板取消后重开卡状态

- 根因：上一版 `active=false` 只 `abort()` 在途请求，不改 `phase`。若取消发生在保存中，请求被 abort 后 `save()` 的 `if (aborted) return` 直接返回，`phase` 永久停在 `'saving'`；重开后面板的增/删按钮因 `phase==='saving'` 被禁用，卡死。
- 修复：`active=false` 时打断在途请求并用 `phaseAfterDeactivate()` 把 `loading/saving` 复位为 `ready`（`error` 保留给重试）；`active` 从 false 变 true 时递增 `reloadKey` 重读一次服务端真值，不自动重发未完成的写入。
- 效果：重开后按钮可用、列表显示的是服务端已提交的状态；被打断的写不会重传，也不会用旧内存覆盖。

## 4. B5/Message 与 C10/C11 真实数据链：B 的边界

链接顺序（A/C 编排）：C10 触发 → C4 出发绑定快照 → C7 事件 → C6 保存 Find → **B5 生成归来分享/邀请** → 完成旅途 → A 页面及回应接线。
