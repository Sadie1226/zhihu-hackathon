## 4. 与交付包的一处差异（只改验证脚本，不改业务）

`scripts/e6/verify-inbox-default.mjs` 原第 23 行是：

```js
assert.equal(await page.getByRole('alert').count(), 0)
```

在本机环境里这一行**稳定失败**（实测 3 次都是 `1 !== 0`）。原因是 Next App Router 会挂一个 `#__next-route-announcer__`，它带 `role="alert"`、文本为空、位于 shadow root 内：

- `document.querySelectorAll('[role="alert"]')` 查不到它（不穿透 shadow root）
- Playwright 的 role 引擎会穿透 shadow root，于是把它算进 `count()`

它是框架自带的读屏播报容器，不是这一页的报错。所以我把断言收窄到页面主体：

```js
assert.equal(await page.locator('main').getByRole('alert').count(), 0)
```

语义没变——「邀请失败的提示必须已经消失」，只是不再把框架 chrome 算成业务告警。改的是验证脚本，`mailbox-view.tsx` / `mailbox-preview.tsx` 与交付包逐字节一致。

另外：`getByRole('alert').filter({ hasText: '邀请暂时读不到' })` 那两处不受影响，空文本的播报容器匹配不到这个文本。
