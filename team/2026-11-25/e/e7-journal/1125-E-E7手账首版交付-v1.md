## 1. 首版做了什么

正式路由 `/journal`，沿用 `AppShellProvider` / `SessionGate`，米白像素风，页头有「回小屋」。默认落在「旅途」，页内三个分类：

| 分类 | 数据来源 | 首版行为 |
| --- | --- | --- |
| 旅途 | `GET /api/dogs/:id/trips?limit=50` → `GET /api/trips/:id/finds` + `GET /api/trips/:id/message` | 列出历史出行；展开才按这一趟自己的数据取地点、发现条数与归来话 |
| 来往 | `GET /api/dogs/:id/inbox?filter=all` + `GET /api/exchanges?from_dog=:id`，按 exchange ID 去重 | 保留收发方向；未送达收件不露标题正文、不给拆信；作者可读自己的发件 |
| 收到的礼物 | 从 inbox 派生：`kind='gift'`、`to_dog` 是本狗、`delivered_at` 非空 | 只列已收到；不标「已珍藏」，不做收藏操作 |

没有新增 `to_dog` 查询，没有新增回应接口，没有新增写入口（除主动拆信时的已读 PATCH）。

### 判定函数复用

`canOpen` / `letterState` / `letterTitle` / `safeSource` 直接来自 `components/e6/mailbox-model.ts`，不复制第二套口径。手账只补三件事：`mergeExchanges`（收发合并去重）、`receivedGifts`（礼物归属）、`tripOutcome`（出行结果文案）。

## 3. 业务边界（逐条对照要求）

1. **未送达收件不显示标题正文。** `entryBody()` 对封存项一律返回 `null`，视图拿到 `null` 就不渲染正文；`letterTitle()` 对未送达收件返回「有一份东西还在路上」。即使 `read_at` / `replied_at` 有脏值也不会放开（单测覆盖）。
2. **不提供拆信或回应。** 封存卡片没有「拆开看看」，也不出现详情面板。
3. **是否送达只读 `deliveredAt`。** 没有本地推断，没有按 `deliverAfterTripSeq` 猜。
4. **只有主动拆开已送达收件才 PATCH。** `shouldMarkRead()` 只对「收件 + 已送达 + 未读」为真；发件人读自己的发件不写任何时间戳。
5. **E 不写 `deliveredAt` / `repliedAt` / 关系事实 / 狗快照。** 手账没有任何这类写入口。
6. **示例伙伴标明。** 伙伴信息来自 relations；`isSample` 为真时标「· 示例伙伴」。读不到关系就写「伙伴身份信息暂未读到」，不编名字。
7. **请求失败与成功空列表分开。** 失败走 `phase='error'` 并给「重新读取」，空列表走空态文案，两者不共用。
8. **回复复用 B 的 `ReplyBody`。** 通过 `ReplySlot`，`origin="journal"`，`returnTo="/journal"`。

## 4. 独立降级

三个分类各自一个加载单元，互不牵连：

- **旅途**：`trips` 失败只影响旅途；单趟展开时 `finds` 与 `message` 用 `Promise.allSettled` 各自标记，一个失败另一个照常显示。
- **来往**：inbox 与 outbox 同一次加载但分别标记。只失败一侧时显示「收件暂时读不到…」或「发件暂时读不到…」并保留另一侧；两侧都失败才整块失败。礼物与来往共用同一次 inbox 读取，不重复打接口。
- **礼物**：inbox 失败时显示专门的失败态，不退化成「还没有收到礼物」。

切换身份或切换分类都会 abort 旧请求：每个 effect 用 `AbortController` 并在 cleanup 里 abort，回调里再判 `signal.aborted` 才 setState；已读请求另有 ref 持有，切分类、关详情、组件卸载都会作废。

## 6. 接口缺口（今日实测）

| 接口 | 实测 | 后果 |
| --- | --- | --- |
| `GET /api/dogs/:id/trips?limit=50` | 200 | 旅途可用 |
| `GET /api/trips/:id/finds` | 200 | 发现可用 |
| `GET /api/trips/:id/message` | 200 | 归来话可用；`null` 视为「这一趟没有留下归来话」 |
| `GET /api/dogs/:id/inbox?filter=all` | 200 | 来往收件、礼物可用 |
| `GET /api/exchanges?from_dog=:id` | 200 | 来往发件可用 |
| `PATCH /api/exchanges/:id/read` | 200，写库 | 拆信写已读可用 |
| `GET /api/dogs/:id/relations` | **404** | 伙伴名、示例标记、屏蔽规则都读不到 → 如实提示，不编名字 |
| 礼物列表接口 | **不存在** | 从 inbox 派生已收到的 gift；这是读取降级，不是新接口 |
| `routes.journal` | **仍为 `false`** | 全站导航没有手账入口，只能直接访问 `/journal` |

`relations` 缺失的影响：首版手账不做发件、不做举报屏蔽，所以只影响「伙伴叫什么」和「是不是示例伙伴」，不影响阅读与拆信。这条与 E6 一致，属于 C 未落地。

### 关于 `next.config.ts`

本基线没有 `allowedDevOrigins`，手机用局域网 IP 打开会白屏。我加了与 A 在 `a-slider-fix-1124` 里**完全相同**的一行：

```ts
allowedDevOrigins: ['127.0.0.1', ...(process.env.DEV_ALLOWED_ORIGINS ?? '').split(',').map(host => host.trim()).filter(Boolean)],
```

内容一致，合并时不会冲突；如果 A 决定用自己的版本，直接以 A 的为准。这一行只影响开发服务器放行来源，不改任何页面、鉴权或业务逻辑。

## 7. 给 A 的最小接线说明

1. **导航入口**：`wiring.tsx` 里 `routes.journal` 改为 `true`（当前是 `false`）。E 不新增全局导航，也不改 A 的 wiring。
2. **刷新时机**：手账的刷新依赖 `revisions.exchanges`。如果希望「出行结束」也刷新手账，需要在 `committed()` 里补一次 `journal` 或 `exchanges` 资源；不加也能用，只是要手动切分类或重进页面。
3. **回应**：`bindings.ReplyBody` 已由 B 绑好，`ReplySlot` 可直接用；若某天 B 的模块下线，手账会显示「回应模块尚未接入，这封信仍可继续阅读」，不会报错。
4. **不需要的东西**：手账不发件，所以 `CoOwnerMessageBody` / `RelationshipActions` 未接也不影响首版；不新增导航、不新增弹层、不新增接口。
