## 2. 视觉改动逐条

### 2.1 三层暖色

| 层 | 选择器 | 底色 | 作用 |
| --- | --- | --- | --- |
| 页面底 | `.page` | `#f4e9d6` + `radial-gradient(#e6d8bf 1px)` 8px 网点 | 最暗，像素网点 |
| 卡片 | `.card` | `#fffaf0` | 中间层，列表项 |
| 展开信纸 | `.paper` | `#fffdf7` + 32px 行线 | 最浅，带极淡行线 |

实测三值互不相同、亮度逐层递增（第 4 节）。边框从 `2px` 收轻到 `1px`（`.card` / `.tabs` / `.paper` / 控件）。像素角色与图标描边、`image-rendering` 相关样式未动。

### 2.2 选中分类

同时用三件事区分，不只靠颜色：

- 底色 `#eddfc4`（未选中为 `#fffaf1`）
- 字重 `600`（未选中 `400`）
- 底部细标记 `box-shadow: inset 0 -3px 0 #8b6b42`

实测 375×667：选中 `rgb(237,223,196)` / `600` / `inset`；未选中 `rgb(255,250,241)` / `400` / `none`。

### 2.3 按钮轻压与键盘焦点

- 轻压：`.page button:not(:disabled):active{transform:translateY(1px);background:#f2e4cb}`，只动 `transform` 与底色，**不动盒子尺寸**。
- 焦点：`.page button:focus-visible,…{outline:none;box-shadow:inset 0 0 0 2px #8a6636, 0 0 0 3px rgba(138,102,54,.2)}`，暖棕内环 + 浅外阴影，不改变盒子尺寸、不产生布局跳动。选中态聚焦时把「底部细标记 + 内环 + 外阴影」三层叠加，不互相覆盖。

实测（三个视口）：按下时 `transform: matrix(1,0,0,1,0,1)`，`getBoundingClientRect` 尺寸前后一致（375/320 为 54×44，1440 为 62×46）；键盘 Tab 到分类按钮后 `box-shadow` 含 `inset` 与 `rgb(138,102,54)`，盒子尺寸前后一致。

### 2.4 逐字渐显试样（可关闭）

只作用于**新到、已送达**的收件，且只作用于「短首段」：

- 首行 ≤60 字（`REVEAL_LIMIT`）才逐字；超过 60 字或首行过长，整段直接显示，不做动画
- 字间错峰 `16ms`（`animationDelay = index * 16ms`），单字时长 `200ms`（落在 180–240ms 区间）
- 只动 `opacity`，**不加高斯模糊**，避免像素字发虚
- 点一下正文任意处 → 立即显示全文（`revealedNow`）
- 已读回看 → 直接全文，不再渐显
- 页内有「关掉逐字渐显 / 打开逐字渐显」，选择存 `localStorage['e7-journal:reveal']`
- 系统「减少动态效果」→ 组件 `reducedMotion` 为真时直接全文；同时 CSS 侧 `@media (prefers-reduced-motion:reduce){.glyph{animation:none;opacity:1}}` 兜底
- 读屏读的是完整原文：外层 `p` 带 `aria-label={全文}`，逐字 `span` 为 `aria-hidden="true"`，不会逐字播报
- 未送达收件**不经过这个组件**（`entryBody()` 返回 `null`，封存卡片连拆信入口都没有），因此动画不可能提前渲染未送达正文
- 渐显本身不触发任何请求：已读 PATCH 只由 `openLetter()` 里的 `shouldMarkRead()` 决定，同一封第二次打开不再发

### 2.5 timeout 文案

| 项 | v1 | v2 |
| --- | --- | --- |
| 状态标签 | `回来得晚` | `这次超时了` |
| 说明 | `今天它回来得晚，没带回什么。` | `这一趟超时结束，没有按时回来。记录保留着。` |

不再用「回来得晚」这种说法暗示它成功回来了。实测三视口：`这次超时了` 出现 1 次，`回来了` 出现 1 次（只属于 done 那趟），精确文本 `回来得晚` 出现 0 次（夹具里那句归来话「今天回来得晚，路上绕了远。」是完整句子，不构成标签命中）。

## 5. 没验证到的

## 9. 手机验收前的准备记录（保留，便于复现）

真机要验的只有四件事，都能在夹具页做完，不需要真实身份。这一节是当时给出的操作口径，实际结果见第 10 节。

| 项 | 怎么看 |
| --- | --- |
| 配色、边框、正文阅读感 | 打开 `/e7-preview`，看页面底／卡片／展开信纸三层是否分得清，卡片边框是不是一条细线，长正文读起来累不累 |

| 点正文立即全显 | 渐显过程中点一下正文，整段立刻变实，不用等 |
| 关闭渐显后刷新仍直接全文 | 展开信里点「关掉逐字渐显」，再刷新页面，重新点开同一封（或任何一封「新到」的），直接给全文，不再逐字 |

**夹具的重置方式就是刷新页面。** 夹具的客户端每次挂载都会重新造一份未读数据，所以刷新后那几封又变回「新到」；只有「关掉逐字渐显」这个选择存在 `localStorage['e7-journal:reveal']` 里，刷新不会丢——这正是第 4 项要验的。

夹具里可用的「已送达未读」信共三封：`朋友的近况`（12 字首段，渐显最明显）、`河边的一封长信`（首段 29 字 + 68 字正文，用来看长文阅读感）、`一小卷灰蓝色的毛线`（礼物，5 字附言）。

正式页 `/journal` 需要已有身份：没有会话会跳去 `/adopt`。新领养的狗没有出行和来信，正式页上看不到信，所以渐显那几项在夹具页验；正式页只看配色、边框和整体阅读感。

## 11. 单列给 A：`next.config.ts` 的 `allowedDevOrigins` 差异

这是本分支唯一一处落在共享配置上的改动，**不属 E7 业务范围，单独列出来交 A 决定**。

相对基线 `6f5282d`，`next.config.ts` 只多了一行：

```ts
allowedDevOrigins: ['127.0.0.1', ...(process.env.DEV_ALLOWED_ORIGINS ?? '').split(',').map(host => host.trim()).filter(Boolean)],
```

**为什么需要：** Next 16 会把非 `localhost` 来源的 `/_next/hmr` 判成跨来源开发资源并拦截。缺这一行时，用 `127.0.0.1` 或局域网 IP 打开页面，HTML 能出来但客户端不水合——标签点不动、列表永远停在「正在读取…」。手机真机验收和 E6 增量分支都撞过这个坑（E6 分支没改配置，只能改用 `localhost` 访问）。

**与 A 的关系：** 这一行与 A 在 `a-slider-fix-1124` 里的写法**逐字相同**，合并时不会冲突。是否保留、放在哪个版本里，由 A 统一决定；E 不擅自改共享配置，也不在别的分支重复加。

**影响面：** 只影响开发服务器放行来源，不改生产构建、鉴权、路由或任何业务逻辑；`DEV_ALLOWED_ORIGINS` 不设时退化成只放行 `127.0.0.1`。
