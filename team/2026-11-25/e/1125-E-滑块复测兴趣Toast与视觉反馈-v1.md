## 2. 兴趣选择：规则已有，提示不够醒目

用户特别澄清：不是缺规则，而是当前规则写得不明显。原交付口径保持“选择兴趣时选2–3类，或跳过兴趣”。本轮提出反馈方式优化，不直接将校验规则改为任选1–3类。

| 操作 | 期望行为 | 两秒 toast 建议文案 |
| --- | --- | --- |
| 仅选1类后点击继续 | 留在当前步骤，选择不丢失 | “请再选1类，或跳过兴趣。” |
| 已选3类，再尝试点第4类 | 拒绝新增，保留原3类，不替用户取消已有项 | “最多选择3类，请先取消1类。” |
| 已选2或3类后点击继续 | 正常进入下一步 | 无需错误 toast |
| 点击跳过兴趣 | 按既有跳过规则进入下一步 | 无需错误 toast |

用户倾向用约2秒的toast给予即时提醒。建议同时把现有说明明确呈现为“选2–3类，也可以跳过”，并保留就近选择计数。

实现要求供 A 采用：toast浮于页面，不占用文档流，不把按钮或卡片顶动；重复触发更新当前提示，不堆叠多个弹层。第四项必须有可触达的反馈路径，不能只把未选卡片禁用而完全没有解释。提示由辅助技术可读，保留清楚的静态规则，不能只靠短暂弹层传达限制。震动是用户提出的可选辅助，不是本轮必做，也不能让整个页面晃动。

验收：分别验证1类继续、3类后点第4类、2/3类继续和跳过；toast约2秒，拒绝操作后选择不变、页面不位移；反复操作不遗留弹层。

## 4. 微对比与聚焦：建议先实施的小范围

界面采用米白、浅麦色、暖棕和陶土红的渐进层次。用户“去掉黑粗边”的建议针对界面控件，不要求消除刘看山、场景或纸张插图的像素描边。

输入框建议：默认浅麦细边；聚焦用暖棕色 inset 内环及克制的外阴影共同加深；错误用暖砖红边线与就近说明。边框/阴影切换不改变盒子尺寸，聚焦时仍应清楚可辨，不能以柔和为由丢失键盘焦点。

先在名字输入框、兴趣卡、主次按钮上试样，不做全站覆盖式替换。实际颜色需结合现有像素字体和手机可读性确认。

## 5. 暗色模式：先样稿，再定开发范围

用户提出增加暗色模式，并适当降低暗色下文字粗细。建议先给名字页与小屋各一张“夜间小屋”样稿：深暖灰背景、暗棕灰面板、柔和米色文字、低亮度陶土红按钮。

当前小屋图已有整体光照，不直接全站反色或压黑图片。首轮先评估外围暗色与原图是否协调，夜景素材另定。减字重仅用于有相应字重、且实际可读的字体；不能全站机械减一档或对像素字体强行变细。

本项是视觉提案，尚未获全站开发/新增素材批准，不阻塞现有任务。

## 6. 书信晕染：时间单位已确认是毫秒

用户确认：相邻字错开“十几毫秒”，不是十几秒。录屏没有拆信阅读页面，因此以下是来信页的新动效提案，不是录屏缺陷结论。

建议试样参数：相邻字16ms错峰、单字180–240ms渐显；透明度为主，模糊约0.5px到0作为可选微量效果。仅首次拆信的短首段使用，前字尚未完全清晰时后字开始，以形成轻柔波浪。

避免整封信逐字强制等待。正文始终可完整阅读，点击可立即显示全文；回看直接显示，减少动态效果时关闭；辅助阅读使用完整原文，不逐字制造重复播报。试样需验证手机性能，不能用模糊破坏像素字轮廓或放大滑动负担。

行内图标可从下移0.125em开始视觉校准；按实际图标留白逐项调整，不把统一位移当成已验证对齐。

## 7. 动效区分性格，但服务已有操作

| 操作 | 建议动效气质 |
| --- | --- |
| 性格滑块 | 跟手、松手稳定；不回弹、不顶动布局 |
| 兴趣卡选中 | 短促色阶变化＋勾选反馈 |
| 穿搭选择 | 选中标记轻快，角色锚点与舞台稳定 |
| 继续按钮 | 短暂压下，快速恢复，不夸张弹跳 |
| 拆信 | 安静缓慢的错峰渐显，可跳过 |
| 规则 toast | 快速出现、柔和淡出，不占位 |

用户以拖拽吸附和点赞举例表达“操作不同，动效性格也不同”；不据此在本产品新增拖拽功能或人的点赞入口。
