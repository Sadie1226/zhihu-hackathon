## 一、A 指出的那处错位，改了什么

原 `earliestEvent` 长这样：

```sql
SELECT te.event_id, te.happened_at, e.code, e.text
  FROM trip_event te JOIN event e ON e.id = te.event_id
 WHERE te.trip_id = ? AND te.dog_id = ?
 ORDER BY te.happened_at ASC, te.event_id ASC
```

两个问题，正好是 A 那句话的两半：

| 问题 | 后果 | 现在 |
| --- | --- | --- |
| `JOIN event` 读 `code` / `text` | 摘要固定了，**来源证据还在跟着改文案变** —— 改一次模板，旧 trip 的 `evidence.event.text` 就换一次 | 只读 `trip_event`（`event_id` / `happened_at`）。`text` 取冻结事实；`code` 正式态为 **null** |
| `ORDER BY te.happened_at`（字符串） | 与 C 的 `julianday(...)` 不同序。`2026-11-24T03:00:00Z` 和 `2026-11-24 03:00:00` 混存时，D 认为最早的那条和 C 认为的不是同一条 | 统一 `julianday(happened_at), event_id` |

`pendingWaiting`（`delivered_at`）与 `findsOf`（`created_at`）同样是字符串排序，一并改成 `julianday`。
`recentTrips` 保持 `ORDER BY seq DESC` —— 那是「第几次出门」，整数单调，与文本时间格式无关。

### `code` 为什么正式态是 null

`OccurrenceFact` 只有 `{ text, sourceId, capturedAt }`，adapter 不透传 `event_code_at_occurrence`。
拿今天的 `event.code` 去填，就等于把「证据也不会变」这句话又说反一次。

所以：**正式态 `code` 为 null，且不读 `event` 表**。`evidence.event.id` 仍是发生当时那条（`trip_event.event_id`），
`factSourceId` 里也带着同一个 id，追溯链没断。

如果证据里必须留发生时的 code，需要 C 在 `occurrence-facts.ts` 多返回一个字段（视图里已经有 `event_code_at_occurrence`）——
那是 C 的文件，D 不擅自改，也不在旁边再写一份 SQL 去取（两份 SQL 迟早在「取哪条最早」上分叉，且不报错）。

## 二、CLI 默认接固定事实

```bash
node scripts/d5-derive-snapshot.mjs --db <v7库> [--out evidence.json] [--sql-out x.sql --version N]
```

- **默认** `occurrenceFacts: readOccurrenceFact`（直接 import C 的 adapter，不复制 SQL）。
- 库没有 `v_trip_event_history` 时**直接报错退出 1**，并给出两条正确出路（升 v7 / 显式诊断）。
  不会因为「读不到视图」就悄悄退回模板 —— 那正是要防的事。
- `--template-diagnostic`：显式诊断态，摘要取当前模板，报告标「模板诊断态」，`--sql-out` 照拦。

实测（v7 库，`dog_seed_07` 一趟 done、一条事件）：

```
event ev_cli (code 不入正式证据) @ 2026-11-24T03:00:00.000Z
摘要 「店门口的猫抬头看了它一眼。」
历史固定：全部摘要来自发生当时固定下来的那份，不随改文案变化。
```

把该事件 `text` / `code` 都改掉再跑，**输出一字不变**。

无视图库（演练库 d3.sqlite）：

```
这个库没有 v7 历史视图（v_trip_event_history）：…
  · 让 C 用接口入口把库升到 v7，再跑本命令（正式证据只能这样出）；
  · 只想看形态，显式加 --template-diagnostic（产物标未固定，SQL 会被门禁拦）。
这里不会替你降级成「读当前模板」—— 那正是要防的事。
```

## 三、探针改走真链路，已转绿

`scripts/d5-history-probe.mjs` 原来是自己插 `trip_event` + 一张 fixture 事实表。
那只能证明「读取器写得对」，证明不了「链路真的捕获了」—— 后者才是 A 要验的。

现在走真的：

```
v7 接口库（openD5InterfaceDatabase，真实 v6→v7 迁移）
  → C4 create / start / finish（真 trip）
  → C7 选择器写 trip_event（v7 触发器顺手写 trip_event_fact）
  → D 的 deriveSnapshot + A 的 readOccurrenceFact
  → 改 event.text + event.code
  → 再派生
```

跑出来：

```
① 已存 snapshot 是否被改写
✅ v1 仍是当时那句
② 同一旧 trip 进**新版本**时，摘要是否稳定
✅ 模板改文案 + 改 code 后，旧 trip 摘要不变
     v1：店门口的猫认得每个进门的人，只对熟的抬头。
     v2：店门口的猫认得每个进门的人，只对熟的抬头。
     来源标注：occurrence（factSourceId trip_event_fact:["trip_…","ev_any_shop_cat"]），本批 historyFixed=true
③ 发生当时那份事实本身是否稳定（改模板不该动它）
✅ readOccurrenceFact 前后一致
结论：历史已固定 —— 改文案 / 改 code 都不影响旧 trip，旧版本同时保持不变。
```

退出码：缺口开着 → 1；`--allow-open-gap`（旧名 `--expect-open-gap` 保留）用于「已知未修时的巡检」。
现在正常跑是 0。

> 探针仍然**不进 `node --test`**：它要真跑 C4 + C7，比单测重；而且它验的是「整条链路的行为」。
> 单测那一层由 A 的 `tests/d5-interface-ready.test.mjs` / `tests/snapshot-history-fixed.test.mjs` 覆盖。

## 四、演练脚本的 Windows 三坑

`scripts/d5-seed-drill.mjs` 在 PowerShell 下跑不起来，三个都是实测踩出来的，不是猜的：

| 坑 | 表现 | 处理 |
| --- | --- | --- |
| `git` 不在 PATH | `spawnSync git ENOENT` —— 报错里既没「找不到 git」也没「该指哪」 | 按候选顺序探（`GIT_EXE` → `git` → `C:/Program Files/Git/…`），探不到给人话 + 三条出路 |
| 中文 / 带空格路径 | 拼 shell 字符串就炸 | 全程 `path.resolve` + `execFileSync` 数组参数，不拼 shell |
| `tar` 不一定在 | `git archive \| tar` 直接失败 | 改 `git worktree add --detach`，少一个外部依赖；`--c8-dir` 可完全跳过 git |

新增参数：`--c8-dir <路径>`（手头已有那棵树）、`--db <路径>`、`--force`（库已存在时覆盖重跑）。

顺便改了两处措辞（内容没变）：空事件的原因从「C7 不在本次链路（未入主干）」改成
「本次取的是 C8 分支那一版（C7 没接到它的 start 里）」——后者在 G2 之后才准确；
输出里 `historyFixed` 现在会明确是「演练库没升 v7」还是「真缺事实」。
