# 1119 d4 · 给种子狗捎话：写入侧口径与一个未闭合的洞

> 起因：C 20:11 的口径——「允许给种子狗捎话，不在 UI 禁入口；但必须明确提示不会收到主人回复。」
> 结论先说：**d 的写入侧一行代码都不用改**，但 C 说的「显示在路上／已送达」在种子狗身上**兑现不了**，下面第三节是证据。

## 一、C 的四条口径，逐条对到 d 这边

| C 的口径 | d 侧状况 |
| --- | --- |
| 种子狗明确标注「示例伙伴」 | 不归 d。`is_sample` 已经在 `GET /api/dogs` 和交换查询里原样返回（api.md 第 355 行），e 拿得到 |
| 捎话入口旁、提交前提示「没有真实主人，不会收到回复」 | 不归 d。纯界面文案，落在 `app/` 或 `components/` |
| 寄出后延后投递，显示「在路上／已送达」，不显示「等待主人回复」，不生成假回复 | **延后投递 d 已实现**（`deliver_after_trip_seq = 收件狗 seq + 1`）；「不生成假回复」是 b 的 `replied_at` 独占，d 从不写；「不显示等待回复」是 e |
| 真人伙伴的捎话流程保持原有回应能力 | 不归 d。b 的回应动作 |

**写入侧的三条硬约束，实测都成立**（`gift.test.ts` B6/B7 + `scripts/e2e-d4.ts`）：

- `is_sample=1` 的狗**不能以自己主人名义发话**（`SEED_OWNER_SPEAKS`）——这才是「伪造真实用户内容」
- `is_sample=1` 的狗**可以收**礼物和捎话
- d 写进去的 `delivered_at` / `replied_at` / `read_at` **全是 NULL**，一个都没碰

所以「能写进去本身不是缺陷」这句，d 侧认，且已经在测试里锁住了。

## 二、缺口：种子狗不会出行

按 api.md 第 26–29 行：

```
发送那一刻： deliver_after_trip_seq = 收件狗当前 seq + 1
判断到达：   收件狗存在一次 trip，started_at 不为 null 且 seq >= deliver_after_trip_seq
```

用真 fixture（`contracts/fixtures/dog.json` + `trip.json`）建库实测：

```
种子狗 dog_seed_07 当前 seq = 1        （fixture 里只有 trip_seed_01，seq=1，done）
给它的捎话 deliver_after_trip_seq = 2
满足到达条件的 trip 数 = 0  →  永远不会到达
```

**这不是捎话独有的。给种子狗的礼物、发现，同样永远到不了。** 因为 `trip` 表里种子狗只有一条固定记录，没有任何机制给它排第二趟。

后果很具体：

- C 要求「显示在路上／已送达」——种子狗的东西**永远停在上路**，那个「在路上」会一直挂着
- 用户看到「在路上」会等，这正好是 C 想避免的「以为在等一个回应」的另一种形态
- e 那边如果按 `delivered_at IS NULL` 判断显示「在路上」，就会永远显示

## 三、三条解法，d 一个人定不了

| 方案 | 做法 | 代价 | 归属 |
| --- | --- | --- | --- |
| **A（推荐）** | 种子狗跟真狗一样有出行循环：C 的调度器按固定节奏给种子狗生成 `trip`（如每天 1 趟，`started_at` 为当刻） | 多一条调度线，但语义最干净，不破不变量二 | **c** |
| B | d 在种子狗数据里预置一趟「未来的 trip」（`seq=2`，`started_at` 写成未来时刻） | 一启动就满足条件 = 变相立即送达，**破不变量二**，不能做 | 谁都不能做 |
| C | 给种子狗的 `deliver_after_trip_seq` 直接写 1（已发生的出行） | 同样是立即送达，**破不变量二**，不能做 | 谁都不能做 |

**d 能做的只有 A 里的数据部分**（种子狗的 `trip` 行），但「什么时候生成、按什么节奏生成」在投递器/调度器里，是 C 的写入权。所以这条要 C 给一句。

短期如果不做 A，还有一个不破不变量二的退路：

> **给种子狗的捎话/礼物，界面不显示「在路上」，直接显示「已交给示例伙伴」**——不承诺到达，也不承诺回音，与「不会收到主人回复」的提示同一套语气。

这条要不要，得 e 和 C 一起定。d 只提醒：**别让 UI 显示一个永远不会变的「在路上」。**

## 四、给 e 的落点（可以直接用）

1. 种子狗卡片角落标「示例伙伴」，用 `is_sample` 判断，不用昵称猜
2. 捎话弹窗在提交按钮上方一行：「这是示例伙伴，没有真实主人。可以托它带话，但不会收到主人回复。」
3. 寄出后状态文案只允许两种：**在路上 / 已送达**。不出现「等待回复」「对方正在看」，也不出现任何计时（「还剩 X 天」是禁词）
4. 种子狗名下**任何时候都不出现回复气泡**——不是「暂未回复」，是根本不渲染这块
5. 真人伙伴那条路径不改，该有的回应能力保留

## 五、d 侧不做的事

- 不改 `gift.ts` 任何一行（C 已确认写入侧判断成立）
- 不给种子狗伪造 `replied_at`
- 不改 `deliver_after_trip_seq` 的式子
- 不为了让东西「到得了」而在种子狗数据里塞未来的 trip（方案 B，破不变量二）
