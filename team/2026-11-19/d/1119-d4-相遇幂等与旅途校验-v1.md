## 二、改了什么（三处，都是「拒」或「回查」，没有新增业务）

### 1. 纯关系调用直接拒 —— `NO_EXCHANGE_IN_MEET`

`meet()` 入口：`outgoing` 和 `incoming` 都为空 → 抛 `NO_EXCHANGE_IN_MEET`。

**为什么选拒、不选"补幂等"**：`relation` 表没有"哪次出行见的"字段，磕不出幂等键。要支持就得给表加列，那是改 c 的 schema，走契约流程，今天走不完。a 的原文也允许「或在写入前明确拒绝这类调用」。

### 2. tripId 三重校验 —— `TRIP_NOT_FOUND` / `TRIP_NOT_OWNED` / `TRIP_NOT_OPEN`

写任何东西之前查一次 `trip`：

- 记录不存在 → `TRIP_NOT_FOUND`
- `trip.dog_id !== dogId`（不是发起狗的出行） → `TRIP_NOT_OWNED`
- `trip.status !== 'running'` → `TRIP_NOT_OPEN`（`pending` 还没出门，`done/failed/timeout` 已结束）

三者都在 `BEGIN IMMEDIATE` 之前抛，**拒绝时库一个字节都没动**。

状态常量 `MEETABLE_TRIP_STATUS = 'running'` 单独提出来，将来要放开只改一处。

### 3. 重放返回库里的事实，不返回本次 draft

`recordExchange`：`ON CONFLICT DO NOTHING` 后如果 `changes=0`，**回查那一行**，用库里的 `payload` 和 `deliver_after_trip_seq` 返回。

顺带清掉同一类问题：`meet()` 重放分支以前在 `readRelation` 返回 null 时会**编一个 `metCount: 0` 的关系**交出去，现在改成抛错。这个分支正常不可达（关系与交换同事务写入），编一个假事实比炸掉更坏。

## 三、校验顺序也跟着调了一次

`DOG_NOT_FOUND` 提到 `NO_EXCHANGE_IN_MEET` 之前。

理由：狗 id 拼错时报"狗不存在"，调用方能直接定位；报"没带 exchange"会让人去翻 payload，方向全错。

新顺序：`SELF_MEET` → `KIND_NOT_IN_MEET` → `DOG_NOT_FOUND` → trip 三项 → `NO_EXCHANGE_IN_MEET` → `BLOCKED_RELATION` → `gate` → 事务。

新增 6 条：

| 用例 | 断言 |
| --- | --- |
| 既没 outgoing 也没 incoming | `NO_EXCHANGE_IN_MEET`，relation 0 条、exchange 0 条 |
| tripId 不存在 | `TRIP_NOT_FOUND`，两者都 0 |
| tripId 属于另一只狗 | `TRIP_NOT_OWNED`，两者都 0 |
| 出行已结束（done） | `TRIP_NOT_OPEN`，两者都 0 |
| 出行还没出门（pending） | `TRIP_NOT_OPEN`，relation 0 |
| 同键重放传不同内容 | 返回 `line="第一次写的"`、趟次是库里那个，库里仍 1 条 |

**两处夹具修正，不是删用例**：

- 「换一次出行再遇」原来用 `trip_owner_2` 但从未插入这条 trip（以前 tripId 只是拼字符串，不插也能过）。补 `insertTrip(db,'trip_owner_2','dog_owner',2)`，断言一条没动。
- `insertTrip` 加了 `status` / `endedAt` 参数，因为 schema 触发器要求 `running` 必须有 `started_at`、`done` 必须有 `ended_at`，不补插不进去。

a 要的另两条验收「同次相遇重放不增加熟悉次数」「真正下一次出行才增加」，由原有的「同一 tripId 再调一次」「换一次出行再遇」两条覆盖，**未改动**。

## 五、接线点（调用方要知道的）

| 位置 | 影响 |
| --- | --- |
| 任何调 `meet()` 的地方 | **必须带 outgoing 或 incoming**。以前"只记一次见面"的调用方式不再受理 |
| 同上 | `tripId` 必须是这只狗自己的、`status='running'` 的出行。c 的出行流程要保证调用时机在出行进行中 |
| 消费 `recordExchange` 返回值 | `inserted: false` 时拿到的是**库里的记录**，不是刚传的 draft。拿它渲染"已送达内容"现在是安全的 |
| 消费 `meet()` 返回值 | `replayed: true` 时 `exchanges` 为空数组。需要内容请按 `deriveExchangeId` 自己查 |
