# E4 · 旅途页组件库规范 v1

> E · 2026-11-19。旅途页 `running` / `done` 两态所需的可复用视觉组件。
> 令牌、字号阶梯、场景图规格、角色规范见 [旅途页双状态视觉规范 v1](1119-e4-旅途页双状态视觉规范-v1.md)，本文不重复，只写组件本身。
> 组件命名是本规范的**建议类名**，A 可按现有工程约定改名，但结构与尺寸关系应保持一致。

## 1. 组件清单

| # | 组件 | 建议类名 | 过程态 | 归来态 | 复用价值 |
| --- | --- | --- | --- | --- | --- |
| C1 | 旅途场景容器 | `.trip-scene` | ✅ 主体 | ✅ 配图 | 两态同一容器，只换比例 |
| C2 | 刘看山角色展示区 | `.trip-actor` | ✅ | ✅ | 两态同一组件，只换表情 |
| C3 | 旅途状态文案 | `.trip-status` ＋ `.trip-aside` | ✅ | — | 过程态专用，但 `aside` 可复用到其他等待页 |
| C4 | 归来文案 | `.trip-return` | — | ✅ | 也可用于小屋「归来一句话」 |
| C5 | 发现列表 / 发现条目 | `.trip-finds` / `.find-item` | — | ✅ | 手账旅途详情可复用 |
| C6 | 返回小屋 | `.back-home` | ✅ | ✅ | 所有二级页 |
| C7 | 页面状态面板 | `.state-panel` | ✅ | ✅ | 加载／失败／降级通用 |

**基础规范不单列组件**：间距刻度（4／8／12／16／24／32／48）、字号阶梯、色板令牌是规范层的东西，拆成组件只会制造空壳。

**刻意没做的组件**：

- 不做 `TripHeader` —— 顶栏是应用级导航，已有实现，旅途中复用，不该另起一套。
- 不做 `FindKindBadge` —— 它是 `.find-meta` 里的一个 `span`，只有 6 个字和一圈描边，独立成组件没有复用价值。
- 不做 `Divider` —— 1px 分隔线是样式（`border-bottom:1px solid var(--trip-line)`），不是组件。
- 不做 `TripProgress` / `TripCountdown` / `TripLocation` —— 项目明确禁止，不做组件，也不做「先放着以后用」。

## 2. C1 · 旅途场景容器 `.trip-scene`

**用途**：承载单张完整场景图，并为角色提供定位坐标系。两态共用，只改比例。

**结构**

```html
<figure class="trip-scene" data-state="running">
  <img class="scene-art" src="…-750w.png" alt="一句话场景描述">
  <!-- C2 角色插在这里 -->
</figure>
```

**尺寸**

| | 移动 | 桌面 |
| --- | --- | --- |
| 宽 | 100%（左右出血，无边距） | 栅格左栏 1.35fr |
| 高 | `aspect-ratio:375/365`，`min-height:320px` | `aspect-ratio:4/3`，`max-height:520px` |
| 归来态 | `aspect-ratio:375/260`，`min-height:200px` | 同 4:3 |

**颜色与视觉规则**

- 底色 `--trip-soft`（图未到时不留白屏）。
- **无边框、无圆角、无阴影**——像素风不用圆角；场景自己就是画面边界。
- `overflow:hidden` ＋ `isolation:isolate`，角色阴影不外溢。
- 内层 `img`：`position:absolute; inset:0; object-fit:cover`；`object-position` 过程态 `50% 58%`、归来态 `50% 68%`；`image-rendering:pixelated`。

**使用位置**：过程态首屏正中（第一视觉）；归来态在标题行下方，作为发现的出处背景。

**两条硬约束**

1. `width:100%` 必须显式写。只写 `aspect-ratio` ＋ `min-height` 时，浏览器会用高度反推宽度，320 宽下容器被撑到 329px，产生 9px 横向溢出（本轮实测过）。
2. 场景图里**不烘焙角色、文字、按钮**。角色是 C2 独立层，文字是真实 DOM。

## 3. C2 · 刘看山角色展示区 `.trip-actor`

**用途**：把角色稳定地放在场景里，且在任何断点都保持整数倍像素缩放。

**结构**

```html
<div class="trip-actor">
  <img class="actor-shadow" src="…shadow.png" alt="">
  <img class="actor-art" src="…assembly.png" alt="刘看山：白色北极狐，黑色手脚">
</div>
```

阴影是容器内的独立层，不是场景图的一部分——它要跟着角色移动和缩放。

**尺寸**

| | 移动 | 桌面 |
| --- | --- | --- |
| 容器 | 192 × 192（96 原生 ×2） | 288 × 288（96 ×3） |
| 定位 | `left:50%; top:88%; transform:translate(-50%,-100%)` | 同左 |
| 阴影 | 2–3 行硬边椭圆，宽约脚宽 1.6 倍 | 同左 |

`top:88%` 是**脚底锚点**：容器底边落在场景 88% 高度处，角色站在地面而不是浮着。过程态实测脚底在 y=321（365 × 0.88）。

**颜色与视觉规则**

- 层序 `body → cloth → face → hat → glasses`，不新增层。
- `cloth === 'raincoat'` 时不叠帽子（a4-v25 已有规则，沿用）。
- **只允许整数倍缩放**。用固定 px 容器，不用百分比宽度——百分比在 375 宽下会算出 2.55× 这类非整数比例，像素边缘一半 2px 一半 3px。
- 描边不可去掉、不可做柔边：白狐体色对石路只有 1.69:1，全靠描边 7.89:1 立住轮廓。

**使用位置**：两态都在场景内；过程态表情 `face-hopeful`，归来态 `face-happy`。

**动效**：`@keyframes` 两帧位移（0 / −2px），3.6s，`steps(1,end)`，`transform-origin` 在脚底；`prefers-reduced-motion` 或用户 `reducedMotion` 为真时 `animation:none`。

## 4. C3 · 旅途状态文案 `.trip-status` ＋ `.trip-aside`

**用途**：过程态里唯一的一句话，告诉用户它现在怎么样。**不承担进度、位置、时长**。

**结构**

```html
<p class="trip-status">它沿着河边慢慢走，不着急回来。</p>
<p class="trip-aside">等它回来，这里会换上这一趟的路景。</p>
```

**尺寸**

| | 移动 | 桌面 |
| --- | --- | --- |
| 上边距 | 24 | 0（右栏顶部对齐） |
| 字号／行高 | 16 / 1.9 | 17 / 1.9 |
| 最大行数 | 2 | 2 |
| 辅助句 | 13 / 1.8，上 8 | 14 / 1.8，上 12 |

**颜色**：正文 `--trip-ink`（9.01:1）；辅助句 `--trip-muted`（5.63:1）。

**使用位置**：过程态场景下方，左对齐，不压在图上看对比度。

**文案规则**

- 状态话 ≤ 20 字，第二人称「它」，不用「系统正在为您……」。
- 不写「预计 X 分钟后回来」「已走 3.2 公里」「当前位置：河边」。
- 辅助句只说明「回来后会变成什么」，不解释技术。
- 有情绪但不过度：允许「不着急回来」，不允许「它一定很想你」。

## 5. C4 · 归来文案 `.trip-return`

**用途**：把 `Message.text` 原话以「它说的话」呈现，不是系统通知。

**结构**

```html
<blockquote class="trip-return">
  <p>巷子里那面墙红透了，只有靠窗那块还是绿的。</p>
  <footer>看山说的 · 示例</footer>
</blockquote>
```

**尺寸**

| | 移动 | 桌面 |
| --- | --- | --- |
| 上边距 | 24（场景下 24） | 0 |
| 字号／行高 | 17 / 1.9 | 17 / 1.9 |
| 左竖线 | 3px `--trip-line`，`padding-left:12px` | 同左 |
| 署名 | 12px，上 8 | 同左 |

**颜色**：正文 `--trip-ink`；署名 `--trip-muted`。

**使用位置**：归来态场景正下方（桌面为右栏第一块）。

**规则**

- **必须用 `Message.text` 原话**，不改写、不润色、不加「它说：」前缀。
- 不加气泡尾巴、不加引号、不加头像角标——竖线已经足够表示「引述」。
- 无 `Message` 时不占位，直接从场景进列表；不写「它没有留下话」这种系统腔。
- 零发现或 timeout 时，这句话照样显示（fixture 里 `trip_002` 就是有归来话、没有发现）。

## 6. C5 · 发现列表 `.trip-finds` / 发现条目 `.find-item`

**用途**：把 3–5 条发现排出可读的顺序和层级。

**结构**

```html
<section class="trip-finds" aria-labelledby="finds-title">
  <div class="finds-head">
    <h2 id="finds-title">它带回来的</h2>
    <span>4 条 · 示例内容</span>
  </div>
  <ol class="find-list">
    <li class="find-item" data-lead="true">
      <div class="find-meta"><span class="find-kind">路边的风景</span><span>示例记录</span></div>
      <h3 class="find-title">一面长满爬山虎的墙</h3>
      <p class="find-excerpt">……</p>       <!-- 可选，没有摘要就不占位 -->
      <a class="find-action">读这段发现</a>  <!-- 仅代表条目 -->
    </li>
    <li class="find-item">
      <div class="find-meta"><span class="find-kind">路上的一刻</span><span>示例记录</span></div>
      <h3 class="find-title">有人把旧椅子搬到门口晒太阳</h3>
      <a class="find-link">看这一条</a>
    </li>
  </ol>
</section>
```

**尺寸**

| 元素 | 移动 | 桌面 |
| --- | --- | --- |
| 列表上边距 | 32 | 24 |
| 表头上／下 | 0 / 8，下边框 1px | 同左 |
| 条目上下内边距 | 16 / 16 | 同左 |
| 条目分隔 | `border-bottom:1px solid --trip-line`，末条去掉 | 同左 |
| 代表条目标题 | 19 / 1.6 | 19 |
| 其余条目标题 | 15 / 1.6 | 15 |
| 摘要 | 14 / 1.8，上 4 | 同左 |
| 元信息 | 12 / 1.6，上 8 | 同左 |
| 主操作按钮 | 高 44，`padding:0 14px` | 同左 |
| 次级「看这一条」 | 高 44（整行可点），13px 下划线 | 同左 |

**颜色**

| 元素 | 颜色 |
| --- | --- |
| 标题 | `--trip-ink` |
| 摘要／元信息 | `--trip-muted` |
| 分类标签 `.find-kind` | `--trip-muted` 字 ＋ `--trip-soft` 底 ＋ 1px `--trip-line` 边，行高 18 |
| 主操作 `.find-action` | 底 `--trip-blue`，字 `--trip-on-accent`（5.67:1） |
| 次级 `.find-link` | `--trip-blue` 文字下划线 |

**使用位置**：归来态首屏之后的主阅读体；桌面在右栏、归来话之下。

**层级与顺序规则**

1. 第一条是**代表发现**：标题 19px、有摘要、有主按钮，是首屏里唯一完整露出的条目。
2. 其余条目压缩：标题 15px、摘要按数据决定有无、动作降为整行可点的「看这一条」。
3. 排序：与 `Message.mentions_find_id` 对应的条目排第一（话已经说过它），其余按 `created_at` 升序。**此规则待 A 确认。**
4. 代表条目若已被归来话引用，**不再重复摘要**——同一句话在 200px 内出现两遍是明显的阅读噪音。
5. 没有摘要就不渲染 `<p>`，不留空白高度（fixture 的 `find_m1`、`find_z2` 就是 `excerpt: null`）。

**来源标注**

- `kind='scene'` → 「路边的风景」＋「示例记录」
- `kind='moment'` → 「路上的一刻」＋「示例记录」
- `kind='zhihu'` → 「知乎内容」＋「示例内容」，**且不给可点的假链接**（fixture 的 `source_url` 是假 URL）
- `source_mode` 只对 `zhihu` 有效；`scene`／`moment` 不标 live／cache

**空态**：`finds = []` 时不渲染列表骨架，换成一句 `.finds-empty`（15px，`--trip-muted`）：「今天没找到合适的。它走了一趟，这样也挺好。」不编造条目凑数。

## 7. C6 · 返回小屋 `.back-home`

**用途**：从旅途回到小屋。两态都有，位置固定。

**结构**

```html
<a class="back-home" href="…">回小屋</a>
```

**尺寸**：`min-height:44px; min-width:44px; padding:0 10px`，实测 64 × 44。固定在标题行右侧，与 `h1` 同一行。

**颜色**：文字 `--trip-blue`（5.67:1），下划线；按下态底 `--trip-soft`；边框透明（视觉上不抢标题）。

**使用位置**：两态标题行右上，位置不随状态改变。

**规则**

- **每页只有一个**。归来态底部不再放第二个「回小屋」按钮——底部主操作是「读这段发现」，两个同级主按钮会让页面没有主次。
- 不塞进主导航（小屋／来信／手账／朋友圈）当第五项。
- 触摸区 ≥ 44 × 44，`margin-top:-4px` 让视觉基线对齐标题而不是把行高撑高。

## 8. C7 · 页面状态面板 `.state-panel`

**用途**：加载、读取失败时占住场景框的位置，避免版面跳动。

**结构**

```html
<!-- 加载 -->
<div class="state-panel" role="status">
  <strong>正在打开这段旅途</strong><span>稍等一下，马上就好。</span>
</div>

<!-- 失败 -->
<div class="state-panel">
  <strong>这段旅途没读出来</strong><span>可能是网络断了一下。</span>
  <div class="state-actions">
    <a class="primary">再读一次</a><a>回小屋</a>
  </div>
</div>
```

**尺寸**：撑满 C1 的高度（过程态 365、归来态 260）；内容居中，`gap:12px`，`padding:24px`；按钮高 44。

**颜色**：底 `--trip-soft`；标题 `--trip-ink` 17px；说明 `--trip-muted` 13px；主按钮 `--trip-accent` 底 ＋ 白字（5.60:1）；次按钮透明底 ＋ `--trip-line` 边。

**使用位置**：替换 C1 的内容；此时**标题改中性**（「旅途」），下方文案区收起，不显示「它还在路上」这类与错误矛盾的句子。

**四条规则**

1. **不是骨架屏**：没有条状占位、没有脉冲动画、没有进度条。等待旅途和等待数据是两件事。
2. 失败态必须同时给「再读一次」和「回小屋」；重试只重读，**不 POST 新旅途**。
3. 降级态不换面板，用顶部提示条 `.trip-notice`（`--trip-soft` 底 ＋ 3px `--trip-caramel` 左边），原内容照常显示。
4. 面板出现时，页面其余部分不抖动——高度由 C1 保证。

## 9. 两态的组件组合

**过程态**

```
顶栏（应用级，非本库）
└ trip-head ── h1 ＋ C6 回小屋
└ trip-layout
   ├ C1 场景容器
   │  └ C2 角色（face-hopeful）
   └ col-right
      ├ C3 状态话
      └ C3 辅助句
└ trip-foot 示例标注
```

**归来态**

```
顶栏（应用级）
└ trip-head ── h1 ＋ C6 回小屋
└ trip-layout
   ├ C1 场景容器
   │  └ C2 角色（face-happy）
   └ col-right
      ├ C4 归来话
      └ C5 发现列表（3–5 条，首条为代表）
└ trip-foot 示例标注
```

差别只有两处：**C1 的比例**（365 → 260）和**右栏／下方承载什么**（C3 → C4 ＋ C5）。C2、C6、页脚两态完全一致——这是「同一页面的两种状态」而不是「两个页面」的证据。

**移动端与桌面端**

| | 移动（≤899） | 桌面（≥900） |
| --- | --- | --- |
| 布局 | 单列，场景出血，文案 18px 边距 | 两栏 1.35fr / 0.85fr，间距 32 |
| C1 | 375 × 365 / 260 | 4:3，最高 520 |
| C2 | 192px | 288px |
| C3 位置 | 场景下方 | 右栏，与场景垂直居中 |
| C5 位置 | 文案下方，单列 | 右栏，文案下方 |
| 页脚 | 贴底（`margin-top:auto`） | 内容下方 |

DOM 顺序在两种断点下一致（场景 → 文案 → 列表），桌面只用 CSS Grid 改排布，不重排 DOM——保证朗读顺序和焦点顺序稳定。
