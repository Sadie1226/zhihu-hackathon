调用方式：服务端使用 `searchZhihu(query, count=3)`。Count 限 1–10。
端点沿用团队正式手册：`GET https://developer.zhihu.com/api/v1/content/zhihu_search`。
Query/Count 使用 URLSearchParams 编码，鉴权为 Bearer + `Math.floor(Date.now()/1000)`。
禁止跟随重定向、禁用请求缓存、15 秒请求超时、无自动重试。

只返回标题、摘要、原文 URL、sourceMode、AuthorityLevel、VoteUpCount；
不返回作者、头像、签名、评论或原始响应。标题/摘要作为纯文本，去除 HTML 高亮标记。
原文 URL 保留上游内容路径，限定 HTTPS 知乎问题/回答/文章地址，移除查询和 fragment；不猜造链接。
按可信度等级、赞数降序稳定排序。合法空集合返回空；无效结构不会被当作空成功。

搜索材料复用现有 Find 字段类型，但不是落库 Find：没有生成 id/tripId，也没有写数据库。
只有当前请求成功返回的材料标 live。离线测试里的 synthetic 响应只验证分支行为，不能作为真实成果使用。

## 错误与集成边界

| 情况 | 内部结果 | 处理 |
| --- | --- | --- |
| 无密钥、HTTP 401/403、业务 20001 | AUTH，retriable=false，alert=true | 不向前端透传；后续调用方接服务端告警及 cache/fixture |
| HTTP 429、业务 30001 | RATE_LIMITED，retriable=false | 不自动重试；给调用方 cache/fixture 降级指示 |
| 网络/请求超时、HTTP 5xx、无效 JSON/结构 | NETWORK，retriable=true | 失败如实保留，不生成假成功或伪造 live |
| 本地参数不合法、业务 10001 | CONFLICT，retriable=false | 参数纠正 |

AUTH/RATE_LIMITED 是内部判别结果，`fallback='cache-or-fixture'` 为接入指示，不是假称已实现降级。
C9 的持久缓存、降级材料和实际告警通道仍是后续任务；本轮不提供前端 API。
真实联调没有遇到上游 20001/30001，相关分支通过模拟 HTTP/业务错误验证，不能声称真实限流验收。
协议错误不保留上游 Message、响应体或异常 cause，防止回显请求头或凭据。

下一阶段才接 trip/find：搜索之前必须执行 blocked_topics 过滤；使用真实出行 ID 持久化，
保持 sourceMode 语义，接入 C9 缓存/降级，不改变 C4 生命周期或邮箱字段所有权。
