## 3. 实际 HTTP 端点

| 方法与路径 | 入 / 出 | 归属与错误 |
| --- | --- | --- |
| `GET /api/dogs/:id/wishes?includeRevoked=false` | `{ wishes: Wish[] }`，字段含 `source/sourceUrl` | 只认 `readSessionId`；越权/无会话 404；参数非法 409 |
| `POST /api/dogs/:id/wishes` | `{ text, category }` → `{ wish }` | 多余键（含 `source`）409；来源固定 `owner/null` |
| `PATCH /api/wishes/:id/revoke` | `{}` → `{ wish }` | 复用 `revokeWish`；重复撤销返回同一条与首次时间 |
| `POST /api/uploads/photo` | multipart `file` → `{ url, bytes, mime, width, height }` | 401/413/415；落盘 `uploadDir()` |
| `GET /uploads/<name>` | 图片字节 + 真实 MIME | 文件名形状不符/不存在 404；与存储位置解耦 |
| `POST /api/replies` | `{ exchangeId?/invitationId?, text?, photoUrl? }` → `{ reply }` | photoUrl 三段校验；唯一冲突幂等重放 |
| `GET /api/dogs/:id/invitations` | `{ invitations: InvitationView[] }` | 查 `v_invitation_state`，按 dog.session_id 限定 |

所有响应 `Cache-Control: no-store`。无 schema、无迁移；部署新增一个可选环境变量 `UPLOAD_DIR`（见第 3.1 节），本地不设也能跑。

### 3.1 上传落盘与部署（11-19 修订）

| 项 | 值 |
| --- | --- |
| 存储根目录 | `uploadDir()` = `process.env.UPLOAD_DIR \|\| './data/uploads'`，定义在 `app/(b)/b6-photo.ts`，写入/回应校验/读取路由三处共用 |
| 本地 | `./data/uploads`，`data/` 在 `.gitignore:25`，不进仓库 |
| 部署 | 在 `/etc/zhihu-hackathon.env` 加 `UPLOAD_DIR=/var/lib/zhihu-hackathon/uploads`；`deploy/zhihu-hackathon.service` 的 `ReadWritePaths` 已含该目录、`StateDirectory` 已建父目录，**service 文件无需改** |
| 对外 URL | 仍是 `/uploads/<name>`，由新增 `app/(b)/uploads/[name]/route.ts` 读 `uploadDir()` 返回；存储与 URL 解耦 |

不用 `public/uploads/` 的原因：`1118-a:109,176` 的建议基于本地 dev；`next start` 部署用 `ProtectSystem=strict`，代码目录只读，写 `public/` 会 EACCES。此改动由 A 的 `1119-a-给B:29` 收口要求触发。

## 4. 三处返回规则

- `origin:'trip'` 仅表示页面来自归来区，不是回应来源枚举；提交只用 `invitationId` / `exchangeId`。
- `returnTo` 由调用方给实际入口（归来页传 `/trip`，来信/手账传各自路由）；组件渲染返回链接，不固定跳小屋，不写 `history.back()`。
- 「先不回」不提交、不写记录；邀请本身不过期。
