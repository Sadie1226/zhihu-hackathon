# 看山出门 · K 契约 · errors.md

> 出 c，11-16。**出错时返回什么、界面显示什么。**
>
> 一条总原则：**别把五种情况混成一个 500。** 它们对用户的意味完全不同 ——
> 断网可以重试，限流该安静降级，不合规不该解释。混在一起，界面就只能说「出错了」，
> 而「出错了」在不变量三下是催促。

---

## 一、四个禁区（违反了就是阻断缺陷，不是 bug）

### 禁区一：主人的聊天原文一个字都不进 `snapshot`

`snapshot` 是**白名单字段表**，不是黑名单。

有人想在快照里加个 `chat_summary`，答复是不行 —— **摘要也是原文派生的，一样会串味。**
这只狗要给别人家的狗读，读到的只能是「它是什么样」，不能是「它主人说过什么」。

### 禁区二：屏蔽在任何地方优先于心愿

`blocked_topics` 的过滤优先级**高于心愿、高于朋友牵挂、高于当天抽到的事件**。

c 的搜索键、d 的交换内容、e 的展示，**三处都要过**。漏一处就是漏。

### 禁区三：谁都不许自己新建表、自己加字段

只有 c 改 K，**只加不删**，旧字段留到 11-29 之后再清。
要加的字段先在本文件同级的 `api.md` 里说清形状，群里贴 diff。

### 禁区四：关系类事实只有 d 写

e 的朋友圈、b 的「它记得你回应过」，**全部只读 d 写下的那一份**。
两处各算一遍 = 两个版本 = 用户觉得被骗（不变量五）。

## 二、错误码

`types.ts` 里的 `ContractErrorCode` 就这七个。**没有第八个。**

| 码 | 什么时候 | 返回体 | 界面显示 | 能重试吗 |
| --- | --- | --- | --- | --- |
| `NETWORK` | 请求根本没到服务器／服务器连不上知乎 | `{ code, detail, retriable: true }` | **如实说断网**，四态里的「失败」，给一个重试 | ✅ 是 |
| `RATE_LIMITED` | 知乎返回 `30001` | 不返回给前端。**服务端自己降级** | 无提示。内容改用 cache，标 `cache` | ❌ **不重试** |
| `AUTH` | 知乎返回 `20001` | 不返回给前端。**服务端告警** | 无提示。静默降级到 cache 或 fixture | ❌ 否 |
| `BLOCKED` | 内容不合规 / 撞了屏蔽主题 | `{ code, detail: '', retriable: false }` | **什么都不显示，也不解释为什么** | ❌ 否 |
| `TIMEOUT` | 出行超时收尾 | `{ code, detail, retriable: false }` | **不是报错**。是一次正常结束的归来 | ❌ 否 |
| `NOT_FOUND` | 查不到那只狗／那条邀请 | `{ code, detail, retriable: false }` | 说清「这条已经不在了」，给一条回去的路 | ❌ 否 |
| `CONFLICT` | 空回应、两个来源、重复提交、一天三次出行 | `{ code, detail, retriable: false }` | 就地提示具体哪一条不对，**不丢已输入的内容** | ❌ 否 |

### 三条容易写反的

**`RATE_LIMITED` 不重试，这是故意的。** 知乎限流时重试只会把额度烧得更快。降级、标 `cache`、继续。

**`BLOCKED` 不解释原因。** 解释了就等于告诉用户「这个词被屏蔽了」，那是把审核逻辑漏给人看。直接不显示。

**`TIMEOUT` 在界面上不是错误。** 它和「今天它回来得晚，没带回什么」是同一件事。做成红色报错就违反了「低压力」。

## 三、不算错误的三种情况

**这三种返回空数组，不返回错误码。** 混进错误分类是这份文件最常见的误用。

| 情况 | 返回 | 界面 |
| --- | --- | --- |
| **没搜到** | `{ finds: [] }` | 「今天没找到合适的」**不催、不加感叹号** |
| **被屏蔽主题** | 不进结果集 | **什么都不显示** |
| **邀请没人回应** | `{ state: 'waiting' }` | 安静地留着。**没有红点、没有指标、没有「已过期」** |

## 四、降级路径（c 的活，e 只管显示）

```
真搜索 → 成功：source_mode = 'live'      界面「刚从知乎看到」
       → 限流/鉴权失败：走 24 小时缓存    source_mode = 'cache'   界面「几小时前看到的」+ 原文仍可点
       → 缓存也没有：走 fixtures          source_mode = 'fixture'  界面「示例内容」+ 醒目样式
```

**降级必须如实标 `source_mode`，不许把 cache 标成 live。** 不变量四。

**断网状态下的硬要求**：朋友圈、手账、小屋、以及已经缓存的旅途，**全部还能打开**。它们都是本地数据，不该因为断网变白屏。这条按阻断缺陷处理。

## 五、禁词：`errors.md` 里也不许出现

错误文案同样属于「用户可见的地方」。**禁词表在 `app/(b)/invite/spec.md`，界面和报错都跑同一个脚本。**

最容易在错误文案里犯的三个：

| 别写 | 为什么 | 写成 |
| --- | --- | --- |
| 「差一点就好了」 | 暗示用户做错了 | 「这次没连上，可以再试一次」 |
| 「已过期」 | 过期本身就是惩罚 | （不会有这个状态 —— 邀请永不过期） |
| 「坚持一下，快回来了」 | 催促 | 「它在路上，回来会告诉你」 |

**提交前跑一次禁词脚本。有输出就是没做完，不是「文案后面再润色」。**

## 六、五种阻断缺陷（冻结之后也修）

11-29 之后别的一律不改，**但这五种随时修**：

1. **主流程走不完** —— 领养→心愿→出门→带回→邀请→回应，中间任何一步卡死
2. **越权看到别人的数据** —— 能读到别的 session 的狗、聊天、心愿
3. **重复投递** —— 同一件礼物到两次（`delivered_at` 没做幂等）
4. **伪造真实用户内容** —— 种子狗装成真人养的、AI 假装对面主人回话
5. **泄露密钥** —— `ZHIHU_ACCESS_SECRET` 进了仓库或前端

**第 4 条在这个项目里最容易被踩**，因为它不是写错代码，是少写了一个标注。
