# 看山出门

知乎黑客松 S3 · 湾区共创季 · 赛道二「AI × 陪伴与交互（社区 × 数字伙伴）」

> **一只刘看山自己过日子。你在旁边看着，它偶尔问你要不要一起；路上认识别的狗，带回来东西，和一份等你回应的邀请。**

开篇四个字：**治愈、低压力**。这四个字决定了后面所有的取舍。

## 一、这是什么

一个 AI 数字伙伴。它有自己的生活节奏，不需要你下指令才动；它出门、带回发现、向你发出一个具体的邀请，然后等你。

**核心闭环：**

```
它出门 → 带回来发现 → 它发出一个具体邀请 → 你回应 → 你的回应成为它下一次出门的材料
```

三条立场：

1. **不回应不惩罚。** 没有红点、没有连续天数、没有进度条、不催。邀请会安静地留着。
2. **回应了关系会长。** 你给的东西会真的进到它下次的旅途里，能被看出来。
3. **「明天还回来」靠的是「世界在等你回话」，不是靠打卡。**

### 五条不变量

**违反了就不是这个产品。** 任何人拿检测问句对自己的模块，30 秒能自检。

| # | 不变量 | 检测问句 |
| --- | --- | --- |
| 一 | 狗是主体，人是客人 | 界面上有没有一个按钮让人直接操作另一个人？ |
| 二 | 一切都不是即时的 | 从我的屏幕到对方的屏幕，中间有没有一段「在等」？ |
| 三 | 不回应不惩罚 | 不回应会看到红点、指标、连续天数、催促吗？ |
| 四 | 真实来源可点，假数据显形 | 这段内容不是这条请求现拿的，写清楚了吗？ |
| 五 | 一只狗一个主人，一段经历一个出处 | 有没有可能两条路写出同一个事实的两个版本？ |

## 五、`team/` · 当日交付存放区

**交付走你的分支，文件放 `team/日期/你的字母/`，放完不要再改。** 目录位置是推荐写法，不是验收门槛 —— 验收看「东西在不在、说没说清」，见 [`team/README.md`](team/README.md) 第三节第〇条。索引看 [`team/STATUS.md`](team/STATUS.md)，那个只有 a 改。

```
team/
  2026-11-15/a/    ← a 当天交的
  2026-11-16/c/    ← c 当天交的
  ...
  STATUS.md        ← 索引，只有 a 改
  指南-交付与取用.md ← 开工前读你自己那一页
```

全部 21 个日期文件夹（11-15 → 12-05）已经建好，空着的是还没到那天，**不是没建**。

**三条硬规矩：**

1. **日期按「交的那天」算**，不按任务编号里的截止日算。11-18 交的 e2b 就放 `2026-11-18/e/`。

3. **文件名说清是什么。** 规则、命名示例、目录归属见 [`team/README.md`](team/README.md)。

**代码不进 `team/`。** 按下面的目录归属直接放进 `app/` `lib/`。`team/` 只放「要给别人用、还没变成代码」的规则、线框、文案、素材清单。

## 七、怎么动手

### 一个决定归谁

问一句：**「我定的这条，别人违反了会怎样？」**

- 别人得返工 → 群里发六行提案，等 24 小时（没异议就默认通过，不要等所有人表态）
- 只影响他自己那块 → **他自己定，别去问人**

```
【提案】一句话说清是什么
影响谁：
为什么是现在：
备选：至少一个，写清代价
我打算怎么做：三步以内
什么时候能看到：具体日期
```

**异议必须写「为什么」+「一个替代方案」。只写「不行」不算异议，视为同意。**

### 谁能拦

| 谁 | 范围 | 拦了必须给什么 |
| --- | --- | --- |
| **a** | 产品范围、是否偏离中心、优先级 | 替代方案，或明确说砍掉 |
| **c** | 契约、数据表、部署、依赖、密钥 | **替代实现**，不能只说不行 |
| **e** | 视觉一致性、资产锚点规范 | **替代样式** |
| **b / d** | 仅自己功能 | 说清哪一步会坏 |

**只否决不给方案 = 把自己的活推给别人，站会上点名。**

### 分支与合并

**`main` 只有 a 能改。别人禁止推 main，一次都不行。**

- `main` 始终可部署，**坏了算最高级事故**
- 每人每天从最新 main 切一条新分支，名字带任务号：`b4-chat`、`d6-gift`、`e2b-assets`
- **第二天不要接着用旧分支**——它在你合并那一刻就作废了，每天从新的 main 重切
- **每天必须交一次，哪怕只改了一个按钮。** 攒三天再合并，冲突量翻十倍
- 每次合并打一个 tag，格式 `v{序号}-{月日}`，序号只增不减：`v1-1116`、`v2-1120`
- 每次合并写一行 [`team/合并记录.md`](team/合并记录.md)，**写清改了谁的文件、为什么**

**完整命令和「被改动了怎么查」写在 [`team/指南-交付与取用.md`](team/指南-交付与取用.md) 的通用节，每个人开工前读一遍。**

### 提交前自检

```bash
# 1. 禁词：不变量三的机器可查版本
grep -rnE '连续|打卡|天数|坚持|别忘|快回来|还剩|已过期|差一点|加油|你还没|已经很久|太棒' app/ components/ lib/

# 2. 密钥：不该出现在提交里的东西
git diff --cached | grep -iE 'secret|token|password|api[_-]?key' | grep -v '.env.example'
```

**有输出就是没做完，不是「后面再润色」。**

完整的协作约定（PR 怎么写、验证一栏要求）见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

## 八、本地跑起来

**11-16 已建（c 的 c2）。** Node 24+、`node:sqlite` 内置、零 ORM。`npm install` 之后 `npm run dev` 能起本地服务。
公网部署仍是 **BLOCKED**（暂无服务器），只有本地验收和 `deploy/` 部署包。

```bash
git clone https://github.com/Sadie1226/zhihu-hackathon.git
cd zhihu-hackathon
npm install
cp .env.example .env    # 填 ZHIHU_ACCESS_SECRET，不要提交
npm run dev
```

健康检查：`http://localhost:3000` 能看到首页。

## 九、提交前必看的四件事

1. **没提交密钥。** `.env` 不在提交里，代码里没有硬编码的 Access Secret
2. **没提交数据库和上传文件。** 它们已在 `.gitignore` 里，别强行 `git add -f`

### 信息与授权

这是公开仓库，**12-07 提交前会一直公开**。请勿提交 API 密钥、账号凭据、真实用户聊天记录或个人资料。

**私密内容不在这个仓库里。** GitHub PAT、知乎 Secret、服务器信息存在仓库外的 `E:\Hackathon\项目记录\`，git 管不到那里。**永远不要把那边的内容复制进来。**
